### 2.1 **关键缺口**：端到端真实数据测试

**当前问题**:
- ✅ 单元测试使用 Mock 数据（不需要 API）
- ✅ 端到端测试脚本存在，但使用 Mock URL

**影响范围**:
1. **FetchStep → 真实网页抓取**
   - 未验证真实微信/知乎/网页能否正确抓取
   - 未验证 Playwright 在真实环境的稳定性

2. **AnalyzeStep → DeepSeek API**
   - 未验证真实内容的 AI 分析效果
   - 未验证 API 超时、限流处理

3. **IdeaSharpenStep → CLI 交互**
   - 未验证真实场景下的超时机制
   - 未验证用户输入的数据流

4. **StoreStep → 真实存储**
   - 未验证 Markdown + SQLite + Vector 三重存储
   - 未验证文件路径、数据库约束、向量索引

### 2.2 **次要缺口**：边界条件测试

**缺少的场景**:
1. **超长内容**（>10,000 字）
   - 是否触发 idea Sharpen？

   - 向量分块是否正确？

2. **特殊字符和编码**
   - Emoji、LaTeX 公式、代码块
   - 文件名冲突（标题相同）

3. **并发执行**
   - 多个工作流同时执行
   - 数据库并发写入

4. **错误恢复**
   - 中途失败的工作流
   - 部分存储失败的场景

### 2.3 **次要缺口**：性能测试

**缺少的指标**:
1. **执行时间验证**
   - 归档流程是否 ≤ 5 分钟？

   - 内存使用
   - 数据库大小增长
