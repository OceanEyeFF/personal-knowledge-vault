### DeepSeek API 核心特性与使用限制总结

#### 一、 核心特性

* **领先的模型能力**  
* **推理能力全球领先**：DeepSeek-V3.2 的推理能力达到 GPT-4o 和 Claude-3.5-Sonnet 的水平 1-3。  
* **思考能力集成**：deepseek-reasoner 模型（思考模式）支持长思维链推理，特别在数学、代码和逻辑验证上表现卓越，甚至在部分基准测试中媲美 o1-preview 4-6。  
* **首创思考融入工具调用**：DeepSeek-V3.2 是首个支持在思考模式下调用工具的模型，模型可以通过多轮“思考+工具调用”给出更详尽准确的回答 7, 8。  
* **超长上下文与模型细节**  
* **上下文窗口**：API 对应的模型版本为 DeepSeek-V3.2，支持高达 **128K** 的上下文长度 9, 10。  
* **双模型体系**：提供 deepseek-chat（适合日常问答和通用任务）和 deepseek-reasoner（专注深度逻辑推理）两个端点 10, 11。  
* **开发友好功能**  
* **JSON 输出与工具调用**：两款模型均支持 JSON 模式输出和 Function Calling 10。  
* **上下文缓存（Context Caching）**：通过缓存重复的系统提示词或上下文，大幅降低输入成本（缓存命中价格仅为未命中的 1/10） 10, 12。  
* **补全模式**：支持聊天前缀补全（Chat Prefix Completion）；deepseek-chat 还额外支持 FIM（Fill-in-Middle）补全 10, 13。  
* **极致的性价比**  
* **价格低廉**：API 价格极具竞争力，输入（缓存未命中）为 $0.28/1M tokens，输出为 $0.42/1M tokens 10。

#### 二、 使用限制与注意事项

* **Token 与输出限制**  
* **单次输出长度**：deepseek-chat 默认最大输出为 4K，最高可设为 **8K** tokens；deepseek-reasoner 默认最大输出为 32K，最高可设为 **64K** tokens 5, 10, 14。  
* **思维链输出规则**：使用 Reasoner 模型时，思维链内容（reasoning\_content）是**只读**的。开发者在进行多轮对话时，**不得**将该内容回传至下一次请求的输入中，否则会破坏上下文管理系统 15, 16。  
* **请求限制与并发**  
* **无硬性并发限制**：DeepSeek 官方表示不限制用户并发量 17。  
* **动态节流**：在流量高峰期，系统会进行动态限流，可能导致 **429 错误**或响应延迟 18, 19。  
* **连接超时**：如果请求发出 10 分钟后仍未开始推理，服务器将强制关闭连接 17。  
* **技术兼容性限制**  
* **工具调用适配**：思考模式目前未充分适配使用非标准工具调用的组件（如 Cline、RooCode），建议此类场景使用非思考模式 8。  
* **Reasoner 模型功能缺项**：deepseek-reasoner 目前不支持 FIM 补全功能 10。  
* **Speciale 模型限制**：临时研究版 Speciale 不支持工具调用，且仅支持思考模式对话 20。  
* **无状态机制**  
* API 是**无状态**的。DeepSeek 不会通过服务器自动记忆对话历史，开发者必须在每次调用时手动发送完整的对话上下文（Context Replay） 14, 16, 21。  
* **隐私与合规**  
* **数据存储**：数据存储在位于**中国内地**的云服务器上 22, 23。  
* **数据使用**：在用户未手动关闭“数据用于优化体验”设置的情况下，用户的输入输出数据可能会被用于模型训练 24。
