## 📊 分步骤详解

### 1. FetchStep 数据流

```mermaid
graph LR
    A[state.get: url] --> B[get_processor]
    B --> C[processor.process]
    C --> D[Entry 对象]
    D --> E[state.set]
    E --> F[entry]
    E --> G[title]
    E --> H[content]
    E --> I[source_type]
    E --> J[source_url]
```

**数据类型**:
```typescript
输入: { url: string }
输出: {
  entry: Entry,
  title: string,
  content: string,
  source_type: string,
  source_url: string
}
```

---

### 2. AnalyzeStep 数据流

```mermaid
graph LR
    A[state.get: entry] --> B[entry.content]
    B --> C[DeepSeekClient]
    C --> D[summarize]
    C --> E[extract_tags]
    D --> F[summary_100_words]
    E --> G[tags: List[str]]
    F --> H[state.set]
    G --> H
```

**数据类型**:
```typescript
输入: { entry: Entry }
输出: {
  summary: string,
  tags: string[]
}
```

---

### 3. IdeaSharpenStep 数据流

```mermaid
graph TD
    A[state.get: entry] --> B{word_count >= 500?}
    B -->|否| C[跳过交互]
    B -->|是| D[Rich Panel 显示]
    D --> E[用户输入]
    E --> F[notes]
    F --> G[state.set]
    C --> G
```

**数据类型**:
```typescript
输入: { entry: Entry }
输出: {
  notes: string  // 可能为空
}
```

---

### 4. StoreStep 数据流

```mermaid
graph TD
    A[state.get: entry] --> B{targets 配置}
    B --> C[markdown]
    B --> D[sqlite]
    B --> E[vector]

    C --> F[MarkdownStore.save]
    F --> G[file_path]

    D --> H[SQLiteStore.insert_entry]
    H --> I[knowledge_id]

    E --> J[Embedder.embed_chunks]
    J --> K[VectorStore.add_entry]
    K --> L[vector_ids]

    G --> M[state.set]
    I --> M
    L --> M
```

**数据类型**:
```typescript
输入: { entry: Entry }
输出: {
  file_path: string,       // ".data/vault/wechat/标题.md"
  knowledge_id: number,    // 123
  vector_ids: number[]     // [1, 2, 3]
}
```

## 🔗 端到端数据转换

### 输入 → 输出映射

| 阶段 | 输入 | 输出 | 数据转换 |
|------|------|------|---------|
| **用户** | URL字符串 | - | - |
| **FetchStep** | `{url: string}` | `Entry` | HTML → Markdown |
| **AnalyzeStep** | `Entry.content` | `summary, tags` | 文本 → AI 生成 |
| **IdeaSharpen** | `Entry` | `notes` | 用户输入 |
| **StoreStep** | `Entry` | `file_path, knowledge_id, vector_ids` | 对象 → 持久化 |
| **WorkflowResult** | `state.to_dict()` | 完整状态字典 | State → Result |

## ⚠️ 关键数据传递点

### State 键名约定

| 键名 | 来源步骤 | 使用步骤 | 类型 |
|------|---------|---------|------|
| `url` | 用户输入 | FetchStep | `string` |

| `title` | FetchStep | - | `string` |
| `content` | FetchStep | AnalyzeStep | `string` |

## 🎯 总结

### 数据流特点

✅ **单向流动**: URL → Entry → 增强 Entry → 持久化
✅ **State 传递**: 步骤间通过 `context.state` 共享数据
✅ **增量构建**: 每个步骤都在前一步基础上添加数据
✅ **并行存储**: StoreStep 同时写入 3 个后端

### 关键转换点

1. **URL → Entry** (FetchStep + Processors)
2. **Content → Summary + Tags** (AnalyzeStep + DeepSeek)
3. **Entry → Storage** (StoreStep + 3 个存储后端)
