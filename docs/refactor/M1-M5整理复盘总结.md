## 🏗️ 架构设计分析

### 优秀的设计模式

#### 1. 工作流驱动架构 ✅

```
WorkflowEngine (M5)
    ├── FetchStep → Processors (M3)
    ├── AnalyzeStep → AI Services (M2)
    ├── IdeaSharpenStep → Rich UI
    └── StoreStep → Storage (M1)
```

**优点**:
- 清晰的职责分离
- 高度可配置（YAML）
- 易于扩展新步骤

---

#### 2. 三层存储架构 ✅

```
主存储层: MarkdownStore (人类可读)
    ↓
索引层: SQLiteStore (快速查询 + FTS5)
    ↓
语义层: VectorStore (向量检索)
```

**优点**:
- Markdown 主存储（Git 友好）
- SQLite 元数据索引（高性能）
- 向量语义检索（AI 增强）

---

#### 3. 智能检索路由 ✅

```
查询 → 分词 → token_count
    ├─ < 5 tokens  → BM25 (精确关键词)
    └─ ≥ 5 tokens  → Hybrid (BM25 + Vector + RRF)
```

**优点**:
- 自动选择最优策略
- 短查询快速响应（BM25）
- 长查询语义理解（向量+混合）

---

### 需要改进的地方

#### 1. 数据类型不一致 ⚠️

**问题示例**:
```python
# Entry 定义
keywords: list = field(default_factory=list)

# SQLite 存储
keywords TEXT  -- 逗号分隔字符串

# 转换代码（分散在各处）
keywords_str = ",".join(entry.keywords) if entry.keywords else ""
```

**建议**: 统一数据类型或使用适配器模式

---

#### 2. 配置字段命名不规范 ⚠️

**已修复示例**:
```yaml
# 错误
storage_backends: [markdown, sqlite]

# 正确
targets: [markdown, sqlite]
```

**教训**: 配置字段命名应与代码保持严格一致

---

#### 3. 缺少字段验证 ⚠️

**问题**:
```python
# Entry 声明为必填但无验证
title: str  # 必填但没有 __post_init__ 检查
```

**建议**: 使用 Pydantic 或添加 `__post_init__` 验证
