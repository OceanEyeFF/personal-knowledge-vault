## src/ 目录详解

### 模块组织原则

- **工作流驱动**: 核心逻辑由工作流引擎编排
- **插件化**: 内容处理器采用插件架构，易于扩展
- **分层清晰**: 存储层、业务层、表示层分离

### 1. workflow/ - 工作流引擎

**职责**: Slash Commands 框架、工作流编排、进度追踪

```
src/workflow/
├── engine.py               # 工作流引擎核心
├── commands.py             # Slash Commands 注册
├── steps/                  # 工作流步骤定义
│   ├── fetch_step.py       # 内容抓取步骤
│   ├── analyze_step.py     # AI 分析步骤
│   ├── sharpen_step.py     # idea Sharpen 步骤
│   └── store_step.py       # 存储步骤
└── context.py              # 工作流上下文管理
```

**核心类** (伪代码):

```python
# src/workflow/engine.py
class WorkflowEngine:
    def execute(self, workflow_name: str, input_data: dict):
        """
        执行工作流

        Args:
            workflow_name: 工作流名称（如 "archive-url"）
            input_data: 输入数据（如 {"url": "..."}）

        Returns:
            执行结果
        """
        workflow = self.load_workflow(workflow_name)
        context = WorkflowContext(input_data)

        for step in workflow.steps:
            result = step.execute(context)
            context.update(result)

        return context.output
```

**插件接口** (伪代码):

```python
# src/processors/base.py
class ContentProcessor(ABC):
    @abstractmethod
    def can_handle(self, url_or_text: str) -> bool:
        """判断是否能处理该内容"""
        pass

    @abstractmethod
    async def process(self, input: str) -> ProcessedContent:
        """
        处理内容

        Returns:
            ProcessedContent(
                title=str,
                content=str,      # Markdown 格式
                metadata=dict,    # 元数据
                raw_html=str      # 原始 HTML（可选）
            )
        """
        pass
```

**注册机制**:

```python
# src/processors/__init__.py
PROCESSORS = [
    WechatProcessor(),
    ZhihuProcessor(),
    ChatProcessor(),
    NewsProcessor(),
    GenericWebProcessor(),  # 通用网页处理器（兜底）
]

def get_processor(url_or_text: str):
    for processor in PROCESSORS:
        if processor.can_handle(url_or_text):
            return processor
    raise ValueError("No suitable processor found")
```

**职责**: BM25 全文检索 + 向量语义检索 + 混合策略

```

└── query_router.py         # 查询路由器（决定使用哪种策略）
```

**策略路由** (伪代码):

```python
# src/retrieval/query_router.py
class QueryRouter:
    def route(self, query: str, corpus_size: int) -> SearchStrategy:
        """
        根据查询特征选择检索策略

        Args:
            query: 用户查询
            corpus_size: 内容库规模

        Returns:
            SearchStrategy枚举: BM25 | VECTOR | HYBRID
        """
        query_len = len(query)
        has_keywords = self._has_precise_keywords(query)

        if query_len < 10 and has_keywords:
            return SearchStrategy.BM25
        elif query_len > 50 or not has_keywords:
            return SearchStrategy.VECTOR
        else:
            return SearchStrategy.HYBRID
```

**核心类** (伪代码):

```python
# src/storage/markdown_store.py
class MarkdownStore:
    def save(self, entry: Entry) -> Path:
        """
        保存条目为 Markdown 文件

        生成文件名规则: {时间戳}-{标题slug}.md
        示例: 20260214-distributed-systems.md
        """
        frontmatter = self._build_frontmatter(entry)
        content = f"---\n{frontmatter}\n---\n\n{entry.content}"

        file_path = self.vault_dir / f"{entry.timestamp}-{entry.slug}.md"
        file_path.write_text(content, encoding="utf-8")
        return file_path

# src/storage/sqlite_store.py
class SQLiteStore:
    def index_entry(self, entry: Entry):
        """
        将条目元数据存入 SQLite

        涉及表: entries, tags, concepts, entry_tags
        """
        self.db.execute("INSERT INTO entries (...) VALUES (...)")
        self._index_tags(entry)
        self._index_concepts(entry)
        self._update_fts5(entry)
```

**API 封装示例** (伪代码):

```python
# src/ai/deepseek_client.py
class DeepSeekClient:
    def summarize(self, content: str, max_words: int = 300) -> str:
        """
        生成摘要

        Args:
            content: 原文内容
            max_words: 摘要最大字数

        Returns:
            摘要文本
        """
        prompt = self._load_prompt("summarize", content=content, max_words=max_words)
        response = self.client.chat.completions.create(
            model="deepseek-chat",
            messages=[{"role": "user", "content": prompt}]
        )
        return response.choices[0].message.content
```

## 配置文件说明

### 1. config/config.yaml - 主配置

```yaml
# 数据存储路径
storage:
  vault_dir: ".data/vault"
  db_path: ".data/db/knowledge_vault.db"
  vector_index_path: ".data/vectors/embeddings.index"

ai:
  deepseek:
    model: "deepseek-chat"
    max_tokens: 2000
  openai:
    embedding_model: "text-embedding-3-small"
    embedding_dim: 1536

# 检索配置
retrieval:
  bm25:
    k1: 1.5          # BM25 参数
    b: 0.75
  vector:
    top_k: 10        # 返回 Top K 结果
    ef_search: 50    # HNSW 搜索深度
  hybrid:
    bm25_weight: 0.4
    vector_weight: 0.6

# 工作流配置
workflows:
  archive_url:
    steps:
      - fetch
      - analyze
      - sharpen    # idea Sharpen（根据内容决定是否触发）
      - store

  search:
    default_strategy: "hybrid"
```

### 2. config/workflows/ - 工作流定义

每个 Slash Command 对应一个 YAML 文件：

```yaml
# config/workflows/archive-url.yaml
name: archive-url
description: "归档网页内容"

steps:
  - id: fetch
    type: fetch_content
    processor: auto  # 自动选择处理器
    retry: 3

  - id: analyze
    type: ai_analyze
    tasks:
      - summarize   # 生成摘要
      - extract_tags  # 提取标签
      - extract_concepts  # 提取概念

  - id: sharpen
    type: idea_sharpen
    condition: |
      content_length > 3000 or
      concept_count >= 5 or
      content_type in ["discussion", "analysis"]
    questions:
      - "这篇内容的核心价值是什么？"
      - "你想记住哪些关键点？"

  - id: store
    type: store_entry
    targets:
      - markdown
      - sqlite
      - vector_index
```

## 模块依赖关系

### 依赖层次

```
┌─────────────────────────────────────────┐
│  main.py (CLI 入口)                      │
└────────────────┬────────────────────────┘
                 │
        ┌────────▼────────┐
        │ workflow/       │  工作流引擎
        │ (编排层)         │
        └────┬───┬───┬────┘
             │   │   │
    ┌────────┘   │   └──────────┐
    │            │               │
┌───▼────┐  ┌───▼────┐   ┌─────▼──────┐
│processors│  │retrieval│   │ ai/       │
│(业务层)  │  │(检索层) │   │(AI 服务层)│
└───┬────┘  └───┬────┘   └─────┬──────┘
    │            │               │
    └────────┬───┴───────────────┘
             │
        ┌────▼────┐
        │ storage/│  存储层
        │(数据层)  │
        └─────────┘
```

### 关键依赖关系

| 模块 | 依赖 | 说明 |
|------|------|------|
| `workflow/` | `processors/`, `ai/`, `storage/` | 编排各模块完成任务 |
| `processors/` | `ai/`, `storage/` | 调用 AI 分析，存储结果 |
| `retrieval/` | `storage/` | 从存储层读取数据进行检索 |
| `ai/` | - | 无依赖，纯 AI API 封装 |
| `storage/` | - | 无依赖，纯数据层 |
