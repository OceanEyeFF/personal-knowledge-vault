## 添加新的 Slash Command

### 概述

Slash Command 是用户与系统交互的主要方式，每个命令对应一个工作流。

**开发流程**:
1. 定义工作流 YAML 配置
2. 实现所需的自定义步骤（如果现有步骤不够用）
3. 注册命令
4. 测试验证

---

### 示例：添加 `/kb:batch-import` 命令

**需求**: 批量导入多个 URL，跳过 idea Sharpen 环节，全自动处理。

#### Step 1: 创建工作流配置

创建 `config/workflows/batch-import.yaml`:

```yaml
name: batch-import
description: "批量导入 URL，全自动处理"

# 输入参数定义
input:
  urls:
    type: list
    required: true
    description: "URL 列表"

# 工作流步骤
steps:
  - id: validate_urls
    type: validate_input
    rules:
      - all_valid_urls

  - id: process_batch
    type: parallel_process
    max_concurrency: 5        # 最多并行处理 5 个
    for_each: input.urls
    sub_workflow: archive-url-simple  # 引用简化版归档流程

  - id: report
    type: generate_report
    template: "batch_import_summary"
```

#### Step 2: 创建简化版归档工作流

创建 `config/workflows/archive-url-simple.yaml`:

```yaml
name: archive-url-simple
description: "简化版归档流程（无 idea Sharpen）"

steps:
  - id: fetch
    type: fetch_content
    retry: 3

  - id: analyze
    type: ai_analyze
    tasks:
      - summarize
      - extract_tags

  - id: store
    type: store_entry
    targets:
      - markdown
      - sqlite
      - vector_index
```

#### Step 3: 注册命令

在 `src/workflow/commands.py` 中注册：

```python
# src/workflow/commands.py
from src.workflow.engine import WorkflowEngine

engine = WorkflowEngine()

@engine.command("batch-import", help="批量导入 URL")
async def batch_import_command(urls: List[str]):
    """
    批量导入命令

    Args:
        urls: URL 列表

    Returns:
        执行结果摘要
    """
    result = await engine.execute_async(
        workflow_name="batch-import",
        input_data={"urls": urls}
    )
    return result
```

#### Step 4: 测试

自动化只编写使用合成 URL 和 fake transport 的单元/集成测试，并用以下入口执行：

```powershell
.\scripts\run-test.ps1 -Direct -DataRoot .data-test\workflow-batch -Command @("pytest", "tests/unit/test_workflow_engine.py", "-q")
```

真实 URL 的 batch-import 属 user-only 流程；U1/G8 未交付前不提供可复制命令。

## 工作流 YAML 配置规范

### 基础结构

```yaml
name: <workflow-name>           # 工作流唯一标识（必需）
description: <description>       # 工作流描述（必需）
version: "1.0"                   # 版本号（可选）

# 输入参数定义（可选）
input:
  <param_name>:
    type: <str|int|bool|list|dict>
    required: <true|false>
    default: <default_value>
    description: <description>

# 工作流步骤（必需）
steps:
  - id: <step_id>                # 步骤唯一标识
    type: <step_type>            # 步骤类型
    <additional_config>          # 步骤特定配置
```

---

### 步骤类型 (step_type)

#### 1. fetch_content - 内容抓取

```yaml
- id: fetch
  type: fetch_content
  processor: auto              # auto | wechat | zhihu | generic
  retry: 3                     # 重试次数
  timeout: 30                  # 超时时间（秒）
```

---

#### 2. ai_analyze - AI 分析

```yaml
- id: analyze
  type: ai_analyze
  tasks:
    - summarize                # 生成摘要
    - extract_tags             # 提取标签
    - extract_concepts         # 提取概念
    - detect_sentiment         # 情感分析（可选）
  model: deepseek-chat         # 可选，默认使用配置文件中的模型
```

---

#### 3. idea_sharpen - 人机协作

```yaml
- id: sharpen
  type: idea_sharpen
  condition: |                 # 触发条件（Python 表达式）
    content_length > 3000 or
    concept_count >= 5
  questions:
    - "这篇内容的核心价值是什么？"
    - "你想记住哪些关键点？"
  timeout: 300                 # 用户响应超时（秒）
  skip_on_timeout: true        # 超时后自动跳过
```

---

#### 4. store_entry - 存储条目

```yaml
- id: store
  type: store_entry
  targets:
    - markdown                 # 保存为 Markdown 文件
    - sqlite                   # 索引到 SQLite
    - vector_index             # 生成向量索引
  on_duplicate: skip           # skip | overwrite | merge
```

---

#### 5. parallel_process - 并行处理

```yaml
- id: process_batch
  type: parallel_process
  max_concurrency: 5           # 最大并行数
  for_each: input.urls         # 遍历输入列表
  sub_workflow: archive-url-simple  # 子工作流
```

---

#### 6. conditional - 条件分支

```yaml
- id: check_length
  type: conditional
  condition: content_length > 5000
  then:
    - type: ai_analyze
      tasks: [summarize_long]
  else:
    - type: ai_analyze
      tasks: [summarize_short]
```

---

### 条件表达式

工作流支持使用 Python 表达式进行条件判断：

**可用变量**:
- `content_length`: 内容字数
- `concept_count`: 概念数量
- `tag_count`: 标签数量
- `content_type`: 内容类型（如 "discussion", "news", "technical"）
- `source`: 来源类型（如 "wechat", "zhihu"）

**示例**:

```python
# 长文且是技术内容
content_length > 3000 and content_type == "technical"

# 讨论记录或深度分析
content_type in ["discussion", "analysis"]

# 概念多或标签多
concept_count >= 5 or tag_count >= 3
```

## 开发自定义工作流步骤

### Step 1: 创建步骤类

```python
# src/workflow/steps/my_custom_step.py
from src.workflow.steps.base import WorkflowStep
from src.workflow.context import WorkflowContext

class MyCustomStep(WorkflowStep):
    """
    自定义步骤示例

    配置参数:
        - param1 (str): 参数说明
        - param2 (int): 参数说明
    """

    async def execute(self, context: WorkflowContext) -> dict:
        """
        执行步骤逻辑

        Args:
            context: 工作流上下文

        Returns:
            dict: 执行结果，会被合并到 context.state
        """
        # 1. 从上下文获取数据
        input_data = context.state.get("previous_step_output")

        # 2. 执行自定义逻辑
        result = self._process_data(input_data)

        # 3. 返回结果
        return {
            "my_step_output": result,
            "status": "success"
        }

    def _process_data(self, data):
        # 实现具体逻辑
        ...
```

### 错误处理

步骤应该妥善处理错误：

```python
from src.exceptions import WorkflowError

class MyCustomStep(WorkflowStep):
    async def execute(self, context: WorkflowContext) -> dict:
        try:
            result = self._process_data(context.state)
            return {"output": result}
        except ValueError as e:
            # 可恢复的错误，记录日志并返回默认值
            context.log(f"警告: {e}，使用默认值")
            return {"output": None}
        except Exception as e:
            # 不可恢复的错误，抛出 WorkflowError
            raise WorkflowError(f"步骤失败: {e}") from e
```

## 开发内容处理器插件

### 需求场景

添加对新网站的支持，例如 CSDN 博客。

---

### Step 1: 创建处理器类

```python
# src/processors/csdn_processor.py
from src.processors.base import ContentProcessor, ProcessedContent
from src.processors.safe_fetch import SafeFetcher
from bs4 import BeautifulSoup

class CSDNProcessor(ContentProcessor):
    """
    CSDN 博客处理器

    支持 URL 格式:
        - https://blog.csdn.net/{username}/article/details/{id}
    """

    def can_handle(self, url_or_text: str) -> bool:
        """判断是否为 CSDN URL"""
        return "blog.csdn.net" in url_or_text

    async def process(self, url: str) -> ProcessedContent:
        """
        处理 CSDN 博客

        Returns:
            ProcessedContent
        """
        # 1. 抓取 HTML
        html = await self._fetch(url)
        soup = BeautifulSoup(html, 'lxml')

        # 2. 提取核心内容
        title = soup.find('h1', class_='title-article').text.strip()
        content_div = soup.find('div', id='content_views')
        content_md = self._html_to_markdown(content_div)

        # 3. 提取元数据
        author = soup.find('a', class_='follow-nickName').text.strip()
        pub_date = soup.find('span', class_='time').text.strip()

        return ProcessedContent(
            title=title,
            content=content_md,
            metadata={
                "source": url,
                "author": author,
                "publish_date": self._parse_date(pub_date),
                "platform": "csdn"
            }
        )

    async def _fetch(self, url: str) -> str:
        """抓取网页 HTML"""
        headers = {"User-Agent": "Mozilla/5.0 ..."}
        response = await SafeFetcher(timeout_seconds=30).fetch(
            url,
            headers=headers,
        )
        response.raise_for_status()
        return response.text

    def _html_to_markdown(self, html_element) -> str:
        """将 HTML 转换为 Markdown"""
        # 使用 markdownify 或自定义转换逻辑
        from markdownify import markdownify as md
        return md(str(html_element))

    def _parse_date(self, date_str: str) -> str:
        """解析 CSDN 的日期格式"""
        # 实现日期解析逻辑
        ...
```

所有 URL processor 都必须复用 `SafeFetcher`：DNS 校验、固定 IP 连接、redirect 与页面子资源重校验是不可绕过的 W2 安全合同。不得增加 Playwright、requests、httpx 或其他客户端作为失败降级路径。

## 最佳实践

### 1. 工作流设计原则

- **单一职责**: 每个工作流只做一件事
- **可组合性**: 通过 `sub_workflow` 组合复杂流程
- **错误处理**: 明确定义失败时的行为（重试/跳过/中断）
- **幂等性**: 工作流应该可以安全地重复执行

---

### 2. 步骤开发原则

- **轻量级**: 步骤应该快速执行（< 5秒）
- **无状态**: 不要在步骤对象中保存状态，使用 `context`
- **日志记录**: 关键操作都应记录日志
- **类型注解**: 使用 type hints 提高可读性

---

### 3. 处理器开发原则

- **健壮性**: 处理各种异常情况（网络错误、解析失败）
- **降级策略**: 优雅降级，避免完全失败
- **性能优化**: 使用异步 IO，避免阻塞
- **可测试性**: 提供测试 URL 和预期输出

---

### 4. 配置管理

**避免硬编码**:

```python
# ❌ 不好
class MyStep(WorkflowStep):
    def execute(self, context):
        max_retry = 3  # 硬编码

# ✅ 好
class MyStep(WorkflowStep):
    def __init__(self, max_retry: int = 3):
        self.max_retry = max_retry

    def execute(self, context):
        for i in range(self.max_retry):
            ...
```

**YAML 配置**:

```yaml
- id: my_step
  type: my_custom_step
  max_retry: 5  # 从 YAML 配置
```

---

**为自定义步骤编写文档**:

## 常见问题

### 问题 1: 工作流配置未生效

**症状**: 修改了 YAML 配置，但执行时没有变化。

**原因**: 工作流引擎缓存了配置。

**解决**:

```python
# 强制重新加载配置
engine = WorkflowEngine(reload_config=True)
```

---

### 问题 2: 自定义步骤未注册

**症状**: 执行工作流时报错 "Unknown step type: my_custom_step"。

**原因**: 忘记在 `WorkflowEngine` 中注册步骤。

**解决**: 检查 `src/workflow/engine.py` 中的 `self.steps` 字典。

---

### 问题 3: 处理器优先级问题

**症状**: 通用处理器总是被选中，自定义处理器从不执行。

**原因**: 处理器列表顺序错误，通用处理器在前面。

**解决**: 将通用处理器放在列表最后：

```python
PROCESSORS = [
    WechatProcessor(),
    ZhihuProcessor(),
    MyCustomProcessor(),
    GenericWebProcessor(),  # 必须在最后（兜底）
]
```
