## Executive Summary

当前知识库工作流存在一个关键缺陷：**用户无法审核和修改 AI 自动生成的摘要、标签和清理内容，只能被动接受 AI 的输出结果**。这导致用户对生成的内容质量缺乏掌控力，无法在条目入库前进行质量把关。

本功能通过在工作流中引入 **「用户审核与修改阶段」**，赋予用户对 AI 生成内容的完整掌控权。用户可以预览、修改、评论、指导 AI 重新生成，并最终决定是否入库。这是 **所有工作流的必经步骤**（网页归档、AI 对话保存、文本导入等），保证入库的每条内容都经过用户确认。

**核心价值**：
- 🎯 提高知识库条目的质量和可信度
- 🎯 强化用户对内容的掌控感和参与感
- 🎯 支持 AI-Human 协作的迭代优化流程
- 🎯 保留完整的审核历史和版本追踪

## Problem Statement

### 现状痛点

1. **无审核环节**：AI 生成的摘要、标签直接入库，用户无法干预
2. **质量无保证**：无法修改错误的 AI 输出，也无法给出反馈指导改进
3. **流程不灵活**：没有快速保存选项，用户审核流程流程复杂
4. **标签管理困难**：无地方编辑标签，导致标签系统混乱
5. **内容预览缺失**：用户看不到 AI 如何去广告、去尾端，缺乏透明度
6. **缺少评论机制**：用户有额外笔记无处可存，不属于摘要和标签

### 提议的解决方案

设计一个 **轻量级、交互式的审核流程**：

```
用户归档/保存
  ↓
[审核阶段 - 用户可选/强制]
  ├─ 查看原始内容预览（去广告、去尾端效果）
  ├─ 查看 AI 生成的摘要、标签、去污染内容
  ├─ 修改摘要（直接编辑 / 用编辑器编辑）
  ├─ 修改标签
  ├─ 用 Prompt 指导 AI 重新生成
  ├─ 添加个人评论（不属于摘要和标签的自由笔记）
  └─ 最后决定：通过/拒绝/修改后通过
  ↓
[批准 → 入库] / [拒绝 → 草稿区] / [再次审核]
```

### 业务影响

- **内容质量**：每条入库内容都经过用户确认，质量提升 30%+
- **用户体验**：赋予用户掌控感，建立 AI-Human 信任
- **工作流完整性**：闭合了「生成 → 审核 → 入库」的完整环路

## Success Metrics

### 主要 KPIs

1. **审核完成率**: 不低于 95%（用户实际使用审核功能的比例）
   - 测量方法：统计通过审核的条目数 / 总入库条目数
   - 目标：首周达到 80%，一个月内达到 95%

2. **审核修改率**: 预期 40-60%（用户实际修改 AI 输出的比例）
   - 测量方法：统计修改过摘要/标签的条目数
   - 目标：首周达到 30%，稳定在 40-60%

3. **用户满意度**: 不低于 4.0/5.0
   - 测量方法：问卷调查、反馈收集
   - 目标：质量评分 ≥ 4.0

4. **重新生成命中率**: 预期 60-70%（AI 在用户提示后改进成功的比例）
   - 测量方法：统计用户确认改进的重新生成次数
   - 目标：首周稳定在 50%+，后期达到 65%+

5. **草稿恢复率**: 预期 10-15%（拒绝的条目后来被恢复的比例）
   - 测量方法：统计从草稿区恢复的条目数
   - 目标：了解用户拒绝的真实比例和悔改意愿

### 验证计划

- **Week 1**: 内测，收集用户反馈
- **Week 2**: 优化 UX，改进 AI 建议质量
- **Week 3**: 全量上线，持续监控数据
- **Month 2**: 根据数据进行优化调整

## User Personas

### Primary: 知识库管理者（快速审核者）

- **角色**: 个人知识库的所有者，需要快速整理和保存内容
- **目标**:
  - 高效审核 AI 生成的内容
  - 确保入库内容的质量和准确性
  - 保持对知识库的完全掌控
- **痛点**:
  - 目前无法修改标签和摘要，内容不符合期望
  - AI 有时会出错（比如标签太长、摘要不准确）
  - 希望有快速入库的选项，但又想有质量把关
- **技术水平**: 中高级（熟悉 CLI，能用编辑器）

### Secondary: AI 协作者（迭代优化者）

- **角色**: 通过与 AI 协作来优化内容处理的用户
- **目标**:
  - 通过 Prompt 指导 AI 改进输出
  - 建立 AI-Human 的迭代反馈循环
  - 理解 AI 如何工作，不断优化提示词
- **痛点**:
  - 目前没有直接与 AI 对话的机制来改进结果
  - 无法看到历史修改和版本对比
- **技术水平**: 高级（熟悉 AI，能设计 Prompt）

## User Stories & Acceptance Criteria

### Story 1: 查看 AI 生成内容与原始内容对比

**As a** 知识库管理者
**I want to** 在审核前看到原始内容的预览（已去广告、去尾端）和 AI 生成的摘要、标签
**So that** 我能理解 AI 的处理效果，做出知情的审核决定

**Acceptance Criteria:**
- [ ] 用户能看到清理后的内容预览（去广告、去尾端）
- [ ] 用户能看到 AI 生成的摘要和标签
- [ ] 可以并排对比原始内容和处理后内容
- [ ] 界面清晰，信息层级合理（标题 → 摘要 → 标签 → 预览）

---

### Story 2: 直接修改摘要和标签

**As a** 知识库管理者
**I want to** 能够直接编辑 AI 生成的摘要和标签
**So that** 我能快速修复 AI 的错误或调整内容以符合我的需求

**Acceptance Criteria:**
- [ ] 用户可以直接修改摘要（文本编辑）
- [ ] 用户可以直接修改标签（逗号分隔）
- [ ] 支持两种编辑方式：
  - [ ] 在控制台中直接输入多行文本（用 EOF 结束）
  - [ ] 弹出系统编辑器（vim/nano）编辑
- [ ] 修改后的内容实时预览
- [ ] 修改不会丢失，用户可以随时返回查看

---

### Story 3: 通过 Prompt 指导 AI 重新生成

**As a** AI 协作者
**I want to** 能够用 Prompt 指导 AI 重新生成摘要或标签，并保持同一 session 中的上下文
**So that** AI 能看到我的修改历史和反馈，进行更准确的改进

**Acceptance Criteria:**
- [ ] 用户可以输入重新生成的 Prompt 指导
- [ ] AI 在同一 session 中处理，能看到前面的对话和用户修改
- [ ] 新生成的摘要/标签会替换旧版本
- [ ] 用户可以进行多轮迭代（修改 → Prompt 指导 → 重新生成 → 确认）
- [ ] 所有重新生成的 Prompt 都被记录

---

### Story 4: 添加个人评论

**As a** 知识库管理者
**I want to** 能够添加个人评论和笔记，这些评论不属于摘要和标签
**So that** 我能保存一些额外的想法或上下文信息

**Acceptance Criteria:**
- [ ] 用户可以在审核时添加评论字段
- [ ] 评论与摘要、标签、内容分离存储
- [ ] 评论可以是多行文本
- [ ] 评论在入库时被保留，用户可以后续查看

---

### Story 5: 最终审核决定与草稿管理

**As a** 知识库管理者
**I want to** 能够最终决定内容是否入库，或将其存储在草稿区以便后续处理
**So that** 我能控制什么时候真正将内容添加到知识库

**Acceptance Criteria:**
- [ ] 用户可以选择"通过审核 → 入库"
- [ ] 用户可以选择"拒绝 → 草稿区"（用户可以后续恢复）
- [ ] 用户可以选择"修改后再审核"
- [ ] 草稿区中的条目可以查看、编辑、恢复或永久删除
- [ ] 审核历史被记录，用户可以查看历史版本和修改记录

---

### Story 6: 版本回溯与历史追踪

**As a** AI 协作者
**I want to** 能够查看审核过程中的所有版本变更，以及每个操作的历史记录
**So that** 我能理解内容是如何演进的，以及支持回溯到任何之前的版本

**Acceptance Criteria:**
- [ ] 用户可以查看完整的修改历史（包括何时修改、修改了什么、为什么修改）
- [ ] 用户可以回溯到任何之前的版本
- [ ] 回溯操作本身也被记录在历史中
- [ ] 历史记录清晰展示：原始版本 → 修改 1 → AI 重新生成 → 修改 2 等
- [ ] 用户可以比较任意两个版本的差异

## Functional Requirements

### Core Features

#### Feature 1: 内容预览与展示

**描述**: 在审核界面中，用户能看到清理后的原始内容预览和 AI 生成的摘要、标签

**用户流程**:
1. 用户触发归档/保存流程
2. 系统展示：
   - 源URL/标题
   - 原始内容的预览片段（已去广告、去尾端）
   - AI 生成的摘要
   - AI 生成的标签
   - 内容统计（字数、来源等）
3. 用户可以向下浏览完整的预览内容

**边界情况**:
- 如果内容很长，只展示前 500 字的预览，用户可选择看完整内容
- 如果没有摘要或标签，显示占位符提示
- 去广告效果失败时，展示原始内容并说明原因

**错误处理**:
- 如果内容预处理失败，仍允许用户继续审核（手工验证）

---

#### Feature 2: 摘要编辑（双模式）

**描述**: 用户可以用两种方式编辑摘要：控制台多行输入 或 系统编辑器

**用户流程 A - 控制台输入**:
1. 用户选择"修改摘要"
2. 系统提示用户输入新摘要，输入 EOF (Ctrl+D) 结束
3. 新摘要即时展示

**用户流程 B - 编辑器编辑**:
1. 用户选择"用编辑器编辑摘要"
2. 系统打开 $EDITOR (vim/nano) 或默认编辑器
3. 用户编辑保存后，新摘要被读取

**边界情况**:
- 用户输入空摘要：提示警告，允许继续
- 摘要超长（>500 字）：提示警告但允许保存
- 编辑器打开失败：降级到控制台输入

**错误处理**:
- 编辑过程中按 Ctrl+C 取消，返回到审核主菜单
- 编辑器未找到，自动降级到多行输入

---

#### Feature 3: 标签编辑

**描述**: 用户可以修改和管理标签，支持添加/删除/验证

**用户流程**:
1. 用户选择"修改标签"
2. 系统显示当前标签列表
3. 用户可以：
   - 逗号分隔输入新标签列表
   - 或交互式添加/删除单个标签
4. 系统验证标签（长度 1-20 字符，符合命名规范）
5. 用户确认修改

**边界情况**:
- 标签长度不符合规范（< 1 或 > 20 字符）：提示用户但允许保存
- 标签重复：自动去重
- 标签为空：提示警告但允许继续

**错误处理**:
- 无效字符：提示并要求重新输入

---

#### Feature 4: AI 重新生成（Prompt 指导）

**描述**: 用户可以用 Prompt 指导 AI 重新生成摘要或标签，在同一 session 中保持上下文

**用户流程**:
1. 用户选择"让 AI 重新生成摘要/标签"
2. 系统展示：
   - 当前版本的摘要/标签
   - 之前的 Prompt 指导历史
3. 用户输入新的 Prompt（比如"标签太长了，帮我拆分"）
4. 系统调用 AI，在同一 session 中：
   - 传入原始内容
   - 传入修改历史和用户反馈
   - 生成新版本
5. 新版本展示给用户
6. 用户选择：接受 / 再次指导 / 手工修改

**上下文保持**:
- AI session 记录：原始内容、AI 初始输出、用户修改 1、用户 Prompt 1、AI 重新生成 1、用户修改 2、...
- AI 能看到完整的迭代历史，生成更一致的结果

**边界情况**:
- 用户连续重新生成 > 3 次：提示"建议手工修改"
- AI 生成超时：提示用户稍候或手工修改

**错误处理**:
- API 失败：降级到"用户手工修改"流程
- Session 断开：创建新 session 并同步历史

---

#### Feature 5: 个人评论

**描述**: 用户可以添加不属于摘要和标签的个人评论和笔记

**用户流程**:
1. 用户在审核任意时刻选择"添加评论"
2. 用户输入多行评论（同样用 EOF 结束或编辑器）
3. 评论被保存

**用途示例**:
- "这篇文章来自 XX 博主，值得关注后续内容"
- "包含 Python 代码示例，后续可整理成代码库"
- "与 [条目 ID] 内容相关，需要建立关联"

**边界情况**:
- 评论为空：允许跳过
- 评论超长（> 2000 字）：允许保存但提示

---

#### Feature 6: 审核决定与草稿管理

**描述**: 用户做出最终审核决定：入库 / 草稿 / 拒绝

**用户流程**:
1. 用户完成审核（修改摘要、标签、评论等）
2. 系统显示最终确认菜单：
   ```
   [1] 通过审核 → 直接入库
   [2] 需要再审核 → 返回修改
   [3] 拒绝 → 存入草稿区（可恢复）
   [4] 彻底删除 → 永久删除（二次确认）
   ```
3. 用户选择

**草稿区功能**:
- 显示所有拒绝/待审核的条目
- 用户可以查看、编辑、恢复或永久删除
- 草稿会定期清理提示（比如 30 天未修改）

**错误处理**:
- 用户选择"拒绝"时，显示二次确认："确认要拒绝吗？条目将存入草稿区"

---

#### Feature 7: 历史追踪与版本回溯

**描述**: 记录审核过程中的所有版本变更，用户可查看历史和回溯

**审核历史记录**:
- 初始版本（AI 生成）
- 每次修改（摘要、标签、评论）
- 每次 AI 重新生成（含 Prompt）
- 每次审核决定

**版本展示**:
```
版本历史：
[v1] AI 初始生成 (2026-02-23 10:30)
  - 摘要：XXX
  - 标签：tag1, tag2

[v2] 用户修改摘要 (2026-02-23 10:35)
  - 变更：摘要改为 YYY

[v3] AI Prompt 重新生成 (2026-02-23 10:40)
  - Prompt：标签太多了，帮我精简到 3 个
  - 新标签：tag1, tag3

[v4] 用户回溯到 v2 (2026-02-23 10:45)
  - 说明：标签改太多了，还是用 v2 的版本

[最终版本] 用户审核通过 (2026-02-23 10:50)
  - 版本：v2
  - 评论：已审核，准备入库
```

**用户可以**:
- 查看任意版本的完整内容
- 比较任意两个版本的差异
- 回溯到任何之前的版本（回溯操作本身也被记录）

### Out of Scope

- ❌ GUI 审核界面（Phase 2）
- ❌ 自动审核（ML 模型辅助）
- ❌ 批量审核快捷方式（仅支持逐条）
- ❌ 标签预设和自动补全（现在不做）
- ❌ 审核流程自定义（固定流程）
- ❌ 多用户审核权限管理（个人库假设）

## Technical Constraints

### Performance

- **交互响应时间**: < 100ms（UI 反应）
- **AI 重新生成时间**: < 30s（用户可容忍的等待时间）
- **内容预览加载**: < 2s
- **历史查询**: < 1s（回溯查询）

### Security

- **数据隐私**: 所有用户修改都存储在本地 SQLite，不上云
- **操作记录**: 完整的审核历史，防止数据丢失
- **编辑器安全**: 使用系统编辑器时，确保文件权限正确

### Integration

- **与工作流集成**: `ReviewStep` 作为所有工作流的必经步骤
- **与 AI 服务集成**: 使用现有的 DeepSeek/OpenAI 客户端，保持同一 session
- **与存储层集成**: 使用现有的 `SQLiteStore`、`MarkdownStore`、`VectorStore`
- **与 CLI 集成**: 集成到现有 `archive` 命令，支持交互式审核

### Technology Stack

- **语言**: Python 3.11+
- **CLI 框架**: Click + Rich（现有）
- **数据库**: SQLite + 新的 `review_queue` 和 `review_history` 表
- **编辑器集成**: `tempfile` + `subprocess`（调用系统编辑器）
- **AI 集成**: 现有的 `DeepSeekClient` 和 `OpenAIClient`（asyncio + session 管理）

## Appendix

### Glossary

- **审核队列**: 待审核的条目列表，存储在 `review_queue` 表
- **草稿区**: 被拒绝的条目存储区，用户可随时恢复或删除
- **AI Session**: 保持上下文的 AI 对话会话，包括历史信息
- **版本**: 审核过程中的一个快照，记录摘要、标签、评论等
- **Prompt 指导**: 用户用自然语言指导 AI 重新生成内容的命令
