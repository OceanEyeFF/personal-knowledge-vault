## 1. 产品改动与兼容边界

| 问题 | 改动 | 兼容与验证边界 |
| --- | --- | --- |
| R-01 | 公共 rebuild plan 绑定稳定 data-root SHA 和同次已验证 runtime snapshot 的完整字节摘要。 | 不重新读取 snapshot 产生混合身份，不散列秘密配置或私有 HMAC。旧 public plan 须重新 inspect/plan。 |
| R-07 | 同步/异步共用 Q1 archive/delete/apply_ai_patch 执行器；统一 claim/recovery 候选、轮内去重、持久退避与跨轮公平。 | 同 target 不越过未解决前置；无进展不能耗尽单轮额度；只恢复本地产物，不驱动新的 Q2/Provider attempt。 |
| R-08 | 完整叶子路径显式分类；Group 只分派，Click 解析完成后叶子才门禁。 | 共享命令别名按实际调用路径判权；未分类叶子拒绝；Outcome read 仍要求 READY，既有 degraded 只读允许列表不变。 |

产品仅修改 `pkv_kernel/embedding.py`、`src/application/r4_lifecycle.py`、
`src/storage/content_lifecycle.py` 和 `src/main.py`。未修改 CLI command 业务实现、Outcome、
独立 rebuild ledger/policy/stage、迁移 SQL、SDK/API 版本或 capability registry。

v1 公共确认与持久 replay 身份原先共用材料。W2 将确认增加 root/snapshot 绑定，但保留
原 v1 replay 材料和编码，避免已存在 processing 记录因键算法改变而失去防重复效果。
根由各自 ledger 文件隔离；旧 replay 不区分快照是保守围栏，不是允许重复调用的例外。
W1 冻结的 v2 分域 identity、预算期间及 ledger v3 升级继续留 W4。

Q1 不将不确定恢复误记为 rejected，也不抹除已提交 core 事实。恢复使用既有 storage proof，
旧 PROCESSING 在 root lease 下换新的 token/fence 后收敛；不可验证记录保留修复状态。
健康独立任务仍可推进；目标被需修复前置阻塞时返回既有 `repair_required`，后继任务保留。
普通退避不伪装为 repair。异步完整执行仍经 tracked worker，取消时保持 lease 至工作收尾。
