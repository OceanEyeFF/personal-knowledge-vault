## 2. 当前产品定义

Personal Knowledge Vault 当前应被理解为：

**面向 AI 与人的、本地优先的知识操作系统内核。**

它当前的核心不是重交互知识库 GUI，而是：

- 稳定的内容归档能力
- 工作流驱动的处理管线
- 面向 AI Agent 的 MCP 能力
- 混合检索能力
- 可维护、可重建的本地数据底座

---

## 3. 当前不是什么

以下内容不应作为当前阶段的主产品定义：

- 不是 Obsidian 风格的重编辑 GUI
- 不是以视觉和交互体验为主竞争力的桌面应用
- 不是只提供 `search/get/list` 的轻量文档库包装层
- 不是以图谱可视化为当前优先目标的知识图项目

---

## 4. 当前已落地能力

### 4.1 交互面

- `CLI`：归档、搜索、浏览、统计、配置
- `MCP`：基础搜索、详情读取、列表浏览、标签统计、URL/文本归档、关联推荐
- `GUI`：桌面工作台入口，已支持搜索、浏览、归档、设置、统计、聊天等界面

### 4.2 系统能力

- `Workflow`：归档与搜索流程编排
- `Storage`：Markdown 主存储 + SQLite 元数据 + hnswlib 向量索引
- `Retrieval`：BM25、向量检索、混合检索、自动路由
- `AI`：摘要、标签提取、Embedding、基础知识引用
- `Testing`：已有单元、集成、黑盒、E2E 测试基础

---

## 5. 当前关键缺口

当前系统已经具备“检索型 MCP”，但还不具备“可推理知识接口”。

主要缺口如下：

- 缺少正式的 `relation_index / knowledge_graph` 等价层
- `get_related` 仍以向量相似度近邻为主，不等于关系探索
- 缺少多跳查询能力
- 缺少关系解释能力
- 缺少证据聚合能力
- 缺少围绕上述能力的最小评测闭环

---

## 6. 当前主战场

当前阶段的主战场只有三项：

1. `relation_index / knowledge_graph`
2. 推理型 `MCP Tool`
3. 评测与验证机制

GUI 在当前阶段继续保留，但定位收敛为：

- 浏览与调试工作台
- 条目详情与关系结果检查器
- 配置、索引、状态、成本面板

---

## 7. 当前非目标

以下内容当前不应成为主投入方向：

- 重视觉打磨的 GUI 改造
- 知识图谱可视化优先落地
- 多模态范围快速扩张
- 在关系层缺位的情况下继续堆高阶界面功能
- 继续让历史 Prompt 或旧里程碑文档定义当前路线

---

## 8. 当前技术基线

后续设计默认基于以下事实：

- 主存储：Markdown
- 元数据索引：SQLite
- 向量索引：hnswlib
- 检索策略：BM25 / Vector / Hybrid / Auto Router
- 主要交互面：CLI + MCP + GUI Workbench
- 处理范式：Workflow 驱动

如后续发生技术栈切换，应先更新本文件，再更新模块设计与实现文档。

## 10. 增量更新规则

每个 Phase 完成后，至少同步更新以下内容：

1. 本文件中的“已落地能力 / 关键缺口 / 主战场”
2. `README.md` 的能力说明与版本信息
3. `docs/operations/CHANGELOG.md`
4. 对应模块的设计文档或接口文档
5. 如路线发生变化，同步更新 `阶段开发路线与依赖-2026-03.md`

更新原则：

- 不重写历史叙事
- 只修正当前事实
- 已实现与规划中必须明确区分
- 若发现文档与代码冲突，优先修正一级真相源

## 11. 当前一句话结论

PKV 当前阶段最重要的不是继续扩张 GUI 叙事，而是补齐关系层、推理型 MCP 与验证闭环，让 AI 真正把知识库当成可探索、可解释、可组合的知识环境。
