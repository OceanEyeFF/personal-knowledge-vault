## 2. 当前产品定义

Personal Knowledge Vault 当前应被理解为：

**面向 AI 与人的、本地优先的知识操作系统内核。**

它当前的核心不是重交互知识库 GUI，而是：

- 稳定的内容归档能力
- 工作流驱动的处理管线
- 面向 AI Agent 的 MCP 能力
- 混合检索能力
- 可维护、可重建的本地数据底座

---

## 3. 当前不是什么

以下内容不应作为当前阶段的主产品定义：

- 不是 Obsidian 风格的重编辑 GUI
- 不是以视觉和交互体验为主竞争力的桌面应用
- 不是只提供 `search/get/list` 的轻量文档库包装层
- 不是以图谱可视化为当前优先目标的知识图项目

## 4. 当前已落地能力

### 4.1 交互面

- `CLI`：归档、搜索、浏览、统计、配置
- `MCP`：通过 stdio 提供基础搜索、详情读取、列表浏览、标签统计、URL/文本归档、关联推荐；M13 不发布 HTTP/Bearer
- `GUI`：桌面工作台入口，已支持搜索、浏览、归档、设置、统计、聊天等界面；M13 发布搜索只保证 BM25

### 4.2 系统能力

- `Workflow`：只从真实、版本化 YAML 加载 `archive-url` 与 `archive-text` 归档流程；`search.yaml` 不受支持
- `Storage`：Markdown 主存储 + SQLite 元数据 + hnswlib 向量索引
- `Retrieval`：BM25、向量检索、混合检索、自动路由
- `Relations`：已落地关系模型、关系存储、显式迁移、低歧义关系 extraction / backfill 与一跳 query service
- `AI`：摘要、标签提取、Embedding、基础知识引用
- `Testing`：已有单元、集成、黑盒、E2E 测试基础

### 4.3 当前接口快照

当前已核验的交互面如下：

- `CLI` 核心命令：`archive` / `search` / `show` / `list` / `config` / `stats`
- `MCP Tool`：`search_knowledge` / `get_entry` / `list_tags` / `list_entries` / `get_stats` / `archive_url` / `archive_text` / `get_related` / `query_subgraph` / `explain_relation` / `collect_evidence` / `find_bridges` / `timeline_of` / `contrast`
- `MCP Prompt`：3 个
- `MCP Resource`：9 个
- `GUI` 当前视图：`BrowserView` / `SearchView` / `ArchiveView` / `ChatView` / `StatsView` / `SettingsView`

默认自动化继续保持离线：只使用 `.data-test` 隔离根、合成数据与可控 mock；不连接真实 Provider，不读取真实 API key 或真实 Vault。Chat 的 Artifact E2E 将由 W3/W4 的外置 deterministic loopback harness 提供响应，harness/fake provider 不进入 release payload。

### 4.4 当前已验证但边界有限的能力

以下能力真实存在，但边界需要明确：

- `MCP` 当前已进入“检索型 + 最小推理型”接口阶段，但还不是完整的高阶推理接口
- `ChatView` 已支持流式对话、会话 CRUD、知识引用注入、保存对话到知识库
- 知识引用当前通过 `chat_view.py` + `knowledge_ref.py` + `ChatViewModel.set_knowledge_context()` 完成
- 会话持久化当前由 `SQLiteStore` 管理，底层使用 `chat_sessions` 表
- `Phase A / T1+T5` 已新增 `src/relations/models.py`、`src/storage/relation_store.py`、`src/relations/extractors.py`、`src/relations/query_service.py`、`scripts/backfill_relations.py` 与 `knowledge_relations` 迁移脚本
- 关系层当前已完成“低歧义关系”的模型、存储、最小抽取、回填与一跳查询基础，证据先以 JSON 文本字段存储
- 第一版关系抽取当前覆盖 Markdown 显式链接、Front Matter `related_docs`，以及 Front Matter 关系字段 `children` / `version_of`
- 当前正式关系类型为 `references`、`related_document`、`parent_of`、`version_of`
- 当前关系来源类型为 `markdown_link`、`frontmatter_related_docs`、`frontmatter_field`、`manual`、`backfill`；其中自动抽取当前只覆盖前三类
- 当前自动边都归类为“显式事实边”，不包含纯语义推断边
- 回填脚本默认 `dry-run`，只有显式传入 `--apply` 才会写入 `knowledge_relations`
- 当前已补入 `backfill_quality_report.v1` 报告结构，可输出 `mode`、`knowledge_scope`、`quality_gate`、`conflict_samples` 与执行上下文
- 当前 `scripts/backfill_relations.py` 已支持测试副本库上的质量门禁参数：`--min-coverage`、`--max-noise`、`--max-conflict`、`--fail-on-gate`
- query service 当前已支持一跳查询 `list_relations`、`get_neighbors`、`get_relations_between`，以及内部多跳子图遍历 `query_subgraph` 与最小关系解释 `explain_relation`

- `collect_evidence` 当前已固定 `chunk_retrieval_status` 合同：`not_requested` / `success` / `no_hits` / `path_unavailable` / `search_error`
- 当前已新增 `src/relations/exploration_service.py`，提供 `find_bridges`、`timeline_of`、`contrast` 的 `partial-v1` 最小交付；公开响应仍为 `implementation_level=partial`

- 关系查询当前优先按关系类型分组，组内按 `weight DESC -> updated_at DESC -> relation_id ASC` 稳定排序
- 当前工作区还新增了 `RelationSubgraphNode` / `RelationSubgraphResult`，用于固定多跳子图查询的节点、边与截断状态返回结构
- 当前工作区已把关系样例扩展到两跳路径，并新增 `backfill -> query_subgraph` 联通验证
- 当前已把 `query_subgraph`、`explain_relation` 与 `collect_evidence` 暴露为只读 MCP Tool，MCP 当前从“检索型 + 关联推荐”进入最小推理型接口阶段

## 6. 当前关键缺口

当前系统已具备检索型 MCP、最小推理接口、固定离线引用契约和 Phase C
最小评测闭环；三个高阶探索 Tool 已按 `partial-v1` 交付，但仍诚实声明
`implementation_level=partial`，没有升级为 full implementation。

主要缺口如下：

- 关系层已经补上最小 extraction / backfill / 一跳 query，并新增内部多跳子图遍历、最小关系解释、chunk-aware 证据聚合，以及桥接/时间线/对比的 partial implementation；但这些高阶能力仍未形成完整闭环
- `get_related` 仍以向量相似度近邻为主，不等于关系探索
- `collect_evidence` 当前已支持 chunk-aware 路径、稳定 chunk locator 与文档级兼容路径；真实库样本覆盖与更完整的验收口径仍待收口
- `find_bridges` 当前已在显式关系子图与 tags/标题/摘要重合之外，引入局部图桥接信号（断开邻居对、深度跨度）并返回逐跳 `evidence_path`，但不代表完整语义桥接
- `timeline_of` 当前会优先使用 `event_time > published_at > archived_at` 的结构化真实时间字段，并显式返回 source 与时间字段 locator，但不代表正文中的真实事件时间
- `timeline_of` 当前在多时间源并列主导时会把 `inferred_time_field` 返回为 `mixed`，用于避免单一高优先级字段导致整体偏乐观
- `contrast` 当前已在检索候选、tags、摘要与稳定对比维度结构之外，引入跨主题显式关系路径、`relation_graph_signal` 与候选—来源 provenance，但不代表完整语义对比
- 已建立并验收 Phase C 最小离线评测闭环：16 条固定任务通过真实 FastMCP
  `list_tools` / `call_tool` / `read_resource` 执行，当前 fresh run 为 151/151 checks
  （119 项版本化声明式检查 + 32 项自动公开 envelope 检查）、`overall=1.0`、
  全部维度 `1.0`、0 failed、`targets_met=true`。
- 当前独立 baseline proposals 的 Tool 选择/参数/结果、chunk 相关性与
  partial/degraded 可观察性及可引用性均通过，详见
  `docs/operations/MCP最小评测基线-2026-07-29.md`。
- Phase B citation 合同已完成，当前采用 `threshold_enforced` 策略：固定
  报告 schema、独立 gold/proposals、119 项声明式检查、32 项自动公开 envelope 检查与现有阈值；CLI
  `--enforce-thresholds` 将阈值结果升级为退出码门禁。

## 7. 当前主战场

离线基线收口后的工作顺序是：

1. M13 W1/W2 已完成；当前开始 W3 可复现打包链，之后进入 W4 Artifact 验收
2. 按真实需求继续增强探索 Tool 的 full 语义能力，但不得抹去现有 partial 边界
3. 在 U1/G8 与 FT5 交付后，另行规划用户授权的真实快照验证

M13 是离线基线之后的下一阶段，不代表真实数据已经验收，也不解除真实快照前置阻塞。

W1 当前事实（2026-08-07）：

- GUI、CLI、MCP 通过同一个 runtime bootstrap 解析只读 bundled resources 和单一用户数据根
- Markdown 主存储、SQLite/FTS/tags/chunks 必需索引和 Vector 辅助索引具有显式跨存储终态；失败不再被 adapter 伪装为空结果或完整成功
- operation journal v3 使用文件 identity + SHA-256；SQLite `storage_operation_commits` 与业务投影在同一事务提交，commit-after-raise 只按 operation-bound proof 对账
- Vector index/metadata 由持久 pair marker 保护，启动会回滚可证明的中断发布；未知替换保留现场并 fail-closed
- Vault 文件读写、删除、预览、证据读取和关系回填统一做 canonical containment，并拒绝链接、硬链接、same-inode 内容漂移和不可判定路径
- 只有完全不存在的数据库是 fresh；损坏、缺版本表、链/表漂移、旧版和未来版均 fail-closed，Developer Preview 不隐式升级历史库；当前 schema 为 `1.2.4`（9 个迁移）
- Artifact 资源 allowlist 已建立，但实际冻结、可复现构建和 Artifact E2E 属于 W3/W4，尚未完成
- 独立 SubAgent 最终复审未发现确定性 P0/P1；非协作 ABA、Windows 掉电持久序及历史原地升级 WAL/列级 drift 为明确后置边界
- 冻结后离线验收为 unit `1583 passed, 19 skipped`、integration/blackbox/e2e `277 passed, 9 deselected`；未读取或改写真实 `.data/`

W2 当前事实（2026-08-07）：

- Workflow 只执行真实、版本化的 `archive-url.yaml` / `archive-text.yaml`，并固定 step 顺序、trigger、condition、`on_error`、processor route 与 `success/degraded/error` 终态；`search.yaml` 明确不受支持
- Retrieval 的 BM25/Vector/Hybrid/Auto 共用 `success/no_hits/invalid/error/degraded` 合同；GUI、CLI、MCP adapter 不把错误/降级伪装为空结果或成功，BM25 不构造 Provider
- MCP 发布面保持 stdio-only；14 Tools、9 Resources、3 Prompts 的公开 envelope、证据 locator、聚合守恒、SSRF 重校验与错误传播已有 source-level 合同。Phase C 当前为 16/16 tasks、151/151 checks、全部维度 `1.0`
- GUI Chat 将 session 切换、双发、停止、Provider/save 失败收口为互斥的 `completed/stopped/error`，并通过正常 Provider/Workflow seam 完成流式响应、持久化、知识引用与保存；没有内置 fake/test mode
- W2 registry 的受支持、`partial-v1` 及明确 unsupported 源代码能力均为 `source_verified`；MCP HTTP 和由 W3 主责的外置 Chat loopback harness 仍为 `defined`，W4 handoff 全部为 `artifact_pending`
- 四条冻结工作流的独立复审未发现确定性 P0/P1；历史 Vector 非 seed 候选的全量语义扫描作为 fresh-install 范围外 P2 后置，不改变当前 fail-closed 写入/seed 读取合同
- W3/W4 尚未完成；当前没有 `artifact_verified` 结论，也未连接真实 Provider，未读取真实 API key 或 Vault

GUI 在当前阶段继续保留，但定位收敛为：

- 浏览与调试工作台
- 条目详情与关系结果检查器
- 配置、索引、状态、成本面板
