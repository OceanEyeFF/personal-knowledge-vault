## 2. 当前产品定义

Personal Knowledge Vault 当前应被理解为：

**面向 AI 与人的、本地优先的知识操作系统内核。**

它当前的核心不是重交互知识库 GUI，而是：

- 稳定的内容归档能力
- 工作流驱动的处理管线
- 面向 AI Agent 的 MCP 能力
- 混合检索能力
- 可维护、可重建的本地数据底座

---

## 3. 当前不是什么

以下内容不应作为当前阶段的主产品定义：

- 不是 Obsidian 风格的重编辑 GUI
- 不是以视觉和交互体验为主竞争力的桌面应用
- 不是只提供 `search/get/list` 的轻量文档库包装层
- 不是以图谱可视化为当前优先目标的知识图项目

## 4. 当前已落地能力

### 4.1 交互面

- `CLI`：归档、搜索、浏览、统计、配置
- `MCP`：基础搜索、详情读取、列表浏览、标签统计、URL/文本归档、关联推荐
- `GUI`：桌面工作台入口，已支持搜索、浏览、归档、设置、统计、聊天等界面

### 4.2 系统能力

- `Workflow`：归档与搜索流程编排
- `Storage`：Markdown 主存储 + SQLite 元数据 + hnswlib 向量索引
- `Retrieval`：BM25、向量检索、混合检索、自动路由
- `Relations`：已落地关系模型、关系存储、显式迁移、低歧义关系 extraction / backfill 与一跳 query service
- `AI`：摘要、标签提取、Embedding、基础知识引用
- `Testing`：已有单元、集成、黑盒、E2E 测试基础

### 4.3 当前接口快照

当前已核验的交互面如下：

- `CLI` 核心命令：`archive` / `search` / `show` / `list` / `config` / `stats`
- `MCP Tool`：`search_knowledge` / `get_entry` / `list_tags` / `list_entries` / `get_stats` / `archive_url` / `archive_text` / `get_related` / `query_subgraph` / `explain_relation` / `collect_evidence` / `find_bridges` / `timeline_of` / `contrast`
- `MCP Prompt`：3 个
- `MCP Resource`：4 个
- `GUI` 当前视图：`BrowserView` / `SearchView` / `ArchiveView` / `ChatView` / `StatsView` / `SettingsView`

### 4.4 当前已验证但边界有限的能力

以下能力真实存在，但边界需要明确：

- `MCP` 当前已进入“检索型 + 最小推理型”接口阶段，但还不是完整的高阶推理接口
- `ChatView` 已支持流式对话、会话 CRUD、知识引用注入、保存对话到知识库
- 知识引用当前通过 `chat_view.py` + `knowledge_ref.py` + `ChatViewModel.set_knowledge_context()` 完成
- 会话持久化当前由 `SQLiteStore` 管理，底层使用 `chat_sessions` 表
- `Phase A / T1+T5` 已新增 `src/relations/models.py`、`src/storage/relation_store.py`、`src/relations/extractors.py`、`src/relations/query_service.py`、`scripts/backfill_relations.py` 与 `knowledge_relations` 迁移脚本
- 关系层当前已完成“低歧义关系”的模型、存储、最小抽取、回填与一跳查询基础，证据先以 JSON 文本字段存储
- 第一版关系抽取当前只覆盖 Markdown 显式链接与 Front Matter `related_docs`
- 回填脚本默认 `dry-run`，只有显式传入 `--apply` 才会写入 `knowledge_relations`
- query service 当前已支持一跳查询 `list_relations`、`get_neighbors`、`get_relations_between`，以及内部多跳子图遍历 `query_subgraph` 与最小关系解释 `explain_relation`
- 当前已新增 `src/relations/evidence_service.py`，提供文档级 `collect_evidence(question)` 证据包聚合 v1
- 当前已新增 `src/relations/exploration_service.py`，提供 `find_bridges`、`timeline_of`、`contrast` 的 partial implementation
- 查询结果当前提供平铺 `items` 与按 `relation_type` 分组的 `grouped_items`
- 关系查询当前优先按关系类型分组，组内按 `weight DESC -> updated_at DESC -> relation_id ASC` 稳定排序
- 当前工作区还新增了 `RelationSubgraphNode` / `RelationSubgraphResult`，用于固定多跳子图查询的节点、边与截断状态返回结构
- 当前工作区已把关系样例扩展到两跳路径，并新增 `backfill -> query_subgraph` 联通验证
- 当前已把 `query_subgraph`、`explain_relation` 与 `collect_evidence` 暴露为只读 MCP Tool，MCP 当前从“检索型 + 关联推荐”进入最小推理型接口阶段
- 当前已把 `find_bridges`、`timeline_of`、`contrast` 暴露为只读 MCP Tool，但只实现了启发式/弱语义版本，并通过 `implementation_level=partial` 与 `limitation_notes` 显式声明限制
- 迁移工具当前已支持只读 `--health-check`，用于检查脚本链和 `schema_version` 记录健康度
- CLI 当前没有聊天子命令，会话管理入口主要位于 GUI

## 5. 当前明确未实现项

以下内容在当前仓库中应明确视为“未实现”，不能被当作已有能力使用：

- `shared_tag` 等高噪声关系的正式物化策略
- 面向真实数据库的正式 relation backfill 执行仍未进行；当前只提供默认安全的脚本路径
- 独立的 `src/gui/services/` 对话服务层
- 独立的 `src/ai/chat_presets.py`
- `pkv chat ...` CLI 会话命令

说明：

- 这些内容在路线文档中属于目标或候选项
- 在当前仓库中不应被写成“已具备”

## 6. 当前关键缺口

当前系统已经具备“检索型 MCP”，但还不具备“可推理知识接口”。

主要缺口如下：

- 关系层已经补上最小 extraction / backfill / 一跳 query，并新增内部多跳子图遍历、最小关系解释、文档级证据包聚合，以及桥接/时间线/对比的 partial implementation；但这些高阶能力仍未形成完整闭环
- `get_related` 仍以向量相似度近邻为主，不等于关系探索
- `collect_evidence` 当前仍是文档级证据包 v1，不含 chunk 原文落库与精细证据去重
- `find_bridges` 当前只基于显式关系子图和简单度数启发式
- `timeline_of` 当前只按 `archived_at` 排序，不代表真实事件时间
- `contrast` 当前只基于检索候选与表面字段，不代表完整语义对比
- 缺少面向推理型 MCP 的黑盒评测闭环

---

## 7. 当前主战场

当前阶段的主战场只有三项：

1. `Phase A` 关系层补强（抽取 / 回填 / 查询服务）
2. 推理型 `MCP Tool`
3. 评测与验证机制

GUI 在当前阶段继续保留，但定位收敛为：

- 浏览与调试工作台
- 条目详情与关系结果检查器
- 配置、索引、状态、成本面板

---

## 8. 当前非目标

以下内容当前不应成为主投入方向：

- 重视觉打磨的 GUI 改造
- 知识图谱可视化优先落地
- 多模态范围快速扩张
- 在高阶关系能力未完成的情况下继续堆高阶界面功能
- 继续让历史 Prompt 或旧里程碑文档定义当前路线

## 9. 当前技术基线

后续设计默认基于以下事实：

- 主存储：Markdown
- 元数据索引：SQLite
- 向量索引：hnswlib
- 检索策略：BM25 / Vector / Hybrid / Auto Router
- 主要交互面：CLI + MCP + GUI Workbench
- 处理范式：Workflow 驱动

如后续发生技术栈切换，应先更新本文件，再更新模块设计与实现文档。

## 14. 当前一句话结论

PKV 当前阶段最重要的不是继续扩张 GUI 叙事，而是在已落地的关系层基础骨架之上，继续补齐抽取、查询、推理型 MCP 与验证闭环，让 AI 真正把知识库当成可探索、可解释、可组合的知识环境。
