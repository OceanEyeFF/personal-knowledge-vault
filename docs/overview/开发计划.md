## 并行化开发策略

### 理念

四个独立轨道同时推进，最大化开发效率

### Track 1: 基础设施层（Week 1-2）

**交付物**：
- ✅ PostgreSQL + pgvector 环境搭建
- ✅ 数据库 Schema 创建（所有表）
- ✅ 基础 Repository 抽象（CRUD接口）
- ✅ 文件存储管理器
- ✅ 配置管理系统

### Track 2: AI 工作流引擎（Week 1-3）

**交付物**：
- ✅ Slash Commands 框架
- ✅ 工作流配置解析器（YAML）
- ✅ Agent 编排器（协调多个处理器）
- ✅ 进度追踪与日志系统
- ✅ 错误处理与重试机制

### Track 3: 内容处理器（Week 2-4）

**交付物**（可多人并行）：
- ✅ WebArchiver 核心框架
- ✅ 微信文章处理器
- ✅ 知乎内容处理器
- ✅ 通用网页处理器
- ✅ BilibiliProcessor（转录 + 评论）

### Track 4: RAG 检索引擎（Week 2-4）

**交付物**：
- ✅ 策略选择器（自动决定检索策略）
- ✅ BM25 全文检索实现
- ✅ 向量检索集成
- ✅ 混合检索算法
- ✅ 结构化检索（时间轴）

### 依赖关系

```
Track 1 (基础设施)
    ↓ (提供数据层接口)
    ├→ Track 2 (工作流引擎)
    ├→ Track 3 (内容处理器)
    └→ Track 4 (RAG 引擎)

Track 2 ⟷ Track 3: 定义接口后可并行
Track 4 ← Track 1: 依赖数据层，可与 Track 2/3 并行
```

## 里程碑与验收标准

### Phase 0: 原型验证（3-5天）

**目标**: 端到端 Demo，验证技术可行性

**必做任务**：
- [ ] 实现 `/kb:archive-url` 处理知乎文章
- [ ] BM25 检索能找到刚存入的文章
- [ ] 完整的日志和进度展示

**成功标准**：
- ✅ 一条命令完成"链接→知识库"
- ✅ 检索能返回正确结果
- ✅ Claude Code 能自主完成流程（人工介入 < 2次）

### Phase 1: 网页归档 MVP（Week 1-2）

**目标**: 完整的网页归档能力

**交付**：
- [ ] 支持微信、知乎、通用网页
- [ ] AI 生成摘要和标签
- [ ] BM25 检索工作正常

**成功标准**：
- ✅ 归档 50 篇文章，准确率 > 90%
- ✅ 检索准确率 > 85%（人工评估）

### Phase 2: B站视频处理（Week 2-3）

**目标**: 视频转文本 + 评论分析

**交付**：
- [ ] 音频转录（Whisper）
- [ ] 评论抓取与分析
- [ ] 时间轴索引

**成功标准**：
- ✅ 转录准确率 > 90%（抽样检查）
- ✅ 支持时间点查询

### Phase 3: 智能检索优化（Week 3-4）

**目标**: 混合检索策略

**交付**：
- [ ] 自动策略选择
- [ ] 向量检索
- [ ] 混合排序

**成功标准**：
- ✅ 检索准确率 > 90%
- ✅ P95 响应时间 < 500ms

### Phase 4: 整合与优化（Week 5-6）

**目标**: 系统稳定性

**交付**：
- [ ] 完整测试覆盖
- [ ] 错误处理
- [ ] 性能优化
- [ ] 用户文档

## 成本与资源

### API 调用成本

**假设**：
- 每天归档 10 篇内容（平均 3000 字）
- 每天检索 50 次
- 每周处理 2 个视频（平均 20 分钟）

**月度成本**: ~$1.45/月

**年度成本**: ~$17.4

### 基础设施成本

| 项目 | 方案 | 成本 |
|------|------|------|
| **服务器** | 本地运行（个人电脑） | $0 |
| **数据库** | PostgreSQL（本地） | $0 |
| **存储** | 本地硬盘（100GB 足够 1 年） | $0 |
| **总计** | - | **$0/月** |

**扩展成本**（可选）：
- 云端备份（对象存储）: ~$2/月
- VPS 部署（如需 24/7 运行）: ~$5/月

### 人力资源

**开发团队**（建议）：
- 1 人全栈开发（可独立完成）
- 每周投入 15-20 小时

**技能要求**：
- Python 后端开发
- 数据库设计
- AI API 调用经验
- 基础前端（第二期）

## 风险管理

### 技术风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| **API 限流/封禁** | 高 | 中 | 多 API 提供商备份、请求限速、本地模型备选 |
| **Whisper 成本超预期** | 中 | 高 | 评估本地 Whisper 部署、选择性转录、限制处理频率 |
| **向量检索性能不足** | 中 | 低 | MVP 阶段数据量小（< 1万）、预留 Qdrant 迁移方案 |
| **网页结构频繁变化** | 低 | 高 | 使用通用 Readability 算法、多个提取策略备选 |

### 数据风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| **数据丢失** | 高 | 低 | PostgreSQL 自动备份（每日）、Git 版本控制、定期导出 |
| **隐私泄露** | 高 | 低 | 本地存储优先、API 调用脱敏、敏感内容加密 |
| **AI 生成质量差** | 中 | 中 | 人工审核机制、多模型对比、质量评分系统 |

### 项目风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| **需求变更** | 中 | 高 | 模块化设计、快速迭代（每周发布）、MVP 优先 |
| **技术债务积累** | 中 | 中 | 代码审查、单元测试覆盖 > 80%、定期重构 |
| **时间超期** | 低 | 中 | 并行开发、里程碑管理、削减非核心功能 |

### 应急预案

**API 服务中断**：
- 主方案: DeepSeek
- 备选 1: OpenAI GPT-3.5
- 备选 2: 本地 Ollama（降级方案）

**数据恢复流程**：
1. 每日自动备份到本地另一磁盘
2. 每周备份到云端（加密）
3. Git 仓库备份 Markdown 文件
4. 提供一键恢复脚本
