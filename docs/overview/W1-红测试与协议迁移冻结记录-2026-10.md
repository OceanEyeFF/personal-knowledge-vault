## 3. 故障注入与证据边界

R-02 使用 Event barrier 与另一线程的真实 writer lease，无 sleep。断言先证明合成 Provider
文档/分块各调用一次、四个 stage artifact 完整、争锁时共享 ledger 字节和 pointer 未变，再验证
安全 pending 错误。它冻结共享 Core 的错误分类；旧 v1 入口也须透传该分类，只有新 v2
入口提供 publish-only 继续。

R-03 用 SQLite authorizer 拒绝实际 state UPDATE，不能在测试中伪造 service 成功或只抛一个
未到达写入窗口的异常。R-05 注入 pointer commit 前故障并保留真实已发布文件。Outcome/Q1
重建 Application 验证持久事实，只是进程内 reopen，不冒充真实 OS 进程重启。

R-04 使用现有公共 SDK 无版本符号；它要到 W5 旧入口拒绝时才转绿，兼容期仍保持 known_gap。
exact v2 四元组审批的正反例另在 W3 编写，不能用这两个旧入口红例代替新协议验收。

CLI 使用真实 offline_entrypoint 子进程，公开 inspect 先证明 absent/READY 状态，再比较
parse-only 请求前后的数据树。未合成损坏用户配置，也未改动 G0。

以下仍为 planned / not_run：完整 ER/OC/Q1/CLI 矩阵、v2 公共继续发布、CLI/MCP 跨进程
恢复、损坏合成配置、MIG-01–10、兼容弃用版本、major-2/installed-wheel 验收。
本轮未运行全量 P0、MCP 覆盖率或 Artifact 验收，不产生新的整体通过或 release 声明。

## 4. 后续实现起点

W2 先处理 R-01、R-07、R-08；W3 实现 Outcome 输入事务、任意版本发布与 v2 review；
W4 在统一 identity 上实现 sealed proof、原操作发布继续与额度重入；W5 才完成 major 切换、
旧无版本入口拒绝以及整体证据收口。任何 DTO、持久字段或错误语义变化须先同步两份冻结合同。

014 SQL、backfill hook 与 MIG 用例留 W3；ledger/proof 实现和升级用例留 W4。迁移编号已预留，
原 013 保持原样，没有运行真实或合成迁移。API-major-2、两项 v2 capabilities 均为未来目标，
本轮不提高当前版本或 release 资格。
