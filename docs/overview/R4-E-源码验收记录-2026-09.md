## 1. 范围与结论

R4 将归档实现为持久但非 daemon 的内部生命周期：

```text
公开 CLI / MCP stdio archive
  -> Q0 admission + private PreparedDocument
  -> Q1′ Markdown + SQLite core commit + durable handoff
  -> Q2 policy / reservation / Provider / DerivationPatch
  -> Q1′ patch commit + staged generation / validate / pointer CAS
  -> READY generation-backed vector / hybrid retrieval
```

该历史基线的 Application 在一次允许的 mutation 中有界 drain 上述任务；进程退出后没有独立后台
worker。只读 CLI/MCP、status、search 与 related 不取得 lease、不 drain、不创建 Provider，
也不写 data root。

下一主线已确认但待实现的规则要求新 AI retry 经显式 plan/confirm/execute；历史自动 drain
证据不能证明这一新合同。Q1 对已完整物化 patch 的本地提交/恢复不等于再次调用 Provider。

公开接口没有新增 rebuild API、CLI rebuild 命令或 MCP rebuild Tool。R4 的 source acceptance
证明既有 `archive*`、`show/get_entry` 和 vector/hybrid search 能正确投影该内部生命周期，
而不是扩大产品发布面。

## 3. 外置 deterministic Provider harness

`tests/harness/r4_openai_compatible_provider.py` 是测试拥有的独立进程，不是产品代码、
Artifact payload 或隐藏 test mode。它只实现正式 OpenAI-compatible 配置可调用的非流式
chat completion 与 embedding 端点，并以固定模型、维度、向量、usage 和版本化步骤脚本给出
确定性响应。

- harness 只监听随机 `127.0.0.1` numeric-loopback 端口；端口、DataRoot、配置和 state dir
  每个场景独立。
- 测试运行器只为该精确 loopback endpoint 放行 Provider 使用的 resolver/connection helper；
  DNS、hostname 和所有非 loopback 网络仍 fail-closed。产品 SSRF/SafeFetcher 策略没有放宽。
- barrier 以事件/有界 timeout 协调 Provider 调用并证明 writer lease 未被持有；测试不依赖
  `sleep` 作为正确性同步。
- telemetry 只保存 endpoint、阶段、计数与摘要 hash，不保存 prompt/body、密钥或 Authorization。

## 5. 已知后续边界

| 场景 | 当前结论 | 原因和后续条件 |
| --- | --- | --- |
| MCP `archive_url` 成功的离线黑盒 | 不作为 R4 source acceptance 成功路径 | SafeFetcher 正确拒绝 loopback；当前没有既不削弱 SSRF 又能公开注入外置 fetch harness 的合同。DNS/redirect 的 fail-closed、零写测试保留。 |
| 失败或预算暂停后，仅靠新 CLI/MCP 只读入口恢复同一 task | 历史 public-resume 缺口；新显式 retry 目标未验收 | 读入口不得 drain。旧实现依赖下一次允许 mutation/内部 trigger；下一主线要求新 Provider retry 显式批准，本记录不覆盖该目标。 |
| Provider 调用中强杀进程后的即时重领 | 后续测试基础设施项 | 没有公开测试时钟、durable provider-start 标记或缩短 claim 的产品合同；不得为测试加入后门或削弱 fence。 |
| `accepted` / `retry_required` patch 后由同步 Kernel delete 推进 | 2026-10 已确认缺陷；修复待实现、未验收 | 现有同步消费者只处理 archive/delete，却领取全局 Q1 队列；合法 patch 会反复 retry 并阻塞删除。按 Q1-01..Q1-05 验证完整动作分发、退避/公平进展、至多一次应用与零额外 Provider。 |

这些边界保留已覆盖场景的历史证据，同时限制其可外推范围；不得继续将其称为所有 Q1 入口与
动作组合均已恢复收敛。后续 Q1 修复、下一主线、public rebuild adapter、Node、Docker、GUI
和真实数据验证分别按对应工作包与授权门禁推进；均不改变 release compliance hold。
