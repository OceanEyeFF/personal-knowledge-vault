## 五、当前主要风险 / 卡点

1. 推理能力仍偏“弱语义 + 启发式”，高阶结果可解释性和稳定性有限。
2. relation backfill 仍以安全路径为主，真实库正式回填与验证尚未形成标准化节奏。
3. `collect_evidence` 已支持 chunk-aware 路径与文档级兼容路径，但 chunk 证据质量门禁与更完整验收仍待收口。
4. `find_bridges`、`timeline_of`、`contrast` 仍属于 partial implementation，缺少完整语义桥接、正文事件时间抽取与高级对比建模。
5. 缺少面向推理型 MCP 的可持续评测基准（数据集 + 指标 + 回归门禁）。

## 六、下一步优先建议（按 ROI 排序）

1. **先做 Phase C 最小闭环**：定义 10~20 条代表性推理任务，固化输入/期望输出/评分规则。
2. **补强 Phase B 三个 partial 工具**：为 `find_bridges/timeline_of/contrast` 增加更明确的数据约束和置信度字段。
3. **推进真实库回填演练**：在测试副本库执行 `--apply` 回填并产出质量报告（覆盖率、噪声率、冲突率）。
4. **将“完成定义”前置**：给 Phase B/C 分别设可量化 Exit Criteria（例如成功率、解释可读性、误报率）。
