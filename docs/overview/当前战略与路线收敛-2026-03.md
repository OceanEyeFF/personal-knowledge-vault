## 2. 当前统一定位

Personal Knowledge Vault 当前应被定义为：

**面向 AI 与人的、本地优先的知识操作系统内核。**

它的核心不是做一个重交互、重编辑体验的知识库 GUI，而是提供：

- 稳定的知识归档能力
- 可组合的工作流能力
- 面向 AI Agent 的 MCP 能力
- 混合检索与关系探索能力
- 可验证、可维护、可重建的本地数据底座

更直接地说：

- `GUI` 是辅助工作台，不是主产品定义
- `MCP` 不是附属接口，而是一等交互面
- `关系层` 和 `多跳检索层` 是下一阶段最值得投资的差异化能力

## 3. 当前事实基线

从现有代码、README 和近期设计文档看，当前项目已经不再处于“原型设想期”，而是具备了以下现实基线：

### 3.1 已成形的能力层

- `CLI`：用于归档、搜索、浏览、统计、配置
- `MCP`：已具备搜索、详情读取、列表浏览、归档、关联推荐，以及最小关系推理与受限探索能力
- `GUI`：已经不是纯计划项，而是实际存在的桌面入口
- `Workflow`：仍然是核心编排机制
- `Storage`：Markdown 主存储 + SQLite + hnswlib 的组合已经成为事实标准
- `Relations`：已具备基础模型、存储、迁移、最小 extraction / backfill、一跳查询、多跳子图、关系解释与 chunk-aware 证据包聚合；桥接/时间线/对比已按 `partial-v1` 交付，公开合同仍为 `implementation_level=partial`
- `Evaluation`：Phase C 固定离线闭环已达到 16/16 tasks、119/119 checks、`overall=1.0`、`citability=1.0`、0 failed、`thresholds_met=true`
- `Operations`：FT7 Direct Python 离线入口与开发 vault 重建脚本已交付；合成重建演练达到 `rebuilt -> up_to_date -> checked`（schema `1.2.4`、9 migrations、3 seed）

### 3.2 当前最重要的能力缺口

当前系统已经从“检索型 MCP”进入“最小可推理知识接口”阶段，但高阶推理闭环仍未完成。

缺口主要体现在：

- `get_related` 仍更像近邻推荐，不是稳定的知识网络探索接口
- `collect_evidence` 当前已支持 chunk-aware 路径（`include_chunks=True`）与文档级兼容路径（`include_chunks=False`），并通过 `chunk_retrieval_status` 区分 `success` / `no_hits` / `path_unavailable` / `search_error`
- `find_bridges` 当前已引入局部图桥接信号与轻量文本重合，但仍缺少全局中心性与语义关系边
- `timeline_of` 当前优先使用 `event_time > published_at > archived_at` 的结构化真实时间字段；当多种时间源并列主导时 `inferred_time_field` 返回 `mixed`，但仍不代表正文事件抽取后的真实时间线
- `contrast` 当前已引入跨主题显式关系路径与 `relation_graph_signal`，但仍缺少争议/补充/因果等高级语义对比建模
- 离线最小评测闭环已经形成；尚未覆盖的是需用户授权的真实快照验证，而不是 Phase C 固定评测
- 真实快照仍受用户明确授权与 U1/G8 阻塞；其中 migration 场景另需 FT5，本轮没有执行真实数据

## 4. 战略收敛结论

### 4.1 当前主战场

离线基线收口后的顺序应明确为：

1. `M13` 离线开发与发布准备
2. 根据实际需求继续增强 `partial-v1` 探索 Tool 的 full 语义能力
3. 用户明确授权且 U1/G8 交付后，再规划真实快照验证；只有 migration 场景另需 FT5

M13 是离线基线后的下一阶段，不等于真实数据验收。

当前默认发布面是 Windows-first、offline、fresh-install 的 Developer Preview，支持 GUI、CLI 与 MCP stdio；HTTP MCP、原地升级、真实数据质量和三个探索 Tool 的 full 语义均不默认纳入 M13。

### 4.2 GUI 的定位

GUI 继续保留，但定位应收敛为：

- 浏览与调试工作台
- 归档结果和任务状态查看器
- 关系链和条目详情检查器
- 配置、索引、成本和系统状态面板

不再把 GUI 定义为当前阶段的主要竞争力来源，也不以“替代命令行”为近期首要成功标准。

### 4.3 审核系统的定位

审核系统属于“工作流完整性增强”，它有价值，但不应遮蔽主线判断：

- 审核系统解决的是 AI 输出可控性问题
- MCP + 关系层解决的是知识环境可推理性问题

两者都重要，但后者更接近 PKV 的长期护城河。

## 5. M13 近期执行路线（W1-W4）

2026-08-01 已确认沿用现有开发文档维护 M13，不再新建平行规划。详细范围、依赖和 DoD 以
[`阶段开发路线与依赖-2026-03.md`](./阶段开发路线与依赖-2026-03.md)
为执行真相源，本节只保留战略摘要。

### W1：运行时布局与数据安全底座

- 收口跨存储一致性、补偿/修复终态和 Vault containment
- migration 至少做到损坏库不冒充 fresh，备份或迁移失败不继续、不半提交
- 拆分 bundled 只读资源与 local config、DB、Vault、vectors、logs、tmp 等用户可写目录

W1 是 W2-W4 的硬前置；除非 M13 明确承诺原地升级，否则完整历史迁移矩阵与 FT5 不进入当前范围。

状态复核（2026-08-07）：W1 已按详细路线完成实现、合成故障注入和独立安全复审；SQLite operation-bound commit proof、Markdown identity + SHA-256 与 Vector 持久 pair marker 已纳入冻结合同。离线验收为 unit `1583 passed, 19 skipped`、integration/blackbox/e2e `277 passed, 9 deselected`，W2 可以开始。完整范围、后置风险与 DoD 仍以链接的详细路线为准；该状态不代表 W2 功能合同、W3 Artifact 或 W4 发布审查已经完成。

### W2：已发布功能合同

以下四条工作流可在 W1 合同稳定后并行：

- Workflow：真实 YAML 的 step、`on_error`、trigger、condition 与 processor 路由
- Retrieval：优先区分 `success/no_hits/invalid/error/degraded`；精确 RRF 后置 P1
- MCP：provider、SSRF 与 stdio；HTTP Bearer 仅在 HTTP transport 被纳入发布面时阻断
- GUI Chat：session 切换、双发、停止及 provider/save 失败的互斥终态

已声明的三个 `partial-v1` Tool 可以保留，但必须继续通过既有 oracle 且不得冒充 full；其他发布能力不能用含混的“部分支持”规避合同，无法满足时必须从 M13 支持面移除。

### W3：可复现打包链

- 从干净 checkout 通过单一非交互入口生成 Windows Artifact
- 显式打包配置、workflows、migrations、Qt/native 依赖及许可证材料
- 记录版本、构建指纹、Artifact 哈希与第三方依赖
- 交付独立的 deterministic loopback Provider E2E harness；它不进入 release payload，Artifact 只通过正常 provider 配置接入，不增加测试后门
- 保证安装包不携带密钥、local config 或 Vault 数据

### W4：Artifact E2E、文档与发布审查

- 在无需 Python/Conda/源码的环境中验证安装、初始化、GUI/CLI、离线归档、外置 harness 驱动的 Chat、MCP stdio、升级拒绝与卸载
- 保持默认离线全量、MCP coverage gate 和 Phase C 16-task 门禁通过
- 完成安装、数据位置、配置、备份恢复、升级/卸载、故障排查和 `partial-v1` 限制文档
- 应用、文档与 Artifact 统一为 `0.8.1`，最终给出明确 `release / hold`

### 后置路线

- P1：POSIX/CI G0 parity、精确 RRF/并发 hardening，以及按需求逐 Tool 的 full 语义增强
- P2：默认休眠的真实数据线；如恢复，先取得用户明确授权并完成 `FT1 → U1/G8`，再按 migration/MCP evidence/delete 指标启用 FT5/FT6/FT3；不再把认真重建本地 Vault 作为近期工作
- P3：重视觉、复杂编辑器、图谱可视化与多模态扩张

## 6. 当前阶段的非目标

以下内容不应作为当前阶段的主投入方向：

- 重视觉打磨的 GUI 设计
- 为 M13 新增复杂编辑器或知识图谱可视化
- 视频/PDF 等多模态扩张
- 默认启用 HTTP MCP、历史库原地升级或真实数据验收
- 在没有真实需求和 full 专属评测前整体晋级三个 `partial-v1` Tool
- 为了完整而继续扩张历史 Prompt 路线
