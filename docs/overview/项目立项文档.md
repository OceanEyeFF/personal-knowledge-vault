## 项目概述

### 1.1 项目背景与问题

在信息密度持续升高的环境里，知识工作者每天会接触大量值得长期保存的内容：

- 网页文章：微信、知乎、技术博客、长文分析
- 对话记录：聊天、讨论、AI 对话、工作笔记
- 个人沉淀：项目总结、随手记录、观点草稿

这些内容的典型问题并不是“收集不到”，而是：

- 保存之后难以稳定回找
- 手工整理成本过高
- 关键词检索和纯向量检索都各有明显短板
- 内容之间缺乏可利用的关系结构
- AI 无法把知识库当作一个可操作、可探索、可解释的环境

### 1.2 当前项目定位

PKV 当前应被定义为：

**面向 AI Agent 与人的、本地优先的知识操作系统内核。**

它不是以 GUI 为核心竞争力的可视化笔记软件，而是以以下能力为核心：

1. **AI-First 协作**：AI 不是外挂工具，而是知识处理与探索过程中的一等参与者
2. **工作流驱动**：归档、分析、检索、审核、入库都可以被清晰编排
3. **MCP 一等能力**：知识库不仅供人搜索，也供 AI Agent 直接调用
4. **本地优先**：Markdown 主存储，SQLite 与向量索引为辅助层，确保数据主权
5. **关系与推理导向**：下一阶段重点不是做更重的 GUI，而是增强关系层和多跳探索能力

### 1.3 当前核心价值主张

- **效率**：降低知识归档、整理、回找的时间成本
- **智能**：结合关键词、语义和结构化关系做更稳定的检索
- **沉淀**：把内容从“文件集合”推进为“可探索知识环境”
- **协作**：让 CLI、MCP、GUI 都能围绕同一套知识底座工作
- **可控**：本地存储、可重建索引、可审核 AI 输出

## 当前范围与边界

### 2.1 当前已成形的能力

- `CLI`：归档、搜索、浏览、统计、配置
- `MCP`：搜索、详情读取、列表浏览、归档、关联推荐
- `GUI`：桌面工作台，支持浏览、归档、搜索和 AI 交互
- `Workflow`：YAML 驱动的工作流编排
- `Storage`：Markdown 主存储 + SQLite 元数据索引 + hnswlib 向量索引

### 2.2 当前阶段主战场

当前阶段最重要的投入方向是：

1. MCP 从“工具集”升级为“可推理知识接口”
2. 构建 `relation_index / knowledge_graph` 等关系层
3. 增强多跳检索、关系解释、证据聚合能力

### 2.3 GUI 的阶段性定位

GUI 保留且继续维护，但当前定位收敛为：

- 工作台
- 浏览与调试入口
- 归档状态、关系结果、配置与统计面板

GUI 不是近期主战场，也不是当前最核心的差异化来源。

### 2.4 当前明确不作为主线的方向

- 以重视觉交互为目标的大规模 GUI 打磨
- 在关系层缺位前优先推进知识图谱可视化
- 优先扩展视频/PDF 等多模态能力，而忽略知识推理中层
- 继续把历史 Prompt 文档当作当前路线定义文档

## 核心设计理念

### 3.1 AI-First 协作

本项目的目标不是“让 AI 帮忙写几个摘要”，而是让 AI 能稳定参与以下过程：

- 归档内容
- 搜索与浏览
- 拉取上下文
- 发现关联
- 沿关系继续探索
- 在必要时接受用户审核与修正

### 3.2 工作流驱动

每个常用操作都应有明确的工作流边界：

- 输入是什么
- 处理中间状态是什么
- 哪一步可以审核、回退、补充
- 最终入库和索引的结果是什么

工作流是 PKV 的组织骨架，而不是单纯的实现细节。

### 3.3 本地优先与可重建

设计原则：

- Markdown 是长期事实源
- SQLite 与向量索引是辅助层
- 索引损坏可重建
- 配置与数据路径可控
- 用户能够长期掌握和迁移自己的知识资产

### 3.4 从检索走向关系探索

项目早期核心问题是“如何更好地搜到内容”，当前阶段则需要更进一步：

- 不只返回相似结果
- 还要解释为什么有关
- 支持从一个知识点走到另一个知识点
- 支持聚合证据，而不是只给一个匹配项

这意味着项目将从“混合检索知识库”继续向“可推理知识环境”推进。

## 当前交互面定义

### 4.1 CLI

作用：

- 面向开发者和高频用户的直接操作入口
- 适合归档、搜索、调试和批量操作

### 4.2 MCP

作用：

- 面向 Claude Code、Codex、Cursor 等 AI Agent 的标准接口层
- 让 AI 直接把 PKV 当作外部知识环境使用

### 4.3 GUI

作用：

- 面向日常浏览、检查、调试和部分交互场景
- 提供工作台，而不是承担全部产品定义

## 下一阶段判断

### 5.1 近期优先事项

- 关系类型建模
- 关系索引与查询层设计
- 高阶 MCP Tool 设计与实现
- 多跳探索与证据聚合评测

### 5.2 代表性能力目标

下一阶段建议优先围绕以下能力展开：

- `query_subgraph`
- `explain_relation`
- `collect_evidence`
- `find_bridges`
- `timeline_of`
- `contrast`

当前实现补注（2026-03-11）：

- `query_subgraph`、`explain_relation`、`collect_evidence` 已在当前代码基线中落地
- `find_bridges`、`timeline_of`、`contrast` 已进入 partial implementation 阶段
- 当前最需要继续投入的不是“是否开始做这些能力”，而是补齐它们依赖的上游数据基础设施与评测闭环

### 5.3 预期结果

完成这些能力后，PKV 将不再只是“一个可搜索的本地文档库”，而会更接近：

**一个能够被 AI 稳定理解、调用和沿关系网络探索的本地知识环境。**
