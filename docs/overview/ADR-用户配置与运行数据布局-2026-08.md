# ADR：用户配置与运行数据布局

**状态：已接受（R0/R1）**
**日期：2026-08-20**

## 背景

PKV 当前是个人知识数据库：负责管理互联网信源、历史新闻和过往文章；`个人文章`
等应用只是它的调用方。CLI、MCP 与未来 GUI 必须共享同一个 PKV 数据根，但用户只
需要编辑一份配置。历史实现把业务配置、密钥和 data-root 内的
`config/local.yaml` 混为一层，且曾以 `%LOCALAPPDATA%` 为默认根，无法表达“先读取
用户配置、再决定数据根”的优先级。

此前 held release candidate 中出现的 `%LOCALAPPDATA%\PersonalKnowledgeVault` 是历史
候选合同/证据，不是本 ADR 的产品政策；R1 不迁移、删除或接管那个目录。

## 决定

运行时严格划分三个平面：

```text
bundled resources（只读）
└── config/config.yaml                         默认业务配置，不含私钥

%USERPROFILE%/.pkv/                            用户 profile
├── config.yaml                                唯一可编辑业务配置，可含 Key/Cookie
└── data/                                      默认 data root
    ├── config/local.yaml                      内部 runtime contract snapshot，无敏感字段
    ├── db/knowledge_vault.db
    ├── vault/
    ├── vectors/
    ├── logs/
    ├── tmp/
    ├── backups/
    └── runtime/
```

`<data-root>/config/local.yaml` 不是用户业务配置、不会 merge 到 `Config`，也不会由
CLI/GUI 设置写入。读取该快照时，任意层级的 key/cookie/auth/token/authorization 等
凭据形字段都 fail-closed；异常不得回显键名或值。R1 只提供读取/验证边界，不定义
快照写入者、revision 或 Embedding payload schema；这些由后续 embedding/runtime
lifecycle 工作在持有写 lease 后定义。

## 解析与快照语义

每个 `Config` 是不可变的解析快照，解析过程本身零写入：

```text
bundled defaults + 用户 config.yaml
  → PKV_DATA_ROOT（若设置）
  → 用户 storage.data_root
  → 用户 storage.data_dir（只读弃用兼容）
  → %USERPROFILE%/.pkv/data
  → 从最终单一根派生 db/vault/vectors/logs/tmp/runtime
```

`PKV_DATA_ROOT` 和 `PKV_LOG_LEVEL` 是唯一正式产品环境变量。旧 `DATA_DIR`、细粒度
子路径变量与 `LOG_LEVEL` 只在 `PKV_TEST_OFFLINE=1` 的隔离测试注入中兼容，且所有
子路径仍必须 containment 在该测试数据根内。

配置 reload 可以重新构造新快照，但不能以“reload”名义偷偷换 data root：调用方必须
比较 `Config.data_root_identity`，发现不同根时进入明确的 inspect → plan → confirm
流程，由 lifecycle 层拒绝直接发布。R1 暂不实现自动切换、数据迁移或索引重建。

## 兼容策略

- `Config.user_config_path` 是新正式路径；`Config.runtime_config_path` 是内部快照路径。
- `Config.local_config_path` 和 `Config.update_local_config()` 保留一个 API-major 的
  弃用兼容，但它们指向/写入 **用户** `config.yaml`，而不是 runtime snapshot。
- `RuntimeLayout.local_config_path` 为既有 runtime 调用保留为 snapshot alias；新代码
  应使用 `RuntimeLayout.runtime_config_path`。
- `storage.data_dir` 仍可读取，产生弃用警告；新配置应写 `storage.data_root`。

## 迁移与安全边界

旧目录或旧配置只能遵循 **inspect → plan → 展示影响范围/备份策略 → 用户确认 →
execute → smoke test**。没有确认不得创建迁移副本、移动数据、重写配置或删除旧目录。
用户 profile 和 data root 分别进行 link/reparse point/hardlink/路径状态校验；用户配置
不复用 data-root containment 规则。

默认测试必须通过 `scripts/run-test.ps1` 的 `.data-test` 根运行，不能探测真实 home、
真实 Vault、Provider 凭据或执行真实迁移。

## 非目标

- 不发布 PyPI、不修改 release hold、安装器或 MCP stdio-only 合同；
- 不在 Core 重新引入 GUI；
- 不自动管理旧 `%LOCALAPPDATA%` held candidate；
- 不在 R1 定义向量索引重建、备份/回滚、跨版本迁移或多进程写 lease 的完整生命周期。
