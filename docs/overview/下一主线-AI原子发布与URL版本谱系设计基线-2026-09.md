## 1. 决策摘要

下一主线保留 R4 的 Q0 admission、Q1′ 唯一内容提交者、Q2 fenced Provider 调用和
generation-only retrieval 基础，但替换其 AI 完成、重试、费用和 URL identity 语义。

1. 对每个 AI 轮次采用本地的“全成或不发布”。这不是跨 PKV 数据库与外部 Provider 的
   exactly-once 承诺：进程中断后，Provider 可能已执行请求，但 PKV 不发布该次的部分 AI
   结果。
2. LLM 派生与 Embedding generation 是两个独立的原子轮次。每轮只能在其完整输出通过
   验证后发布；Q2 只有全部相关轮次已发布后才是 completed。
3. Q0/Q1′ 的核心归档与 AI 生命周期分离。核心 Markdown + SQLite 已提交、AI 未发布时，
   对外是 core_committed 加 ai_retry_required 或 ai_attempt_unknown，不是“归档失败”。
4. Provider 创建和调用始终在 writer lease 外；最终发布重新以 task/fence/CAS 验证。私有
   stage 只属于一个 task/attempt/fence，读路径不可见。
5. retry 不再由任意后续 mutation 自动触发。用户必须通过公开 plan/confirm/execute 动作
   明确批准；每次 retry 创建新的 attempt。
6. 默认费用模式是 reference_only：显示 actual、estimated、unconfirmed 三类事实，不把
   它们默认变成硬阻断。enforced 是用户显式开启的可选模式，才使用 reservation、hard cap、
   budget_paused 与 authorization_required。
7. URL 按“规范 URL + source snapshot fingerprint”建立不可变版本谱系。相同快照复用既有
   knowledge_id；内容变化创建新 knowledge_id，并形成 new --supersedes--> old。
8. 核心内容与 AI artifact 都不可变。后续同一核心 revision 的 AI artifact 不得静默覆盖
   已选 artifact；需要显式选择。

用户提供的行业调研结论只作为本 ADR 的设计背景：外部 Provider 一般不能与本地数据库共同
构成 crash-safe exactly-once 事务。因此本设计只承诺本地 publish 原子性、可审计的不确定
外部影响和诚实的用户提示，不声称 Provider 从未执行或请求绝不重复。

## 3. 术语与不可变边界

| 名称 | 含义 | 可否公开读取 |
| --- | --- | --- |
| core revision | 一次 Q1′ 已证明的 Markdown + SQLite 内容版本；新内容创建新 knowledge_id，而非改写该版本。 | 可，通过既有 entry DTO。 |
| AI attempt | 一次经用户授权或初始自动化启动的外部工作尝试；有唯一 attempt_id、claim/fence、输入和 policy snapshot。 | 仅投影安全状态、计量类别和下一步；不公开 prompt、正文、密钥或 raw Provider response。 |
| AI round | 一个 attempt 中的 LLM 派生轮或 Embedding generation 轮。每轮单独 all-pass-or-no-publish。 | 仅投影已发布/待重试/外部效果未知等状态。 |
| AI artifact | LLM round 完整验证后的不可变 summary/tags/typed patch 产物。 | 被选择后以 entry 的派生视图出现；原始未选择 artifact 不成为默认内容。 |
| selected artifact | 某 core revision 当前经确认的 LLM artifact。第一个有效 artifact 可成为首次选择；后续 artifact 只能 available_unselected，等待显式选择。 | 是，带 artifact identity/revision，而不是可变 inline 字段。 |
| source series | 一个 URL 演进链，含一个或多个规范 URL alias 和多个不可变 knowledge version。 | 是，使用 opaque series_id 与安全 canonical URL。 |
| source fingerprint | 规范 URL、标题、规范化正文及版本化 extraction metadata 的摘要；不含 AI、archive time、Provider 信息或 raw HTML。 | 只公开摘要和稳定 identity，不公开私有抓取物。 |

原始网页 HTML 只可在 Q0 的受控抓取内存或私有、短生命周期临时资产中存在；core commit 后必须
释放。图片/文件附件采用独立后续合同，本工作包不把它们视为网页原始副本的例外。

## 4. 目标生命周期

~~~text
公开 archive_url / archive_text
  -> Q0 admission + task-scoped temporary assets
  -> Q1′ immutable core commit
  -> source-version decision
       same fingerprint: return existing version, no Q2 Provider
       changed fingerprint: new knowledge_id + supersedes edge
  -> durable AI task (core_committed)

AI task
  -> eligible initial run, or explicit user-approved retry plan
  -> claim(task_id, attempt_id, fence)
  -> durable request-intent / policy / source recheck
  -> release writer lease
  -> Provider calls
  -> short fenced publish lease
       LLM round: complete validated immutable artifact
       Embedding round: complete validated generation + READY CAS
  -> Q2 completed only when every required round is published
~~~

### 4.1 本地全成或不发布

LLM round 可以仍由 summary 和 tags 两个正式 Provider 请求组成，但其本地发布点只有一个：
summary 非空且受长度限制、tags 满足规范化合同、typed patch 与输入 core revision 对齐、敏感
输出检查通过之后，才原子写入一个完整 immutable artifact reference。任一项失败时：

- 不写入或选择部分 summary/tags；
- 不改写 core Markdown、SQLite content 或历史 artifact；
- 只保留 attempt、request、fence、reservation/usage 和安全错误码等最小事实；
- 若已在 Provider 调用边界，状态是 ai_attempt_unknown 或 ai_retry_required，而不是声称
  Provider 没有执行。

Embedding round 的本地发布点是完整 generation：所有 document/chunk vectors、mapping、
metadata、manifest 与 source/contract 验证都通过后，才允许 READY binding CAS。任何失败只会
留下不可读、未引用的 private stage；reader 永不扫描或 fallback 到它。

两个 round 独立发布：LLM artifact 已发布而 Embedding 未发布时，LLM 不回滚，也不重复调用；
Q2 aggregate 仍不是 completed。反之，未发布的 LLM partial result 绝不可被下一个 attempt
复用为已完成结果。

### 4.2 外部效果与 attempt 状态

每个 Provider request 在调用前以短 lease 写入 request-intent。调用返回后，只写入 Provider
给出的 correlation/request ID、可验证 usage 与安全状态；没有 Provider correlation ID 时保留
NULL，不伪造通用 idempotency key。

建议的状态投影为：

| 局部状态 | 含义 | 是否可启动 Provider |
| --- | --- | --- |
| not_started | 本轮尚未开始，或初始自动化尚未获授权。 | 仅初始授权后的第一轮。 |
| processing | 有 live claim，正在本地预检或等待 Provider。 | 已在本 attempt 内。 |
| published | 该 round 的 immutable artifact 或 READY generation 已有 fenced proof。 | 否。 |
| ai_retry_required | 本地结果未发布，且可由用户创建新 attempt。 | 仅通过显式 retry execute。 |
| ai_attempt_unknown | 调用边界已跨越但结果/发布不可证明。 | 仅通过显式 retry execute，并先显示风险提示。 |
| budget_paused / authorization_required | enforced policy 或当前 policy 不允许开始。 | 否，Provider 调用数必须为 0。 |
| superseded / repair_required | 输入 core revision、policy 或 durable proof 已失效。 | 否，先重建安全计划或修复。 |

当状态为 ai_attempt_unknown 时，公开 retry plan 必须逐字显示：

> 上一轮未发布任何 AI 结果；Provider 可能已执行该请求。继续会发起新的调用，可能产生额外使用量。

每一次 execute 产生新 attempt_id。已经有 published proof 的 round 不重复计费；没有 published
proof 的外部请求不得被假定为 exactly-once。

### 4.3 Claim、stage 与清理

1. 每个 attempt 绑定 task_id、attempt_id、claim_token、owner_fence、输入 core revision、
   source digest、policy fingerprint 和 lease expiry。
2. Provider construction/call 在 root writer lease 外。Provider 前后的 durable 记录、artifact
   publish、generation pointer CAS、usage/reservation 结算均重新验证同一 live fence。
3. 私有 LLM output stage 和 generation stage marker 必须包含 task_id、attempt_id、owner_fence
   和受控输入摘要；stage 不是 public resource，不能成为 reader binding。
4. 成功 publish 后才允许按 leaf/no-follow 检查释放对应 stage。过期 stage 只能在短 lease 下验证
   “没有 live claim、没有 artifact reference、没有 active/retained generation reference”后回收；
   否则保留为 repair evidence，绝不猜测删除。
5. 强制杀进程的恢复测试可以利用外置 harness 的 request barrier 观察时机；生产代码不增加
   test mode、测试时钟或 fake Provider 后门。

## 5. Durable data model

实现应使用新的版本化 schema，而不是给现有 R4 task row 塞入无从验证的可选字段。下列是
logical model；具体 migration 编号和 SQL 在实现授权后依据当时迁移链确定。

| 逻辑记录 | 最小字段/约束 | 目的 |
| --- | --- | --- |
| ai_tasks | operation_id 唯一、target knowledge_id/core revision、aggregate state、required rounds | 把 core commit 与 AI aggregate 投影连接起来。 |
| ai_attempts | attempt_id、task_id、attempt_no、claim token/fence、policy/input snapshot、state、retry approval proof | 一次可能产生外部影响的边界；不可复用。 |
| ai_provider_requests | request_id、attempt_id、round/stage、intent/result state、Provider correlation ID（可空）、usage fact reference | 诚实记录 started/observed/unknown，而不保存 prompt/body/credential。 |
| ai_round_publications | round kind、task/attempt、immutable output reference 或 READY generation/manifest proof、validation version、state | 只允许完整轮次 published。 |
| ai_artifacts / selections | artifact 绑定 core revision、output digest、summary/tags；selection 绑定 core revision 与 artifact | 让 AI 结果不可变，后续结果显式选择。 |
| cost facts / reservations | attempt/round、actual/estimated/unconfirmed 分类；enforced reservation 的最终状态 | 不把 unknown 写成零，也不让失败 reservation 永久悬挂。 |
| source_series / source_aliases | opaque series_id、canonical URL alias 唯一映射 | 同 URL 和 URL migration 的系列 identity。 |
| source_versions / supersession edges | knowledge_id、series_id、fingerprint、observation ordinal、至多一个 predecessor、auto/manual 来源 | 同快照复用、变更新版本、无环/无多前驱。 |

现有 ai_derivation_tasks、ai_derivation_reservations、ai_derivation_usage 和
content_ai_handoffs 不能被静默解释为新模型。实现第一阶段必须决定并测试一种完整迁移策略：
要么受控重建其 CHECK/foreign-key 合同，要么引入新表并把旧 R4 tasks 隔离为 legacy-only
read projection。两者都不得让旧 task 被新的公开 retry 动作无证明地接管。

### 5.1 Core 与派生读模型

新归档不再用 Q1′ apply_ai_patch 修改 knowledge_items 的 summary/tags 或 Markdown frontmatter。
核心 entry 保持其已提交 revision；get_entry、search result、FTS 和相关服务读取一个明确的
“core + selected artifact”投影。选择新 artifact 是独立、显式、fenced mutation，并只更新
selection pointer/索引投影，不改写 artifact 或 core。

已有 legacy inline summary/tags 在迁移后只能作为 legacy fallback，直到用户/后续专用流程产生
新的 immutable artifact；不得在普通 archive 或 retry 时回填/重写历史条目。

### 5.2 输出验证合同

LLM：

- 结构化结果必须完整；summary 非空、规范化、长度受固定且版本化的上限约束；
- tags 必须是唯一、非空、数量受限的字符串集合；
- summary/tags/typed patch 一起绑定 exact target core revision、input digest、attempt/fence；
- 对敏感值、credential-shaped URL、token/cookie 等命中实行拦截：不保存原文，不发布 artifact，
  只保留安全错误码/已脱敏事实；
- 不引入自动语义正确性裁判。语义质量仍由人审阅、选择或后续独立质量工作流处理。

Embedding：

- 每个 document 与每个已存储 chunk 的 mapping/cardinality 必须精确匹配 capture；
- 向量维度必须等于已确认 contract，所有值 finite，且每一向量的范数必须大于明确的最小阈值；
- metadata、四个 vector artifacts、manifest、source digest、contract 和 strict readonly opener
  必须全部验证，才可 READY CAS；
- stage、manifest 或 pointer 任一环节失败都不是 READY，且不允许 flat-vector fallback。

## 6. 费用与授权

### 6.1 reference_only（默认）

reference_only 仍要求 Provider/模型 policy 被用户确认，但不要求 token hard cap。每个 round
可记录：

- estimated：本地、明确标注为估算的 token/金额参考；
- actual：Provider 返回且可验证的 usage；
- unconfirmed：request-intent 已持久化但 Provider 结果或外部效果不可证明的保守事实。

这些是可审计显示事实，不是默认的 hard blocker。unconfirmed 不得永久保留 reservation，也不得
显示为实际已花费或零花费。

### 6.2 enforced（显式选择）

enforced policy 才要求已确认的 hard cap，并在每一独立 round 的 Provider 前建立 fence-bound
reservation。超过上限时写 budget_paused，Provider factory/call 计数必须为 0；policy 未确认
时写 authorization_required，同样为 0。

reservation 只能是 live attempt 的临时保护，attempt 关闭时必须 settled 或 released。若外部
效果未知，系统记录 unconfirmed exposure 而不把 reservation 无限期锁住；enforced preflight
是否把该 exposure 计入 cap 必须是 policy 中显式、可见、经确认的规则，不能暗中把未知当作
零或实际值。

旧的 retry.max_attempts 不再授权后台重试。它若保留，只能作为公开 retry plan 的安全提示/上限，
不能让 recover_and_drain 自动再次构造 Provider。

## 7. URL 版本谱系

### 7.1 规范化与指纹

Q0 使用与 SafeFetcher 相同的 HTTP(S) canonicalization 形成 canonical URL；fragment、userinfo、
危险/credential-bearing 形式不进入 durable identity。为避免把凭据写入 SQLite/Markdown，
本基线采用 fail-closed：含 credential-bearing URL component 的归档在 admission 前拒绝，而不是
以 redacted URL 冒充原始 identity。

source fingerprint 是版本化 canonical payload 的 SHA-256，至少包含：

1. canonical URL；
2. 规范化 title；
3. 规范化 Markdown/body；
4. 明确 allow-list 的 extraction metadata 及其 schema/version。

它明确排除 AI artifact、Provider usage、archive timestamp、operation_id、raw HTML/headers 和
任何附件字节。规范化算法必须在独立 pure function 中固化，不能依赖本机 locale、当前时间或
无序 mapping。

### 7.2 写入规则

| 输入 | Q1′ 在同一写入事务内的结果 | 禁止行为 |
| --- | --- | --- |
| 同 canonical URL + 同 fingerprint | 返回既有 knowledge_id / entry locator；不创建 core version、Q2 task、Provider request 或 generation work。 | 以 archive time 或 UUID 生成“新版本”。 |
| 同 canonical URL + 新 fingerprint | 创建新 immutable knowledge_id；自动 predecessor 为该 series 的 latest_observed；写 new --supersedes--> old。 | 改写旧内容、旧 AI artifact 或旧 vector binding。 |
| 新 URL + 合法 manual predecessor | 新 URL 成为 predecessor 所属 series 的 alias，手动 predecessor 优先于自动选择。 | 默默合并两个已存在 series。 |
| conflicting manual predecessor、self edge 或 cycle | fail closed，核心归档/关系不产生半提交。 | 选择任意一个 predecessor 或用创建时间猜测。 |

source_versions 以事务内递增 observation_ordinal 定义 latest_observed。它是可推导的观察结果，
不是自动切换的 current pointer；产品不因新版本自动替用户指定“当前版本”或选择新的 AI
artifact。

一个 successor 至多一个 predecessor。cycle 检测在 writer lease/同一 SQLite transaction 内沿
predecessor chain 做有界查询；manual 与 automatic 同时给出不同 predecessor 是冲突，给出同一
predecessor 才可幂等成功。URL migration 若指向已归属另一 series 的 alias，必须返回明确的
series-conflict，而不是隐式 merge。

### 7.3 v1 公开读取能力

v1 只增加确定性、只读的：

- 一个 entry 所属 series 与 alias 摘要；
- 该 series 的 history，按 observation_ordinal 和 knowledge_id 稳定排序；
- 两个显式 knowledge_id 的 compare/diff，精确比较 title、body、selected summary 与 selected
  tags。

diff 不调用 AI、不推断语义、不执行 merge、不选择 artifact，也不更新 current/latest pointer。
旧版本仍绑定其自己的 core revision、AI artifact 和 vector source；新版本单独进入 AI lifecycle。

## 8. 公开接口设计

下列名称是实现提案，最终名称须在 CLI/MCP contract review 中一起冻结；重要的是
inspect → plan → confirm → execute 形状，而不是抢先实现命令。

| 面 | 只读 | 明确写入/网络动作 | 必须返回的安全字段 |
| --- | --- | --- | --- |
| CLI | ai-task inspect、ai-task retry-plan、source series/history/diff | ai-task retry --confirm PLAN_ID --approved | operation_id、task/round state、core_committed、attempt disclosure、safe next action；不含 body/path/key。 |
| MCP stdio | inspect_ai_task、plan_ai_retry、get_source_series、list_source_history、compare_source_versions | execute_ai_retry(approved=true, plan_id=...)、显式 select_ai_artifact | 与 CLI 等价的 JSON envelope、knowledge_id、entry locator、opaque IDs。 |

初次 archive 成功或 degraded 的 CLI 与 MCP envelope 都应返回可验证的 operation_id；当前 MCP 已有，
CLI 必须补齐。公开 retry 的 plan 必须绑定 core revision、policy fingerprint、task state 和
expected attempt predecessor；execute 前重新验证，漂移时返回 plan_stale 而非调用 Provider。

read-only inspect、history、diff、search、get_entry 绝不 drain、claim、创建 Provider、修改
generation、写 audit 或触发 retry。MCP 继续只支持 stdio；GUI、HTTP server 与 pkv-GUI 不在本
工作包范围。

现有 public embedding rebuild 是独立维护生命周期，不能偷偷结算或重试 AI task。若它已经发布
一个严格匹配 target source/contract 的 READY generation，Q2 可在 fenced recheck 后记录
reused_ready_generation 的本地证明；否则两条路径必须互斥/plan-stale，不能重复发布或混算费用。

## 9. 黑盒与回归覆盖矩阵

所有自动化继续经 scripts/run-test.ps1，使用独立 .data-test/<scenario>、独立 Config、
DataRoot、端口和 harness 状态。测试仅可读测试拥有的 durable ledger 来核对公开 operation_id；
不得以私有方法调用替代 CLI/MCP 入口。

| 场景 | 当前状态 | 新增 source blackbox 要求 |
| --- | --- | --- |
| CLI archive-text 成功 → 新进程 vector/hybrid | 已覆盖真实 CLI 子进程与外置 deterministic Provider。 | 保留；增加 operation_id、round published proof、selected artifact 与 READY generation 断言。 |
| MCP archive_text → 新 stdio server retrieve | 已覆盖真实 MCP SDK/JSON-RPC。 | 保留；增加公开 ai state 与 source-safe envelope 断言。 |
| LLM 第二子阶段失败 | 只有内部 retry 特征测试。 | CLI 和 MCP 各至少一条：没有 AI artifact/selection，core 仅一次，retry 必须先 plan/confirm，新的 attempt 可产生额外 usage。 |
| Embedding 失败后恢复 | 有 unit recovery，缺少新公开 retry 语义。 | LLM artifact 已发布且不重调；新进程明确 retry 后只完成 embedding，最终 Q2 completed + READY。 |
| Provider request 中断 | R4-E 列为后续基础设施缺口。 | 外置 harness barrier 观察 request-intent 后终止产品进程；新进程 inspect 显示 attempt_unknown，显式 retry 才继续。无 sleep、无产品 test mode。 |
| reference_only | 未覆盖。 | 无 hard cap 仍能在已授权 policy 下运行；actual/estimated/unconfirmed 分类正确且不造成永久 reservation。 |
| enforced budget/auth | 当前有自动恢复式 unit 覆盖。 | budget_paused/authorization_required 时 harness 计数为 0；更新合成配置后，以新进程对同一 task 走公开 retry，核心不重复。 |
| same URL same snapshot | 未覆盖。 | 外置、正式 fetch contract 可用时：同一 URL/正文返回同一 knowledge_id，Q2/Provider 计数不增加。 |
| same URL changed snapshot | 未覆盖。 | 新 knowledge_id、精确 supersedes edge、old/new AI/vector 独立，重启后 history/diff 稳定。 |
| manual predecessor | 未覆盖。 | URL migration 成功；multiple predecessor/self/cycle 均 fail closed、无半提交。 |
| URL success harness | 当前只覆盖 SSRF/DNS/redirect fail-closed；R4-E 已明确没有安全的成功 URL harness。 | 在正式、非 test-mode 的 fetch boundary 发布前保持为技术阻塞，不能用 monkeypatch 或 loopback SSRF 例外冒充黑盒。现有 DNS/redirect fail-closed 测试必须保留。 |

Provider harness 继续是测试拥有的外置 OpenAI-compatible 子进程：仅通过正式 Provider 配置、
随机 numeric-loopback endpoint、固定模型/维度/向量/usage 接入。它只记录阶段、次数和摘要，
不保存 prompt/body/key；run-test 的精确 loopback 合同不得放宽 SafeFetcher/SSRF 策略。

新增测试不得依赖 sleep、random UUID 排序、固定端口、全局 Config 或真实 URL。任务和 ledger
关联一律使用公开 operation_id、task_id 或 plan_id。

## 10. 实施波次

### Wave A：合同冻结与纯数据模型

- 将本文拆成正式 ADR、状态机/DTO 规范和 migration design；更新与本文冲突的 R4
  Application/AI/Storage/CLI/MCP/Config 文档。
- 为 source fingerprint、URL canonicalization、attempt/round state、artifact selection、cost
  category 和 predecessor validation 写 pure/unit contract tests。
- 冻结错误码与公开状态字典，防止 CLI/MCP 各自猜测。

### Wave B：核心/AI 不可变持久化

- 引入 immutable artifact、selection、attempt/request/round/publication ledger；
- 用新 Q1′ 端口替代 apply_ai_patch 对 core entry 的直接改写；
- 把 LLM 和 Embedding 轮次拆开，增加 request-intent、fence-bound stage 与 stale reclaim；
- 保持 Provider 调用在 lease 外，保留现有 generation 的 strict validation/CAS 优点，并补上
  nonzero vector 验证。

### Wave C：费用与显式 retry

- 升级 ai.automation 配置 schema：reference_only 默认，enforced 明确 opt-in；
- 将自动 drain 限缩为安全的 claim-expiry/reconciliation，不再自动重调 Provider；
- 交付公开 inspect → retry-plan → confirm → execute；补 CLI 成功 envelope 的 operation_id。

### Wave D：URL series 与 read surface

- 建立 source series/alias/version/supersession 写入事务和 deterministic history/diff；
- 改造 URL PreparedDocument 与 StorageCoordinator，使 dedupe 在 Q1′ single writer 中决定；
- 交付 CLI/MCP history/diff/selection projection，不引入自动 current、AI diff 或 merge。

### Wave E：黑盒、独立 review 与文档收束

- 按第 9 节完成真实 CLI/MCP 子进程测试，至少各重复一次；
- 运行既有 R4 CLI/MCP blackbox、R4 unit/integration、P0、MCP、Phase C、致命静态检查和
  git diff --check，全部经规定 wrapper；
- 由独立 reviewer 检查跨进程性、无 Application/R4 bypass、无 product test mode、无网络/真实
  数据访问、无 sleep/fixed port/global config 污染，以及 Q2 completed/READY 的真实证明；
- 报告 URL success harness 的实际合同状态，不把 source acceptance 写成 release acceptance。

## 11. Schema 与迁移边界

现有 knowledge_items.source_url 的 inline UNIQUE 约束是 URL 多版本的硬阻塞。不得通过给 URL
拼接 UUID、伪造 query、覆盖旧行或把多个版本塞入同一 Markdown 文件来规避。移除该约束在
SQLite 中需要受控表重建，并同时保持 knowledge_id、foreign key、FTS trigger、索引、operation
proof 和关系表的一致性。

因此实现需分开证明：

1. disposable 临时 SQLite fixture 上的 schema/data migration、重复启动、FTS/foreign key/row
   identity 和新旧读模型；
2. source blackbox 的全新隔离 DataRoot；
3. 未来真实快照 upgrade。第三项仍受既有 inspect → plan → confirm → execute、FT5/U1/G8 和
   用户明确授权约束，本工作包不执行也不宣称完成。

不能安全 canonicalize 的历史 URL 记录应保持 legacy-unclassified，不自动拼 series 或修改原
record。新 URL series 逻辑只对通过新 admission 合同的记录生效，直到有独立、可审阅的历史
归类计划。

## 12. 非目标与完成定义

本主线不包含 GUI、pkv-GUI、HTTP MCP、daemon、Docker、真实 Provider、真实网页抓取、真实
Vault/用户配置读取、发布封包、Artifact 验收、合规或真实迁移执行。图片/文件附件版本化和
原始网页副本同样不是本 v1 的隐含范围。

source blackbox 通过的定义是：在隔离合成根、正式公开 CLI/MCP 入口、正式 Provider 配置和
外置 deterministic harness 下，能证明本地 atomic publish、显式 retry、正确费用分类、URL
version identity、跨进程 retrieval 和 fail-closed 安全边界。它仍不解除 Artifact/release 的
compliance hold。
