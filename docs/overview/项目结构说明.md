## 1. 总体结构

当前仓库的核心结构如下：

```text
personal-knowledge-vault/
├── src/                  # 主代码目录
├── config/               # 配置与工作流
├── scripts/              # 初始化、备份、迁移、测试脚本
├── tests/                # 测试
├── docs/                 # 项目文档
├── .data/                # 运行时数据（默认被忽略）
├── README.md
├── requirements.txt
└── .env.example
```

说明：

- `docs/` 是项目文档目录，不是知识条目主存储
- 知识条目主存储默认位于 `.data/vault/`
- 当前系统同时存在 CLI、MCP、GUI 三个主要入口

## 2. src/ 目录说明

### 2.1 `src/main.py`

作用：

- CLI 入口
- 注册 `archive / search / show / list / config / stats` 等命令

### 2.2 `src/cli/`

作用：

- 命令定义
- 控制台展示
- 输出格式化

主要文件：

- `commands.py`
- `ui.py`
- `formatters.py`

### 2.3 `src/mcp/`

作用：

- 提供 MCP Server
- 向 AI Agent 暴露 Tool / Resource / Prompt

主要文件：

- `server.py`
- `tools.py`
- `resources.py`
- `prompts.py`
- `utils.py`

这是当前项目的核心入口之一，不再是远期扩展目录。

### 2.4 `src/gui/`

作用：

- 桌面 GUI 工作台
- 浏览、搜索、归档、审核、调试入口

主要结构：

- `app.py`
- `main_window.py`
- `views/`
- `viewmodels/`
- `widgets/`
- `styles/`
- `models/`
- `stores.py`

GUI 当前定位是工作台，不是整个项目的定义中心。

### 2.5 `src/workflow/`

作用：

- 工作流引擎
- 工作流数据模型
- 工作流步骤实现

主要文件：

- `engine.py`
- `models.py`
- `steps.py`

工作流是 PKV 的编排核心。

### 2.6 `src/processors/`

作用：

- 将不同来源内容解析成统一知识条目

当前主要处理器：

- `wechat_processor.py`
- `zhihu_processor.py`
- `generic_processor.py`
- `chat_processor.py`
- `ai_chat_processor.py`
- `text_fallback_processor.py`

### 2.7 `src/retrieval/`

作用：

- 检索策略与实现

主要文件：

- `bm25_retriever.py`
- `vector_retriever.py`
- `hybrid_retriever.py`
- `query_router.py`
- `result.py`

### 2.8 `src/storage/`

作用：

- 管理主存储与辅助索引

主要文件：

- `markdown_store.py`
- `sqlite_store.py`
- `vector_store.py`
- `relation_store.py`
- `migration_manager.py`
- `review_manager.py`

### 2.9 `src/relations/`

作用：

- 定义关系层基础模型与低歧义关系抽取逻辑
- 统一关系类型、方向、来源和查询返回结构

当前文件：

- `models.py`
- `extractors.py`

### 2.10 `src/ai/`

作用：

- 摘要、标签、Embedding 等 AI 能力封装

主要文件：

- `deepseek_client.py`
- `openai_client.py`
- `embedder.py`

### 2.11 `src/utils/`

作用：

- 配置读取
- 日志
- 文本工具
- 环境校验

主要文件：

- `config.py`
- `logger.py`
- `text_utils.py`
- `verify_setup.py`

## 3. 配置目录说明

### 3.1 `config/config.yaml`

负责定义：

- 存储路径
- AI 配置

- `archive-url.yaml`
- `archive-text.yaml`

用于补充中文分词词典。

## 4. 运行时数据目录

默认运行时数据位于 `.data/`：

```text
.data/
├── db/         # SQLite 数据库
├── logs/       # 日志
├── tmp/        # 临时文件
├── vault/      # Markdown 主存储
└── vectors/    # hnswlib 向量索引
```

关键事实：

- `.data/vault/` 才是当前知识条目主存储目录
- `docs/` 不承担知识主存储职责
- SQLite 与向量索引在必要时可以从主存储重建

## 6. 模块关系

可以把当前项目理解为以下关系：

```text
CLI / MCP / GUI
    ↓
Workflow / Services
    ↓
Processors / Retrieval / Review
    ↓
Storage / AI / Utils
```

具体说明：

- `CLI / MCP / GUI` 是三个入口
- `workflow` 组织归档、分析、审核等流程
- `processors` 负责内容解析
- `retrieval` 负责搜索和混合检索
- `storage` 负责主存储和辅助索引
- `ai` 提供摘要、标签、Embedding 等能力
- `utils` 提供配置、日志、文本处理等底层支撑

## 7. 当前最重要的扩展位

从结构视角看，当前最重要的扩展位不是再加一个入口，而是补中间层：

- 关系层
- 高阶 MCP Tool
- 多跳检索能力
- 证据聚合能力

当前已经新增并建议继续围绕以下命名扩展：

- `src/relations/`
- `src/knowledge_graph/`
- `src/evidence/`

说明：

- `src/relations/` 已经落地，当前承担 `Phase A / T1+T3` 的关系模型、低歧义关系抽取与回填服务基础
- `src/knowledge_graph/` 与 `src/evidence/` 仍属于后续能力扩展候选，不应误写为当前已实现目录
