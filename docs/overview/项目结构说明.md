## 1. 总体结构

当前仓库的核心结构如下：

```text
personal-knowledge-vault/
├── src/                  # 主代码目录
├── config/               # bundled 默认配置与版本化工作流
├── scripts/              # 初始化、备份、迁移、测试脚本
├── tests/                # 测试
├── docs/                 # 项目文档
├── .data-test/           # 仅默认自动化的隔离数据根（被忽略）
├── README.md
└── requirements.txt
```

说明：

- `docs/` 是项目文档目录，不是知识条目主存储
- 唯一可编辑用户配置是 `%USERPROFILE%\\.pkv\\config.yaml`；它与仓库内 bundled
  `config/config.yaml` 合并为一次不可变 `Config` snapshot。
- 有效数据根的选择顺序为 `PKV_DATA_ROOT` → 用户配置
  `storage.data_root` → `%USERPROFILE%\\.pkv\\data`。内部代码必须通过
  `Config` / `RuntimeLayout` 取得 `vault_dir`、`db_path`、`vector_index_dir`
  等子路径，而不能拼接 `.data/...`。
- `<data-root>/config/local.yaml` 是 PKV 管理的无密钥 runtime snapshot，不是
  业务配置来源，不能手工存放 Provider key。
- 当前仓库包含 CLI、MCP 两个主要入口，并通过稳定 `pkv_kernel` 服务外部 Wrapper；
  外部 Wrapper 不得导入 `src.*`。

## 3. 配置目录说明

### 3.1 `config/config.yaml`

这是随代码分发的 bundled 默认值，不是用户私有配置。运行时从它与
`%USERPROFILE%\\.pkv\\config.yaml` 构造一个 `Config` snapshot；前者包含：

- 存储默认值（最终子路径仍由 `RuntimeLayout` 从有效 data root 派生）
- AI 配置
- 检索参数
- 工作流默认配置
- 日志配置
- jieba 词典配置

### 3.2 `config/workflows/`

负责存放工作流定义。

当前重点包括：

- `archive-url.yaml`
- `archive-text.yaml`

以上文件都是运行时实际加载、带 `schema_version` 的工作流定义。搜索直接由 Retrieval 层与 adapter 执行；`search.yaml` 不受支持，也没有 `config/config.yaml` 内嵌 steps 回退。

### 3.3 `config/custom_dict.txt`

用于补充中文分词词典。

## 4. 运行时数据目录

默认运行时数据位于 `%USERPROFILE%\\.pkv\\data`。若设置正式环境覆盖
`PKV_DATA_ROOT`，或在用户配置中设置 `storage.data_root`，`RuntimeLayout`
会为那一个有效 data root 重新派生全部子路径：

```text
<data-root>/
├── db/         # SQLite 数据库
├── logs/       # 日志
├── tmp/        # 临时文件
├── vault/      # Markdown 主存储
├── vectors/    # hnswlib 向量索引
├── runtime/    # PKV 管理的运行期状态
├── config/
│   └── local.yaml  # 无密钥 runtime snapshot；不是可编辑业务配置
└── backups/    # 生命周期/备份流程使用的根内备份目录
```

关键事实：

- `Config().vault_dir`（默认即 `%USERPROFILE%\\.pkv\\data\\vault`）才是当前
  知识条目主存储目录；`Config().db_path` 与 `Config().vector_index_dir`
  始终来自同一 snapshot 的 `RuntimeLayout`。
- `docs/` 不承担知识主存储职责
- SQLite 与向量索引在必要时可以从主存储重建
- 旧 checkout 内的 `.data/` 或 `config/local.yaml` 如存在，须保留为历史目录；
  不会被自动迁移、接管或删除。实际迁移须先 inspect、展示影响与备份，再等待用户确认。

## 6. 模块关系

可以把当前项目理解为以下关系：

```text
CLI / MCP / 外部 Kernel Wrapper
    ↓
Workflow / Services
    ↓
Processors / Retrieval / Review
    ↓
Storage / AI / Utils
```

具体说明：

- `CLI / MCP` 是本仓库入口；外部 Wrapper 仅消费 `pkv_kernel`
- `workflow` 组织归档、分析、审核等流程
- `processors` 负责内容解析
- `retrieval` 负责搜索和混合检索
- `storage` 负责主存储和辅助索引
- `ai` 提供摘要、标签、Embedding 等能力
- `utils` 提供配置、日志、文本处理等底层支撑

## 7. 当前最重要的扩展位

从结构视角看，当前最重要的扩展位不是再加一个入口，而是补中间层：

- 关系层
- 高阶 MCP Tool

当前已经新增并建议继续围绕以下命名扩展：

- `src/relations/`
- `src/knowledge_graph/`
- `src/evidence/`

说明：

- `src/relations/` 已经落地，当前承担 `Phase A / T1+T5` 的关系模型、低歧义关系抽取、回填与一跳查询服务基础
- `src/knowledge_graph/` 与 `src/evidence/` 仍属于后续能力扩展候选，不应误写为当前已实现目录
