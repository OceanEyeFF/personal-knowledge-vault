## 迁移系统设计

### 核心原则

1. **向后兼容**: 新代码必须能读取老数据
2. **增量升级**: 每次升级仅应用必要的变更
3. **自动检测**: 启动时自动检测并提示升级
4. **可回滚**: 每次升级前自动备份，支持回滚
5. **幂等性**: 重复执行迁移脚本应该安全

### 架构设计

```
┌─────────────────────────────────────┐
│  应用启动                            │
└────────────┬────────────────────────┘
             ↓
┌─────────────────────────────────────┐
│  检测数据库版本                      │
│  SELECT version FROM schema_version │
└────────────┬────────────────────────┘
             ↓
      版本是否过期？
             ↓
      是 ↓       ↓ 否
┌──────────────┐  │
│  提示升级     │  │
│  自动备份     │  │
│  执行迁移     │  │
│  更新版本号   │  │
└──────────────┘  │
             ↓    ↓
┌─────────────────────────────────────┐
│  正常运行                            │
└─────────────────────────────────────┘
```

## 版本管理机制

### Schema Version 表

```sql
-- 在数据库中创建版本管理表
CREATE TABLE IF NOT EXISTS schema_version (
    version_id INTEGER PRIMARY KEY AUTOINCREMENT,
    version TEXT NOT NULL UNIQUE,           -- 版本号（如 "1.0.0"）
    description TEXT,                       -- 变更描述
    applied_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    applied_by TEXT                         -- 执行者（可选）
);

-- 插入初始版本
INSERT OR IGNORE INTO schema_version (version, description)
VALUES ('1.0.0', '初始 Schema - M1 基础设施层');
```

### 版本号规范

使用语义化版本号：`主版本.次版本.修订版本`

- **主版本** (Major): 不兼容的 Schema 变更（如删除表、删除列）
- **次版本** (Minor): 向后兼容的功能新增（如新增表、新增列）
- **修订版本** (Patch): 向后兼容的问题修复（如索引优化、约束调整）

**示例**:
- `1.0.0` → M1 初始版本
- `1.1.0` → M6 新增 CLI 相关表
- `1.1.1` → M12 新增 AI 对话会话表
- `1.1.2` → Review 系统表结构
- `1.2.0` → Phase A 关系层基础表
- `1.2.1` → 真实事件/发布时间字段
- `1.2.2` → FTS 表与触发器合同对齐
- `1.2.3` → FTS 存储合同修复
- `1.2.4` → 跨存储操作提交凭据
- `1.2.5` → 内部 AI 自动任务、token reservation 与用量账本

### 迁移脚本模板

每个迁移脚本必须包含：

```sql
-- Migration: 002_add_cli_tables.sql
-- Version: 1.1.0
-- Description: 新增 CLI 使用统计表
-- Author: 幽浮酱
-- Date: 2026-02-16

-- ========================================
-- 向上迁移（Upgrade）
-- ========================================

-- 检查版本（防止重复执行）
-- 注意: SQLite 不支持 IF NOT EXISTS 检查版本，需要在 Python 中处理

-- 新增表
CREATE TABLE IF NOT EXISTS cli_command_history (
    command_id INTEGER PRIMARY KEY AUTOINCREMENT,
    command TEXT NOT NULL,              -- 命令名称（archive/search/list 等）
    args TEXT,                          -- 命令参数（JSON）
    executed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    execution_time_ms INTEGER,          -- 执行时长（毫秒）
    status TEXT,                        -- success/error
    error_message TEXT
);

-- 新增索引
CREATE INDEX IF NOT EXISTS idx_cli_history_command ON cli_command_history(command);
CREATE INDEX IF NOT EXISTS idx_cli_history_executed_at ON cli_command_history(executed_at);

-- 更新版本号
INSERT OR IGNORE INTO schema_version (version, description)
VALUES ('1.1.0', '新增 CLI 使用统计表');

-- ========================================
-- 向下迁移（Rollback）- 可选
-- ========================================

-- 如果需要回滚，执行以下 SQL：
-- DROP TABLE IF EXISTS cli_command_history;
-- DELETE FROM schema_version WHERE version = '1.1.0';
```

## 执行流程

### 迁移检测机制（设计说明）

在应用启动时自动检测并提示：

```python
# src/storage/migration_manager.py

import sqlite3
from pathlib import Path
from typing import List, Tuple
import logging

logger = logging.getLogger(__name__)

class MigrationManager:
    """数据库迁移管理器"""

    def __init__(self, db_path: Path, migrations_dir: Path):
        self.db_path = db_path
        self.migrations_dir = migrations_dir

    def get_current_version(self) -> str:
        """获取当前数据库版本"""
        conn = sqlite3.connect(self.db_path)
        try:
            cursor = conn.cursor()

            # 检查 schema_version 表是否存在
            cursor.execute("""
                SELECT name FROM sqlite_master
                WHERE type='table' AND name='schema_version'
            """)

            if not cursor.fetchone():
                # 表不存在，说明是新数据库或旧版本
                return "0.0.0"

            # 获取最新版本
            cursor.execute("""
                SELECT version FROM schema_version
                ORDER BY version_id DESC LIMIT 1
            """)

            row = cursor.fetchone()
            return row[0] if row else "0.0.0"

        finally:
            conn.close()

    def get_pending_migrations(self) -> List[Tuple[str, Path]]:
        """获取待执行的迁移脚本"""
        current_version = self.get_current_version()
        migrations = []

        # 扫描迁移脚本目录
        for migration_file in sorted(self.migrations_dir.glob("*.sql")):
            # 解析版本号（从文件名或文件内容）
            version = self._parse_version_from_file(migration_file)

            # 比较版本号
            if self._version_compare(version, current_version) > 0:
                migrations.append((version, migration_file))

        return migrations

    def apply_migration(self, migration_file: Path, auto_backup: bool = True):
        """执行迁移脚本"""
        logger.info(f"应用迁移: {migration_file.name}")

        # 自动备份（可选）
        if auto_backup:
            self._backup_database()

        # 执行 SQL 脚本
        conn = sqlite3.connect(self.db_path)
        try:
            with open(migration_file, 'r', encoding='utf-8') as f:
                sql = f.read()

            # 执行迁移
            conn.executescript(sql)
            conn.commit()

            logger.info(f"✓ 迁移成功: {migration_file.name}")

        except Exception as e:
            conn.rollback()
            logger.error(f"✗ 迁移失败: {migration_file.name} - {e}")
            raise

        finally:
            conn.close()

    def check_and_prompt_upgrade(self):
        """检查并提示升级"""
        pending = self.get_pending_migrations()

        if not pending:
            logger.info("数据库 Schema 已是最新版本")
            return

        print("========================================")
        print(f" 检测到 {len(pending)} 个待升级的 Schema 变更")
        print("========================================")
        print("")

        for version, migration_file in pending:
            print(f"  • {migration_file.name} (v{version})")

        print("")
        print("建议先在隔离测试路径验证迁移。")
        print("生产备份、迁移和验证必须由用户明确授权并执行。")
        print("")

    def _backup_database(self):
        """备份数据库（调用已有的备份脚本）"""
        import subprocess
        import datetime

        timestamp = datetime.datetime.now().strftime("%Y%m%d-%H%M%S")
        message = f"自动备份 - Schema 迁移前 ({timestamp})"

        # 调用备份脚本
        subprocess.run([
            "powershell",
            "-File", "scripts/backup-data.ps1",
            "-Message", message
        ], check=True)

    def _parse_version_from_file(self, file_path: Path) -> str:
        """从迁移文件解析版本号"""
        with open(file_path, 'r', encoding='utf-8') as f:
            for line in f:
                if line.startswith("-- Version:"):
                    return line.split(":")[-1].strip()

        # 如果没有找到版本号，使用文件名序号
        return "0.0." + file_path.stem.split("_")[0]

    def _version_compare(self, v1: str, v2: str) -> int:
        """比较版本号（返回 1: v1 > v2, 0: v1 == v2, -1: v1 < v2）"""
        parts1 = [int(x) for x in v1.split(".")]
        parts2 = [int(x) for x in v2.split(".")]

        for p1, p2 in zip(parts1, parts2):
            if p1 > p2:
                return 1
            elif p1 < p2:
                return -1

        return 0
```

```python
# 设计伪代码（非当前脚本源码）
"""
数据库 Schema 迁移脚本

用法:
    # 以下裸命令使用当前数据目录；生产操作仅由明确授权的用户执行，AI 不执行
    python scripts/migrate.py              # 交互式升级
    python scripts/migrate.py --auto       # 自动升级
    python scripts/migrate.py --dry-run    # 仅检查，不执行
    python scripts/migrate.py --version    # 查看当前版本
    python scripts/migrate.py --health-check  # 健康检查
"""

import argparse
from pathlib import Path
from src.storage.migration_manager import MigrationManager
from src.utils.config import Config

def main():
    parser = argparse.ArgumentParser(description="数据库 Schema 迁移工具")
    parser.add_argument("--auto", action="store_true", help="自动执行所有迁移")
    parser.add_argument("--dry-run", action="store_true", help="仅检查，不执行")
    parser.add_argument("--version", action="store_true", help="显示当前数据库版本")
    parser.add_argument("--health-check", action="store_true", help="检查迁移链和数据库版本记录")
    parser.add_argument("--no-backup", action="store_true", help="跳过自动备份（不推荐）")
    args = parser.parse_args()

    # 初始化配置
    config = Config()
    db_path = config.db_path
    migrations_dir = Path(__file__).parent / "migrations"

    print("========================================")
    print(" PKV 数据库迁移工具")
    print("========================================")
    print("")
    print(f"数据库: {db_path}")
    print(f"迁移脚本目录: {migrations_dir}")
    print("")

    # 创建迁移管理器
    manager = MigrationManager(db_path, migrations_dir)

    # 获取当前版本
    current_version = manager.get_current_version()
    print(f"当前版本: {current_version}")
    print("")

    # 获取待执行的迁移
    pending = manager.get_pending_migrations()

    if not pending:
        print("✓ 数据库已是最新版本，无需迁移")
        return

    print(f"待执行的迁移: {len(pending)}")
    print("")

    for version, migration_file in pending:
        print(f"  • {migration_file.name} (v{version})")
    print("")

    if args.dry_run:
        print("Dry-run 模式，已退出")
        return

    # 确认执行
    if not args.auto:
        confirm = input("是否执行迁移？(输入 YES 继续): ")
        if confirm != "YES":
            print("已取消迁移")
            return

    # 执行迁移
    print("")
    print("========================================")
    print(" 开始迁移")
    print("========================================")
    print("")

    for version, migration_file in pending:
        try:
            manager.apply_migration(migration_file, auto_backup=not args.no_backup)
            print(f"✓ {migration_file.name} - 成功")
        except Exception as e:
            print(f"✗ {migration_file.name} - 失败: {e}")
            print("")
            print("迁移中断，请检查错误并修复后重试")
            return

    print("")
    print("========================================")
    print(" 迁移完成 ✓")
    print("========================================")
    print("")
    print("迁移完成。请在同一已授权数据根目录验证数据完整性。")

if __name__ == "__main__":
    main()
```

## 最佳实践

### 1. 迁移脚本编写原则

#### ✅ 推荐

```sql
-- 使用 IF NOT EXISTS（幂等性）
CREATE TABLE IF NOT EXISTS new_table (...);

-- 新增列时设置默认值（兼容老数据）
ALTER TABLE entries ADD COLUMN new_field TEXT DEFAULT '';

-- 新增索引时检查存在性
CREATE INDEX IF NOT EXISTS idx_new_field ON entries(new_field);
```

#### ❌ 避免

```sql
-- 不检查存在性（重复执行会报错）
CREATE TABLE new_table (...);

-- 删除列（SQLite 不支持，且会丢失数据）
ALTER TABLE entries DROP COLUMN old_field;

-- 修改列类型（需要重建表，风险高）
ALTER TABLE entries ALTER COLUMN field TYPE INTEGER;
```

---

### 2. SQLite 限制与解决方案

#### 问题：SQLite 不支持 `ALTER TABLE DROP COLUMN`

**解决方案**: 重建表

```sql
-- 1. 创建新表（不包含要删除的列）
CREATE TABLE entries_new (
    knowledge_id INTEGER PRIMARY KEY,
    title TEXT NOT NULL,
    -- 其他列...
    -- 注意: 不包含 old_column
);

-- 2. 复制数据
INSERT INTO entries_new
SELECT knowledge_id, title, ...  -- 不包含 old_column
FROM entries;

-- 3. 删除旧表
DROP TABLE entries;

-- 4. 重命名新表
ALTER TABLE entries_new RENAME TO entries;

-- 5. 重建索引
CREATE INDEX idx_entries_title ON entries(title);
```

**注意**: 此操作风险高，建议：
- 仅在主版本升级时执行
- 提前通知用户
- 提供详细的回滚脚本

---

#### 问题：SQLite 不支持 `ALTER TABLE ALTER COLUMN TYPE`

**解决方案**: 同样需要重建表（参考上面）

---

### 3. 向后兼容的列新增

新增列时，必须设置默认值或允许 NULL：

```sql
-- ✅ 推荐：设置默认值
ALTER TABLE entries ADD COLUMN search_strategy TEXT DEFAULT 'hybrid';

-- ✅ 可选：允许 NULL
ALTER TABLE entries ADD COLUMN custom_field TEXT;

-- ❌ 避免：NOT NULL 且无默认值（老数据会报错）
ALTER TABLE entries ADD COLUMN required_field TEXT NOT NULL;
```

### 4. 测试迁移脚本

在应用到生产环境前，务必先完成临时 SQLite 自动化验证：

空 SQLite 只验证 **fresh install**，不覆盖真实旧库升级兼容性。默认自动化使用 pytest 创建并回收的临时 SQLite/fixture；不得直接指向生产 `.data/`。真实快照升级验证当前尚未执行，必须先完成 FT5、满足 U1/G8 并取得用户明确授权，然后仅在从只读快照制作的一次性可写 clone 上执行。

```powershell

```

`run-test.ps1 ... scripts/migrate.py` 不是测试入口，而是固定返回 exit 2 的安全拒绝。生产裸命令只保留为人工 API 说明，必须另行完成上述门禁和授权，不能从本节复制为现行流程。

如果用户长时间未升级（例如从 v1.0.0 直接升级到 v1.5.0）：

       ↓

       ↓
v1.1.1 → 004_add_chat_sessions.sql
       ↓
v1.1.2 → 005_add_review_system.sql
       ↓

### 6. 大数据量迁移优化

如果数据库包含大量数据（如 10 万+ 条目）：

```sql
-- 使用事务（加快速度）
BEGIN TRANSACTION;

-- 批量更新（避免一次性全表更新）
UPDATE entries SET new_field = 'default'
WHERE knowledge_id BETWEEN 1 AND 10000;

UPDATE entries SET new_field = 'default'
WHERE knowledge_id BETWEEN 10001 AND 20000;

-- ...

COMMIT;
```

或者使用 Python 脚本分批处理：

此类自定义数据迁移不属于 FT7 CAT-0 默认任务。自动化只应把迁移逻辑拆成使用 pytest 临时 SQLite 的单元/集成测试；脚本级或真实快照执行仍需 FT5、U1/G8 与用户明确授权，并且只能针对一次性可写 clone。

```python
# scripts/migrations/custom_data_migration.py

import sqlite3
from src.utils.config import Config

config = Config()
conn = sqlite3.connect(config.db_path)

BATCH_SIZE = 1000

try:
    cursor = conn.cursor()

    # 获取总数
    cursor.execute("SELECT COUNT(*) FROM entries")
    total = cursor.fetchone()[0]

    print(f"总计 {total} 条数据需要迁移")

    # 分批处理
    for offset in range(0, total, BATCH_SIZE):
        print(f"处理 {offset} - {offset + BATCH_SIZE}...")

        cursor.execute("""
            UPDATE entries
            SET new_field = 'default'
            WHERE knowledge_id IN (
                SELECT knowledge_id FROM entries
                LIMIT ? OFFSET ?
            )
        """, (BATCH_SIZE, offset))

        conn.commit()

    print("✓ 数据迁移完成")

finally:
    conn.close()
```
