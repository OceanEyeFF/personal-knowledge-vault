# 关系回填质量验证指南

> 文档类型：运维 / 验证指南  
> 创建日期：2026-03-29  
> 适用范围：Phase B 5.4 关系回填与质量验证

---

## 1. 目的

本指南用于在**测试副本库**上执行关系回填演练，并产出可审计的质量报告。

当前目标不是对真实知识库直接执行正式回填，而是先固定：

- 回填报告结构
- 质量指标口径
- 最小关系推理回归样例集
- 后续进入 Phase C 前的最小门禁命令

---

## 2. 运行前提

- 使用隔离环境：`py311-private`
- 只对 CAT-0 合成库或临时 SQLite 执行 `--apply`
- 使用已包含 `knowledge_relations` Schema 的合成夹具；迁移契约由 pytest 临时 SQLite 测试验证

默认自动化必须从 `run-test.ps1` 启动。pytest 先经 `tests/offline_entrypoint.py pytest` 在 pytest/plugin 导入前建立离线基线，根 `tests/conftest.py` 再维持逐用例隔离；本指南中的仓库 `.py` 脚本经 FT7 Direct Python 入口在同一进程安装配置、网络和子进程 guard。FT7 只接受仓库内 `-m module` 或 `.py`，拒绝 `-c`、stdin 和解释器 flags；它是 CAT-0 纵深防护，不是 OS sandbox。

不要用 `run-test.ps1` 调用 `scripts/migrate.py`：包装器会明确拒绝并返回退出码 `2`。真实迁移尚未执行，仍须 FT5、U1/G8 和用户明确授权；真实快照只读，获批演练也只能在 disposable writable clone 上进行。本指南不授权读取真实快照或对真实知识库回填。

---

## 3. 质量报告输出

`scripts/backfill_relations.py` 当前支持以下报告输出：

- `--report-json`
- `--report-yaml`
- `--report-md`

报告当前固定结构版本：

```text
schema_version = backfill_quality_report.v1
```

核心指标：

- `coverage_rate = resolved_references / total_references`
- `noise_rate = (invalid_references + unresolved_references) / total_references`
- `conflict_rate = conflicted_relations / resolved_references`

附加审计信息：

- `mode`
- `knowledge_scope`
- `quality_gate`
- `conflict_samples`
- `extensions.execution`

## 4. 推荐执行方式

### 4.1 先做 dry-run

```powershell
.\scripts\run-test.ps1 -Direct -DataRoot .data-test\phaseb-5-4 -Command @(
  "python", "scripts\backfill_relations.py",
  "--db-path", ".data-test\phaseb-5-4\db\knowledge_vault.db",
  "--vault-dir", ".data-test\phaseb-5-4\vault",
  "--report-md", ".data-test\phaseb-5-4\tmp\backfill-report.md"
)
```

### 4.2 再做测试副本库 apply 演练

```powershell
.\scripts\run-test.ps1 -Direct -DataRoot .data-test\phaseb-5-4 -Command @(
  "python", "scripts\backfill_relations.py", "--apply",
  "--db-path", ".data-test\phaseb-5-4\db\knowledge_vault.db",
  "--vault-dir", ".data-test\phaseb-5-4\vault",
  "--min-coverage", "0.90",
  "--max-noise", "0.10",
  "--max-conflict", "0.05",
  "--fail-on-gate",
  "--report-json", ".data-test\phaseb-5-4\tmp\backfill-report.json",
  "--report-md", ".data-test\phaseb-5-4\tmp\backfill-report.md"
)
```

说明：

- 若传入质量门禁阈值，报告中会写入 `quality_gate`
- 若同时传入 `--fail-on-gate`，门禁失败时脚本返回退出码 `2`
- 未传阈值时，只输出报告，不做门禁判定

## 6. 当前门禁建议

对测试副本库的最小建议门禁：

- `coverage_rate >= 0.90`
- `noise_rate <= 0.10`
- `conflict_rate <= 0.05`

注意：

- 这组阈值当前只适用于低歧义显式关系来源：
  `markdown_link`、`frontmatter_related_docs`、`frontmatter_field(children/version_of)`
- 若后续扩展到更高噪声语义关系来源，需要重新定义门禁

## 6.1 当前正式关系类型

- `references`
  - 当前来自正文中的 Markdown 显式链接
- `related_document`
  - 当前来自 Front Matter `related_docs`
- `parent_of`
  - 当前来自 Front Matter `children`
- `version_of`
  - 当前来自 Front Matter `version_of`

## 6.2 当前显式关系来源定义

- `markdown_link`
  - 来自正文中的 Markdown 显式链接
  - 当前固定产出 `references`
- `frontmatter_related_docs`
  - 来自 Front Matter `related_docs`
  - 当前固定产出 `related_document`
- `frontmatter_field`
  - 来自 Front Matter 白名单关系字段
  - `children: [child.md, ...]` 产出 `parent_of`
  - `version_of: base.md` 产出 `version_of`

边界说明：

- 上述三类来源都属于“显式事实边”，因为它们直接来自作者写入的链接或结构化字段
- 当前回填与质量报告不包含纯语义推断边
- 若后续引入推断边，必须单独定义来源类型、质量门禁和展示策略，不能与显式事实边混用

## 7. 当前限制

- 当前只验证测试副本库，不等于真实库正式回填完成
- 当前关系来源已扩展到 Markdown 显式链接、Front Matter `related_docs`，以及 Front Matter 关系字段 `children` / `version_of`
- 当前质量报告反映的是“结构可审计性”，不等于完整语义质量评测
- Phase C 仍需要在此基础上补完整评测集与自动化评分规则
