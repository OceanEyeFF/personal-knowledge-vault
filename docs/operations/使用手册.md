## 1. 快速开始
### 1.1 5 分钟上手路线图
如果你已经具备 Python 与依赖环境，可直接从「第一次归档」开始。
- 00:00-01:00 克隆仓库
- 01:00-03:30 安装依赖 (推荐 Conda 脚本)
- 03:30-04:30 配置 API Key (.env)
- 04:30-05:00 第一次归档 + 第一次搜索
---
### 1.2 安装与环境准备
#### 方式 A: Conda 方式 (推荐)
```powershell
# 1) 克隆仓库
git clone https://github.com/yourusername/personal-knowledge-vault.git
cd personal-knowledge-vault
# 2) 安装 (自动创建 conda 环境 pkv-py311)
.\scripts\setup-conda.ps1
# 3) 激活环境
conda activate pkv-py311
```
#### 方式 B: 传统 venv (不推荐)
```powershell
# 1) 克隆仓库
git clone https://github.com/yourusername/personal-knowledge-vault.git
cd personal-knowledge-vault
# 2) 安装
.\scripts\setup.ps1
# 3) 激活虚拟环境
.\.venv\Scripts\Activate.ps1
```
#### 配置 API Keys
```powershell
copy .env.example .env
notepad .env
```
至少需要配置以下两项:
```bash
DEEPSEEK_API_KEY=sk-你的-deepseek-api-key
OPENAI_API_KEY=sk-你的-openai-api-key
```
```text
DeepSeek: https://platform.deepseek.com/api_keys
OpenAI: https://platform.openai.com/api-keys
```

```
.data/
├── db/
│   └── knowledge_vault.db
├── vault/
│   └── {source}/YYYYMMDD-title.md
├── vectors/
│   ├── doc_vectors.idx
```

- SQLite/向量索引用于检索加速。
- 日志默认写入 `.data/logs/pkv.log`。

## 2. 核心功能详解
### 2.0 CLI 总览与全局参数
CLI 名称为 `pkv`。
全局选项:
- `--verbose` : 输出更多信息 (INFO)
- `--debug`   : 输出调试信息 (DEBUG)
- `--version` : 显示版本
示例:
```bash
pkv --version
pkv --help
pkv --debug archive "https://example.com"
```
全局参数可与所有子命令组合使用。
---
### 2.1 `pkv archive` 归档内容
#### 用途
归档网页、聊天记录或文本内容。
归档流程:
- 抓取内容
- AI 分析 (摘要/标签)
- idea Sharpen (可选)
- 写入 Markdown + SQLite + 向量索引
#### 基本用法
```bash
# 归档网页
pkv archive <url>
# 归档聊天记录文件
pkv archive --type chat <file_path>
```
#### 主要参数
- `url_or_path` (位置参数)
  - URL 或本地文件路径
- `--type` (内容类型)
  - `auto` / `webpage` / `chat` / `news`
  - `auto` 会自动识别并选择处理器
- `--skip-sharpen`
  - 跳过 idea Sharpen 交互
- `--tags`
  - 手动指定标签
  - 逗号分隔，例如 `"AI,技术,教程"`
- `--quiet`
  - 静默模式，减少输出
  - 会默认跳过 idea Sharpen
#### 常见场景
场景 A: 归档技术博客
```bash
pkv archive "https://example.com/python-async"
```
场景 B: 归档聊天记录
```bash
pkv archive --type chat "C:/data/chat.json"
```
场景 C: 快速批量归档 (不交互)
```bash
pkv archive "https://example.com/a" --skip-sharpen --tags "AI"
pkv archive "https://example.com/b" --skip-sharpen --tags "Python"
```
#### 输出说明
典型输出字段:
- 标题
- 标签
- 文件路径
- 条目 ID
#### 常见问题
- 网络错误
  - 检查 URL 是否可访问
  - 使用 `--debug` 查看详细错误
- API Key 错误
  - 确保 `.env` 中已设置 `DEEPSEEK_API_KEY` 与 `OPENAI_API_KEY`
- idea Sharpen 交互阻塞
  - 使用 `--skip-sharpen` 或 `--quiet`
---
### 2.2 `pkv search` 搜索知识库
#### 用途
在本地知识库中检索条目。
支持 BM25、向量检索与混合检索。
#### 基本用法
```bash
pkv search "Python 异步"
```
#### 主要参数
- `query` (位置参数)
  - 搜索关键词
- `--strategy`
  - `auto` / `bm25` / `vector` / `hybrid`
  - `auto` 会根据查询长度选择策略
- `--limit`
  - 返回结果数量，默认 10
- `--format`
  - 输出格式: `table` / `json` / `markdown`
#### 示例
```bash
# 使用 BM25
pkv search "Python 异步" --strategy bm25
# 使用向量检索
pkv search "深度学习原理" --strategy vector
# 限制 5 条
pkv search "Python" --limit 5
# 输出 JSON
pkv search "Python" --format json
# 输出 Markdown
pkv search "Python" --format markdown
```
#### 搜索技巧
- 短查询 (1-3 个关键词): 优先 BM25
- 长描述性问题: 使用 vector 或 hybrid
- 想要高召回: 使用 hybrid
#### 输出说明
表格模式包含:
- ID
- 标题
- 得分
- 标签
你可以用 `pkv show <id>` 查看完整内容。
---

#### 输出内容

- 来源 URL

### 2.4 `pkv list` 列表与过滤
#### 用途
列出知识库中的条目。
#### 基本用法
```bash
pkv list
```
#### 主要参数
- `--tag` : 按标签过滤
- `--sort`: 排序字段 (time/title/id)
- `--desc`: 降序
- `--limit`: 限制数量
#### 示例
```bash
# 只看 Python 标签
pkv list --tag Python
# 按时间倒序
pkv list --sort time --desc
# 只显示 20 条

```

### 2.5 `pkv config` 配置管理
#### 用途
查看与管理配置。
支持显示、读取、写入配置。
#### 基本用法
```bash
# 查看完整配置
pkv config show
# 获取单个配置
pkv config get ai.deepseek.model
# 设置配置
pkv config set ai.deepseek.model deepseek-chat
```
#### 说明
- 配置优先级: 环境变量 > config.yaml > 默认值
- 若 `config set` 失败，可直接编辑 `config/config.yaml`
- 环境变量建议写入 `.env`

## 3. 配置和定制
### 3.1 环境变量
环境变量存放在 `.env`。
系统会自动加载 `.env`，无需手动导入。
必填:
- `DEEPSEEK_API_KEY`
- `OPENAI_API_KEY`
可选:
- `DEEPSEEK_BASE_URL` (默认 `https://api.deepseek.com/v1`)
- `OPENAI_BASE_URL`   (默认 `https://api.openai.com/v1`)
- `DB_PATH`           (覆盖数据库路径)
- `LOG_LEVEL`         (DEBUG/INFO/WARNING/ERROR)
示例:
```bash
DEEPSEEK_API_KEY=sk-xxx
OPENAI_API_KEY=sk-xxx
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
OPENAI_BASE_URL=https://api.openai.com/v1
DB_PATH=.data/db/knowledge_vault.db
LOG_LEVEL=INFO
```
注意:
- 修改 `.env` 后需重启 CLI
- 未配置 API Key 会导致归档失败
---
### 3.2 主配置文件 `config/config.yaml`
这是系统主配置文件。
主要包含以下模块:
- `storage` 目录配置
- `ai` AI 服务参数
- `retrieval` 检索参数
- `processors` 处理器参数
- `workflows` 工作流默认配置
- `jieba` 中文分词
- `logging` 日志配置
示例片段:
```yaml
storage:
  vault_dir: ".data/vault"
  db_path: ".data/db/knowledge_vault.db"
  vector_index_dir: ".data/vectors"
  log_dir: ".data/logs"
ai:
  deepseek:
    model: "deepseek-chat"
    max_tokens: 2000
    temperature: 0.7
retrieval:
  bm25:
    k1: 1.5
    b: 0.75
  hybrid:
    bm25_weight: 0.4
    vector_weight: 0.6
```
调整建议:
- `storage` 修改数据目录位置
- `ai.deepseek` 与 `ai.openai` 调整模型
- `retrieval` 调整权重与 top_k
---
### 3.3 工作流配置 `config/workflows/*.yaml`
PKV 使用 YAML 驱动工作流。
主要工作流:
- `archive-url.yaml`
- `search.yaml`
#### 归档工作流 (archive-url)
常见步骤:
- `fetch_content`
- `ai_analyze`
- `idea_sharpen`
- `store_entry`
你可以调整:
- 超时时间
- 重试次数
- idea Sharpen 触发条件
#### 搜索工作流 (search)
常见步骤:
- `route_query`
- `execute_retrieval`
- `format_results`
你可以调整:
- 路由规则
- BM25 / vector 参数
- 输出格式
修改后记得重启 CLI。
---

## 4. 故障排查
### 4.1 常见错误与解决方案
#### 1) API Key 未配置
错误示例:
```
DeepSeek API Key 未配置，请设置环境变量 DEEPSEEK_API_KEY
OpenAI API Key 未配置，请设置环境变量 OPENAI_API_KEY
```
解决方案:
- 检查 `.env` 是否存在
- 确保变量名拼写正确
- 重新打开终端或重启 CLI
#### 2) 网络超时或限流
可能原因:
- 网络不稳定
- API 速率限制
解决方案:
- 稍后重试
- 使用 `--debug` 查看详细日志
- 减少频繁批量归档
#### 3) SQLite CHECK 约束错误
错误示例:
```
CHECK constraint failed: source_type IN (...)
```
解决方案:
- 删除旧数据库后重建:
```bash
rm -f .data/db/knowledge_vault.db
```
- 重新运行归档命令
#### 4) 向量索引异常
现象:
- 搜索结果为空
- 向量索引加载失败
解决方案:
- 删除向量目录重新生成:
```bash
rm -rf .data/vectors
```
- 重新归档一条内容
#### 5) PowerShell 脚本无法执行
错误示例:
```
无法加载脚本，因为在此系统上禁止运行脚本。
```
解决方案:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```
#### 6) hnswlib 安装失败
原因:
- 缺少 C++ 编译环境
解决方案:
- 安装 Visual Studio Build Tools
- 选择 “使用 C++ 的桌面开发”
#### 7) Python 3.13 兼容问题
现象:
- `lxml` / `greenlet` 编译失败
解决方案:
- 使用 Conda 安装 Python 3.11
- 重新执行 `setup-conda.ps1`

## 5. 测试环境使用 ⭐ **NEW**

> **新增于 v0.6.1**: AI 安全测试功能

### 5.1 为什么需要测试环境

在开发新功能、测试配置或与 AI 协作时，直接操作生产数据存在风险：
- ❌ 可能误删除重要数据
- ❌ 可能写入测试数据污染知识库
- ❌ 无法回滚错误操作

**测试环境提供完全隔离的沙箱**：
- ✅ 测试数据写入 `.data-test/`
- ✅ 生产数据完全不受影响
- ✅ 可随时清理测试数据

### 5.2 快速使用测试环境

**方法 1: 使用 PowerShell 脚本（推荐）**

```powershell
# 使用测试环境执行命令
.\scripts\run-test.ps1 archive "https://example.com"

# 查看测试环境统计
.\scripts\run-test.ps1 stats

# 搜索测试数据
.\scripts\run-test.ps1 search "Python"
```

**方法 2: 手动设置环境变量**

```powershell
# Windows PowerShell
$env:DB_PATH = ".data-test/db/knowledge_vault.db"
pkv archive "https://example.com"

# Linux / macOS
export DB_PATH=".data-test/db/knowledge_vault.db"
pkv archive "https://example.com"
```

### 5.3 环境检测

检查当前使用的是生产环境还是测试环境：

```powershell
.\scripts\check-environment.ps1
```

输出示例：

```
========================================
 PKV 环境检测
========================================

[环境变量模式]
  DB_PATH = .data-test/db/knowledge_vault.db
  状态: ✓ 测试环境

========================================
数据库统计:

  总条目数: 1

========================================
✓ 当前为测试环境，可以安全测试
```

### 5.4 清理测试数据

测试完成后，可以清理测试环境：

```powershell
# 删除测试数据库和 Markdown 文件
Remove-Item -Recurse -Force .data-test/
```

> **新增于 v0.6.1**: 数据库增量迁移系统

### 6.1 为什么需要数据库升级

当系统添加新功能时（如 M6 CLI 统计表），数据库 Schema 需要升级：
- ❌ **传统方式**：删除旧数据库，重新初始化（丢失所有数据）
- ✅ **增量升级**：自动检测版本，仅执行待升级脚本（保留老数据）

### 6.2 检查当前版本

```bash
python scripts/migrate.py --version
```

输出示例：

```
当前数据库版本: 1.0.0
```

### 6.3 查看待升级脚本

```bash
python scripts/migrate.py --dry-run
```

输出示例：

```
待执行的迁移: 1

  • 002_add_cli_tables.sql
    版本: v1.1.0
    说明: 新增 CLI 使用统计表
```

### 6.4 执行升级

**建议流程**：

```bash
# 1. 备份生产数据（重要！）
.\scripts\backup-data.ps1 -Message "v1.1.0 升级前备份"

# 2. 在测试环境验证升级
$env:DB_PATH = ".data-test/db/knowledge_vault.db"
python scripts/migrate.py --auto

# 3. 验证测试环境
.\scripts\run-test.ps1 stats

# 4. 执行生产环境升级
python scripts/migrate.py
# 输入 YES 确认

# 5. 验证生产环境
pkv stats
```

**注意事项**：
- ⚠️ 升级前必须备份（迁移工具会自动备份，但手动备份更安全）
- ✅ 先在测试环境验证
- ✅ 迁移脚本支持幂等性（可重复执行）

### 6.5 回滚（如果升级失败）

```powershell
# 从备份恢复
.\scripts\restore-data.ps1

# 选择最近的备份进行恢复
```
