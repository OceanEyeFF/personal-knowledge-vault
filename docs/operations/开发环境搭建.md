## 系统要求

### 最低要求

| 组件 | 要求 | 说明 |
|------|------|------|
| **操作系统** | macOS / Linux / Windows (WSL2) | 推荐 macOS 或 Linux |
| **Python** | 3.11+ | 必须支持 type hints 和 async/await |
| **内存** | 4GB+ | 向量检索需要内存 |
| **磁盘空间** | 10GB+ | 用于存储 Markdown 文件和数据库 |
| **网络** | 稳定的互联网连接 | 需要调用 OpenAI-compatible LLM 和 Embedding API |

### 推荐配置

- **Conda**: Miniconda 或 Anaconda（推荐，避免 Python 3.13 兼容性问题）
- **Python**: 3.11.x（⚠️ 不推荐 3.13，存在依赖兼容性问题）
- **内存**: 8GB+（处理大规模知识库时更流畅）
- **SSD**: 推荐使用 SSD 提升数据库性能

## 数据库初始化

> 本节的 `.data` 初始化仅供用户在本机手动执行；Agent 不执行。Agent 如需验证 Schema/存储，应经 wrapper 运行临时 SQLite 测试或 `setup-test-db.py` 合成种子。

### SQLite 数据库

项目使用 **SQLite** 作为元数据和索引的存储：

```bash
# 创建数据库目录
mkdir -p .data/db

# 初始化数据库 Schema
python scripts/init_db.py
```

**预期输出**:

```
✅ SQLite 数据库初始化成功
📂 数据库路径: .data/db/knowledge_vault.db
📊 已创建表: knowledge_items, content_chunks, tags, knowledge_tags, video_timestamps
🔍 已创建 FTS5 虚拟表: knowledge_items_fts
```

### hnswlib 向量索引

向量索引文件会在第一次添加内容时自动创建：

```bash
# 向量索引存储路径
.data/vectors/
├── embeddings.index   # HNSW 向量索引
└── embeddings.meta    # 元数据（ID 映射）
```

**索引配置** (伪代码):

```python
# src/retrieval/vector_store.py
class VectorStore:
    def __init__(self, dim, max_elements=100000):
        self.dim = dim  # Embedding 维度
        self.index = hnswlib.Index(space='cosine', dim=dim)
        self.index.init_index(
            max_elements=max_elements,
            ef_construction=200,  # 构建时搜索深度
            M=16                  # 每个节点的邻居数
        )
```

## 本机服务配置

### Step 1: 创建配置文件

如果安装脚本尚未创建本机配置，可直接复制项目默认配置：

```bash
cp config/config.yaml config/local.yaml
```

Windows PowerShell 使用：

```powershell
Copy-Item config\config.yaml config\local.yaml
```

### Step 2: 配置 endpoint、模型和 API Key

编辑 Git 忽略的 `config/local.yaml`，只在本机填写真实值：

```yaml
ai:
  llm:
    base_url: "https://example-llm.invalid/v1"
    api_key: "<填写本机 LLM API Key>"
    model: "<填写 LLM 模型名>"
  embedding:
    base_url: "http://127.0.0.1:12345/v1"
    api_key: "lm-studio"  # 客户端要求非空；LM Studio 可使用非敏感占位字符串
    model: "<填写 Embedding 模型名>"
    dim: auto
```

### Step 3: 验证配置与本地安装

> 以下配置检查由用户在本机终端手动执行；它会加载 Git 忽略的 `config/local.yaml`，Agent 不执行、不读取原始输出。

```bash
# 查看生效配置；命令会隐藏 API Key
.\scripts\run-windows.ps1 python -m src.cli.commands config show

# 执行隔离的本地安装与存储验证
.\scripts\test-conda.ps1
```

`test-conda.ps1` 会通过隔离测试路径运行 `verify_setup.py`，验证配置加载、日志、文本处理、Markdown、SQLite 与 HNSW 向量存储。它不验证真实 LLM 连通性。

**典型输出**:

```
✅ 配置加载成功
✅ Markdown 存储正常
✅ SQLite 存储正常
✅ 向量存储正常
```

说明：

- `ai.embedding.dim` 为固定整数时，验证脚本只测试本地向量存储，不请求 Provider
- `ai.embedding.dim: auto` 时，为解析实际维度会额外探测配置的 Embedding endpoint；这仍不代表 LLM 已连通
- 如果本地 Embedding 服务不接受固定 `dimensions`，请将 `ai.embedding.dim` 设为 `auto`
- `auto` 模式下，系统会以首次成功返回的维度作为当前运行默认值，并持久化到 `.data/runtime/embedding_dim.json`
- `ai.embedding.base_url`、`ai.embedding.model` 和 `ai.embedding.dim` 共同构成向量索引契约；模型变化即使维度相同，也会让旧向量语义空间不一致
- 更换 Embedding 模型或维度后，需要重建向量索引，并重新生成文档级和分块级 Embedding
- 若只是临时测试本地服务，优先保持与现有索引一致的模型和维度，或先在隔离数据目录验证

## 故障排查

### 问题 1: Python 3.13 兼容性问题 ⚠️

**症状**:

```
fatal error C1189: #error: "this header requires Py_BUILD_CORE define"
ERROR: Failed building wheel for lxml
```

**原因**: Python 3.13 下部分 native 依赖可能尚无匹配的预编译 wheel。当前 URL processors 不依赖 Playwright/greenlet，而是使用 urllib3 pinned transport；项目仍推荐 Python 3.11 作为开发基线。

**推荐解决方案**: 使用 Conda 创建 Python 3.11 环境

```powershell
# Windows
.\scripts\setup-conda.ps1

# 或手动创建
conda create -n py311-private python=3.11
conda activate py311-private
pip install -r requirements.txt
```

**或手动降级 Python**:
1. 卸载 Python 3.13
2. 安装 Python 3.11 (https://www.python.org/downloads/)
3. 重新运行安装脚本

### 问题 4: SQLite FTS5 不可用

**症状**:

```
sqlite3.OperationalError: no such module: fts5
```

**解决方案**:

SQLite 3.35+ 默认支持 FTS5，如果报错说明版本过低：

```bash
# macOS: 使用 Homebrew 安装最新 SQLite
brew install sqlite3

# Ubuntu/Debian
sudo apt-get install sqlite3

# 验证版本
sqlite3 --version  # 应该 >= 3.35.0
```

---

### 问题 5: API 调用失败

**症状**:

```
Error: API key is invalid or expired
```

**解决方案**:

1. **由用户检查本机配置是否正确加载**：

   该命令会加载 Git 忽略的 `config/local.yaml`，仅限用户本机终端；Agent 不执行、不读取原始输出。

```powershell
.\scripts\run-windows.ps1 python -m src.cli.commands config show
```

确认 `ai.llm.base_url`、`ai.llm.model`、`ai.embedding.base_url`、`ai.embedding.model` 和 `ai.embedding.dim` 与当前服务一致。输出中的 API Key 应保持脱敏；不要在终端、Issue 或日志中打印密钥或密钥前缀。

2. **验证本地安装与存储链路**：

```powershell
.\scripts\test-conda.ps1
```

该命令不验证真实 LLM；`ai.embedding.dim: auto` 时只会额外探测 Embedding endpoint 以解析维度。若配置本地模型，请先确认模型已加载且 OpenAI-compatible endpoint 正在监听；若更换 Embedding endpoint、模型或维度，应清空隔离环境中的旧向量并重建索引。

3. **检查网络代理设置** (如果在国内):

```bash
# 设置 HTTP 代理
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890
```

### 问题 7: 内存不足

**症状**:

```
MemoryError: Cannot allocate memory for HNSW index
```

**解决方案**:

1. **减小向量索引的 `max_elements`**:

```python
# src/retrieval/vector_store.py
self.index.init_index(
    max_elements=10000,  # 从 100000 减小到 10000
    ef_construction=200,
    M=16
)
```

2. **启用增量索引**:

```python
# 分批加载，避免一次性加载所有向量
for batch in batched_entries(batch_size=1000):
    vector_store.add_batch(batch)
```
