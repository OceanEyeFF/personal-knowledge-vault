# 测试环境快速开始

> 在 Windows 上使用 `.data-test/` 验证功能，不修改生产 `.data/`。

---

## Windows Py311 Conda 离线测试环境

P0 固定支持 Python 3.11。首次测试时，在项目根目录新建专用环境：

```powershell
.\scripts\setup-test-conda.ps1
.\scripts\test-conda.ps1 -EnvironmentName pkv-test-py311 -Suite P0
```

`setup-test-conda.ps1` 使用 `environment.test.yml` 创建全新环境，安装
`requirements.txt` 并执行 `pip check`。创建环境和安装依赖需要访问已配置的
Conda/Python 包源。目标环境已存在时脚本会拒绝覆盖或删除；可以传入新的
`-EnvironmentName`。

该入口与生产安装脚本相互独立：

- 不安装 Playwright 浏览器，也不选择任何测试联网调用。
- 不创建或修改 `config/local.yaml`。
- 不创建或读取生产 `.data/`；项目运行路径、pytest 临时目录和 cache 目录使用
  每次新建的 `.data-test/conda-*` 目录。
- Windows `P0` 预检依次运行默认收集与完整离线套件。
- `manual` 与 `network` 测试始终被排除。

MCP `--cov-fail-under=95` 仍由 Ubuntu/Python 3.11 CI 门禁负责；Windows 预检只作
兼容性验证，不据此宣称覆盖率达标。需要缩小范围时，可将 `-Suite P0` 改为
`Smoke`、`Contract` 或 `Offline`。

## 1. 明确 CAT-0 配置边界

离线测试不需要也不会加载 `config/local.yaml`。wrapper 会在 pytest/plugin 或产品
目标导入前清理 live、secret、proxy 环境并绑定 base-only Config。不要为 CAT-0
创建 `.env` / `.env.test`，也不要读取或打印本机 Provider 配置。

## 2. 运行第一个隔离命令

在项目根目录执行：

```powershell
.\scripts\run-test.ps1 -DataRoot .data-test\quick-smoke stats
```

`run-test.ps1` 会创建所选场景目录并设置完整运行路径。CLI、pytest 与受支持的
Direct Python 都经对应 offline entrypoint；pytest G0 在 pytest/plugin 导入前建立，
Direct Python 只接受仓库 `-m`/`.py`。非 Python Direct 不属于 Python G0。

预期隔离路径：

```text
.data-test/quick-smoke/db/knowledge_vault.db
.data-test/quick-smoke/vault/
.data-test/quick-smoke/vectors/
.data-test/quick-smoke/logs/
.data-test/quick-smoke/tmp/
```

## 3. 运行功能验证

```powershell
# 生成确定性合成数据
.\scripts\run-test.ps1 -Direct -DataRoot .data-test\quick-flow -Command @(
  "python", "scripts/setup-test-db.py", "--seed", "42", "--count", "3",
  "--wechat-count", "0", "--zhihu-count", "0"
)
.\scripts\run-test.ps1 -DataRoot .data-test\quick-flow list
.\scripts\run-test.ps1 -DataRoot .data-test\quick-flow show 1

# 消费路径；BM25 不触发 Embedding HTTP
.\scripts\run-test.ps1 -DataRoot .data-test\quick-flow search "测试" --strategy bm25

# 管理路径
.\scripts\run-test.ps1 -DataRoot .data-test\quick-flow stats
```

真实 Provider/URL 不属于本快速开始，当前受 U1/G8 阻塞。

## 4. 核对本地产物

```powershell
Get-ChildItem .data-test -Recurse
git status --short
```

通过标准：

- 数据库、Vault、向量索引和日志都位于 `.data-test/`。
- 脚本输出确认所有运行路径均在 `.data-test/`，且路径守卫未报错；AI 不读取 `.data/` 作对比。
- `config/local.yaml` 和 `.data-test/` 不出现在 Git 待提交列表中。

## 常用命令

| 操作 | 命令 |
|------|------|
| 查看测试统计 | `.\scripts\run-test.ps1 -DataRoot .data-test\quick-flow stats` |
| 生成合成数据 | `run-test.ps1 -Direct -DataRoot .data-test\quick-flow ... setup-test-db.py`（见上） |
| 搜索测试库 | `.\scripts\run-test.ps1 -DataRoot .data-test\quick-flow search "关键词" --strategy bm25` |
| 列出测试条目 | `.\scripts\run-test.ps1 -DataRoot .data-test\quick-flow list` |
| 运行单元测试 | `.\scripts\run-test.ps1 -Direct -DataRoot .data-test\quick-unit -Command @("pytest", "tests/unit", "-q")` |
| 核对 CAT-0 配置 | 只核对 wrapper 报告的 DataRoot；不要用它验证 `config/local.yaml` |

## 真实服务测试（当前阻塞）

wrapper 固定离线哨兵、base-only Config 与网络 guard；设置 `PKV_RUN_LIVE=1` 不能
把它变成 live launcher。真实 Provider/URL/快照必须等待 U1/G8（迁移另需 FT5）与
用户明确授权，届时由专用 user-only launcher 在 disposable clone 中执行。

## 故障排查

### 数据写入了 `.data/`

立即停止可写命令，确认命令通过 `scripts/run-test.ps1` 运行。不要自动删除或覆盖 `.data/`；保留最小复现命令以便排查。

### Provider 配置不生效

wrapper 是 base-only，不能用于验证 `config/local.yaml` 或 Provider。CAT-0 若意外
需要 Provider，应判为测试设计错误；真实服务排查只在 U1/G8 就绪并获用户授权后，
由用户在 Agent 不可见的受控流程中完成。

### 更换了 Embedding 模型

endpoint、模型或维度改变后，原有 `.data-test/vectors` 不可直接复用，必须重建测试向量索引。不要清理 `.data/vectors`。
