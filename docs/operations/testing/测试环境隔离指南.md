# 测试环境隔离指南

> 目标：在 Windows 上验证 PKV 功能时，确保任何测试数据都不会写入用户的有效数据根（`<effective-data-root>`）。

**最后更新**: 2026-08-21
**版本**: v2.2

---

## 隔离边界

### 当前路径合同

PKV 的运行时路径按以下规则解析：

```text
PKV_DATA_ROOT（若设置）
  → 用户配置 %USERPROFILE%\.pkv\config.yaml 中的 storage.data_root
  → %USERPROFILE%\.pkv\data
  = <effective-data-root>
```

其中 `%USERPROFILE%\.pkv\config.yaml` 是唯一可编辑的用户业务配置；`<effective-data-root>\config\local.yaml` 是 PKV 管理、无敏感字段的 runtime snapshot，不是第二份业务配置，也不会 merge 到 `Config`。默认 CAT-0 测试不读取二者。

| 类型 | 保存位置 | 用途 |
|------|----------|------|
| 用户业务配置 | `%USERPROFILE%\.pkv\config.yaml` | 仅用户维护；可能含 Provider 凭据；CAT-0 不读取 |
| runtime snapshot | `<effective-data-root>\config\local.yaml` | PKV 管理、无敏感字段；用于 runtime 验证，不手工编辑 |
| 运行隔离参数 | `scripts/run-test.ps1` 为子进程设置 | 将数据库、Vault、向量、日志和临时目录定向到所选 `.data-test/<scenario>/` |

不再创建或加载 `.env.test`，也不通过 `PKV_LLM_*` 或 `PKV_EMBD_*` 配置 Provider。
`PKV_DATA_ROOT` 与 `PKV_LOG_LEVEL` 是仅有的正式产品环境覆盖；`DATA_DIR`、`DB_PATH`、`VAULT_DIR`、`VECTOR_DIR`、`LOG_DIR`、`TMP_DIR` 与 `LOG_LEVEL` 只在 `PKV_TEST_OFFLINE=1` 的隔离注入中兼容。

### 目录约定

- `<effective-data-root>/`：生产数据根，测试期间不得读取或写入。
- `.data-test/`：本地测试数据，由 `scripts/run-test.ps1` 自动创建和使用。
- `config/config.yaml`：版本化的默认配置，不放密钥。
- `%USERPROFILE%\.pkv\config.yaml`：唯一可编辑的用户配置，位于 checkout 外且由用户维护。
- `<effective-data-root>/config/local.yaml`：PKV 管理的 secret-free runtime snapshot。
- checkout 中的旧 `.data/`、旧 `config/local.yaml`，以及 held release candidate 的 `%LOCALAPPDATA%\PersonalKnowledgeVault` 是历史用户资产/证据；不得自动迁移、接管、复制或删除。只有用户经 inspect → plan → 展示影响与备份 → 确认 → execute → smoke test 后才能处理。

## 快速开始

### 1. 明确 CAT-0 配置边界

默认测试不需要也不会加载 `%USERPROFILE%\.pkv\config.yaml`，也不会读取生产 runtime snapshot。pytest、CLI/MCP 与受支持的 Direct
Python 都在目标代码/pytest plugin 导入前清理 live、secret、proxy 环境，并绑定
base-only Config。包装器在启动 Python 前把 `PKV_DATA_ROOT` 绑定为所选 `.data-test`
根；这仅是 CAT-0 隔离注入，不改变正式产品的路径优先级。用户配置仅供用户正常应用
或未来获批的 user-only live 流程使用；Agent 不读取、不打印，也不能用 wrapper 输出验证 Provider。

### 2. 运行隔离命令

从项目根目录运行：

```powershell
.\scripts\run-test.ps1 -DataRoot .data-test\isolation-smoke stats
.\scripts\run-test.ps1 -DataRoot .data-test\isolation-smoke list
.\scripts\run-test.ps1 -DataRoot .data-test\isolation-smoke search "测试查询" --strategy bm25

# pytest、Python 脚本等非 CLI 命令必须使用 -Direct 和显式 -Command 字符串数组
.\scripts\run-test.ps1 -Direct -DataRoot .data-test\isolation-unit -Command @("pytest", "tests/unit", "-q")
```

默认 CLI、pytest 和 Direct Python 都会被分派到对应的 offline entrypoint。pytest
bootstrap 在 pytest/plugin 导入前建立 G0；Direct Python 仅允许仓库 `-m`/`.py`，
拒绝 `-c`、stdin、解释器 flags、外部 collection/output 路径。非 Python Direct
不属于 Python G0。所有受控分支共享六项路径隔离与同一 `DataRoot` 安全校验。

脚本会在子进程中将以下路径定向到 `.data-test/`：

```text
DATA_DIR   -> .data-test/<scenario>
DB_PATH    -> .data-test/<scenario>/db/knowledge_vault.db
VAULT_DIR  -> .data-test/<scenario>/vault
VECTOR_DIR -> .data-test/<scenario>/vectors
LOG_DIR    -> .data-test/<scenario>/logs
TMP_DIR    -> .data-test/<scenario>/tmp
```

这些变量只用于运行时路径隔离，不是 Provider 配置的替代品。

### 3. 核对隔离结果

```powershell
.\scripts\run-test.ps1 -DataRoot .data-test\isolation-smoke stats
Get-ChildItem .data-test\isolation-smoke -Recurse
git status --short
```

验收条件：

- 运行输出显示的数据路径均位于 `.data-test/isolation-smoke/`。
- `.data-test/isolation-smoke/db`、`.data-test/isolation-smoke/vault`、`.data-test/isolation-smoke/vectors` 按需产生数据。
- 脚本输出确认所有运行路径均在 `.data-test/`，且路径守卫未报错；AI 不枚举 `<effective-data-root>/` 作前后对比。
- `git status --short` 不出现 `.data-test/`、旧 checkout `config/local.yaml` 或其他本机运行产物。

## 真实服务测试（当前阻塞）

`run-test.ps1` 固定 `PKV_RUN_LIVE=0`、base-only Config 与网络 guard；它不是 live
launcher，也不能通过外部设置 `PKV_RUN_LIVE=1` 绕过。真实 Provider、真实 URL 或
真实快照验证当前受 U1/G8 阻塞（迁移另需 FT5），不提供可复制命令。门禁齐备后
也只能由用户明确授权，在 disposable writable clone 中通过专用 user-only launcher
执行，并只向仓库回传脱敏摘要。

### Embedding 索引契约

Embedding 的 endpoint、模型和维度共同构成向量索引契约。任一项改变时，不得复用原有 `.data-test/vectors`；应删除测试向量索引并重新归档或重建索引。不要仅替换模型名称后继续读取旧索引。

## 常见场景

### 功能流转验证

按短路径分开验证存储、消费和管理需求：

```powershell
# 存储：先生成确定性合成条目，再检查列表与详情
.\scripts\run-test.ps1 -Direct -DataRoot .data-test\isolation-flow -Command @(
  "python", "scripts/setup-test-db.py", "--seed", "42", "--count", "3",
  "--wechat-count", "0", "--zhihu-count", "0"
)
.\scripts\run-test.ps1 -DataRoot .data-test\isolation-flow list
.\scripts\run-test.ps1 -DataRoot .data-test\isolation-flow show 1

# 消费：CAT-0 只使用不会触发 Embedding HTTP 的 BM25
.\scripts\run-test.ps1 -DataRoot .data-test\isolation-flow search "测试" --strategy bm25

# 管理：只对测试数据执行统计或维护命令
.\scripts\run-test.ps1 -DataRoot .data-test\isolation-flow stats
```

每条路径先独立通过，再进行端到端串联，可以更快区分抓取、存储、索引或检索故障。

### 单元和集成测试

单元测试优先使用 `tmp_path` 或 `TemporaryDirectory`，并将完整的存储路径注入测试配置。不要只覆盖 `DB_PATH` 而留下 Vault 或向量目录指向 `<effective-data-root>/`。

从 Windows 命令行运行 pytest 时，使用统一包装脚本；pytest 不是 PKV CLI 子命令，必须使用 `-Direct` 和显式 `-Command` 字符串数组：

```powershell
.\scripts\run-test.ps1 -Direct -DataRoot .data-test\isolation-unit -Command @("pytest", "tests/unit", "-q")
```

### Git Worktree

每个 worktree 都应拥有自己的 `.data-test/` 场景根；默认测试不读取用户 profile，也不为 worktree 新建 `config/local.yaml`、`.env` 或 `.env.test`。旧 checkout 配置/数据目录保留为历史资产，不能由测试或脚本自动接管。

## 故障排查

### 测试数据出现在 `<effective-data-root>/`

1. 立即停止当前可写命令。
2. 确认命令是通过 `scripts/run-test.ps1` 启动，而不是直接调用 Python。
3. 检查脚本输出的 `DATA_DIR`、`DB_PATH`、`VAULT_DIR` 和 `VECTOR_DIR`。
4. 保留现场并报告最小复现命令，不要自动移动、删除或迁移 `<effective-data-root>/`。

### Provider 连接失败

CAT-0 基线不应连接 Provider；如果它尝试连接，按隔离设计错误处理并先修复调用路径。
真实 Provider 的 endpoint、模型和维度排查仍受 U1/G8 阻塞；门禁齐备后，
由用户在 Agent 不可见的 user-only 流程中执行，仅回传脱敏结果。不要复制、
打印或上传 `%USERPROFILE%\.pkv\config.yaml` 的内容。

### 维度不匹配

若服务实际返回的向量维度与索引不同：

1. 仅由用户检查 `%USERPROFILE%\.pkv\config.yaml` 的 `ai.embedding.model` 和 `ai.embedding.dim`。
2. 若 `<effective-data-root>/config/local.yaml` 与外部配置/当前数据库构建契约不一致，按产品提示评估重建 Embedding；不得手工改写 snapshot。
3. CAT-0 只可清理 `.data-test/<scenario>/vectors` 并重建测试索引。
4. 不要对 `<effective-data-root>/vectors` 执行清理操作。
