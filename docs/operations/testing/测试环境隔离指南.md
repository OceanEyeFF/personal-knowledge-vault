## 方法一：环境变量隔离（推荐）⭐

### 原理

通过设置环境变量 `DB_PATH`，覆盖默认配置，将所有数据存储到隔离目录。

**优点**:
- ✅ 零配置，立即生效
- ✅ 不修改任何代码或配置文件
- ✅ 可以快速切换环境
- ✅ 适合临时测试和开发调试

**缺点**:
- ⚠️ 需要手动创建测试目录
- ⚠️ 向量索引和 Vault 目录仍使用默认路径（需额外配置）

---

### 步骤 1：创建测试专用 `.env.test` 文件

在项目根目录创建 `.env.test`（已被 `.gitignore` 忽略）：

```env
# 测试环境专用配置
DB_PATH=.data-test/db/knowledge_vault.db

# 可选：使用测试 API Keys（避免消耗生产配额）
PKV_LLM_API_KEY=sk-test-xxxxxx
PKV_EMBD_API_KEY=sk-test-xxxxxx

# 可选：使用更详细的日志
LOG_LEVEL=DEBUG
```

---

### 步骤 2：创建测试目录结构

```powershell
# PowerShell 脚本：初始化测试环境
New-Item -ItemType Directory -Path ".data-test/db" -Force
New-Item -ItemType Directory -Path ".data-test/vault" -Force
New-Item -ItemType Directory -Path ".data-test/vectors" -Force
New-Item -ItemType Directory -Path ".data-test/logs" -Force
New-Item -ItemType Directory -Path ".data-test/tmp" -Force
```

```bash
# Bash 脚本：初始化测试环境
mkdir -p .data-test/{db,vault,vectors,logs,tmp}
```

---

### 步骤 3：使用测试环境运行命令

#### 方式 A：手动加载环境变量（PowerShell）

```powershell
# 加载测试环境变量
Get-Content .env.test | ForEach-Object {
    if ($_ -match '^([^=]+)=(.*)$') {
        [Environment]::SetEnvironmentVariable($matches[1], $matches[2])
    }
}

# 运行测试命令
python -m src.main archive "https://example.com"
python -m src.main search "测试查询"
python -m src.main stats

# 测试完成后关闭终端，环境变量自动清除
```

#### 方式 B：使用脚本封装（推荐）

创建 `scripts/run-test.ps1`：

```powershell
# scripts/run-test.ps1
# 使用测试环境运行命令

param(
    [Parameter(Mandatory=$true, ValueFromRemainingArguments=$true)]
    [string[]]$Command
)

# 加载测试环境变量
if (Test-Path ".env.test") {
    Get-Content .env.test | ForEach-Object {
        if ($_ -match '^([^=]+)=(.*)$') {
            [Environment]::SetEnvironmentVariable($matches[1], $matches[2])
        }
    }
    Write-Host "[测试环境] 已加载 .env.test" -ForegroundColor Green
} else {
    Write-Host "[警告] .env.test 不存在，使用默认配置" -ForegroundColor Yellow
}

# 执行命令
$cmd = $Command -join " "
Write-Host "[执行] python -m src.main $cmd" -ForegroundColor Cyan
Invoke-Expression "python -m src.main $cmd"
```

使用方式：

```powershell
# 测试归档命令
.\scripts\run-test.ps1 archive "https://example.com"

# 测试搜索
.\scripts\run-test.ps1 search "AI"

# 查看测试环境统计
.\scripts\run-test.ps1 stats
```

## 方法二：Git Worktree 隔离

### 适用场景

- 长期测试分支（例如：测试大型重构）
- 需要同时维护多个版本
- 避免频繁切换分支污染工作目录

### 步骤

#### 1. 创建 Worktree

```powershell
# 在项目平级目录创建 worktree（避免嵌套）
git worktree add ../pkv-test-feature feature/test-feature
cd ../pkv-test-feature
```

#### 2. 配置独立测试环境

在 worktree 目录中创建独立的 `.env`：

```env
# ../pkv-test-feature/.env
DB_PATH=.data/db/knowledge_vault.db
PKV_LLM_API_KEY=sk-test-xxxxxx
PKV_EMBD_API_KEY=sk-test-xxxxxx
LOG_LEVEL=DEBUG
```

**关键优势**: 每个 worktree 有独立的 `.data/` 目录，天然隔离！

#### 3. 安装依赖（如果需要）

```bash
cd ../pkv-test-feature
conda activate pkv-py311
pip install -r requirements.txt
```

#### 4. 测试

```bash
python -m src.main archive "https://example.com"
python -m pytest tests/
```

#### 5. 清理 Worktree

```bash
cd ../personal-knowledge-vault  # 回到主仓库
git worktree remove ../pkv-test-feature
git branch -D feature/test-feature  # 可选：删除分支
```

## 数据备份与恢复

### 备份生产数据

```powershell
# PowerShell 备份脚本
$timestamp = Get-Date -Format "yyyyMMdd-HHmmss"
$backup_dir = ".data-backup/$timestamp"

New-Item -ItemType Directory -Path $backup_dir -Force
Copy-Item -Recurse ".data/*" $backup_dir
Write-Host "备份完成: $backup_dir" -ForegroundColor Green
```

```bash
# Bash 备份脚本
timestamp=$(date +%Y%m%d-%H%M%S)
backup_dir=".data-backup/$timestamp"

mkdir -p "$backup_dir"
cp -r .data/* "$backup_dir"
echo "备份完成: $backup_dir"
```

### 恢复数据

```powershell
# 列出可用备份
Get-ChildItem ".data-backup" | Sort-Object Name -Descending

# 恢复到指定版本
$backup_version = "20260216-143000"  # 替换为实际备份时间戳
Remove-Item -Recurse -Force ".data/*"
Copy-Item -Recurse ".data-backup/$backup_version/*" ".data/"
Write-Host "恢复完成: $backup_version" -ForegroundColor Green
```

### 自动备份脚本（推荐）

创建 `scripts/backup-data.ps1`：

```powershell
# scripts/backup-data.ps1
param(
    [string]$Message = "手动备份"
)

$timestamp = Get-Date -Format "yyyyMMdd-HHmmss"
$backup_dir = ".data-backup/$timestamp"

New-Item -ItemType Directory -Path $backup_dir -Force
Copy-Item -Recurse ".data/*" $backup_dir

# 保存备份信息
$info = @{
    timestamp = $timestamp
    message = $Message
    files = (Get-ChildItem -Recurse $backup_dir | Measure-Object).Count
    size_mb = [math]::Round((Get-ChildItem -Recurse $backup_dir | Measure-Object -Property Length -Sum).Sum / 1MB, 2)
} | ConvertTo-Json

$info | Out-File "$backup_dir/backup-info.json" -Encoding UTF8

Write-Host "✅ 备份完成!" -ForegroundColor Green
Write-Host "   目录: $backup_dir" -ForegroundColor Cyan
Write-Host "   说明: $Message" -ForegroundColor Cyan
Write-Host "   文件数: $($info | ConvertFrom-Json | Select -ExpandProperty files)" -ForegroundColor Cyan
Write-Host "   大小: $($info | ConvertFrom-Json | Select -ExpandProperty size_mb) MB" -ForegroundColor Cyan
```

使用方式：

```powershell
# 测试前备份
.\scripts\backup-data.ps1 -Message "测试新归档功能前的备份"

# 测试...

# 如果出错，恢复备份
# (手动从 .data-backup/ 目录恢复)
```

### 场景 4：单元测试使用独立数据库

在 `tests/conftest.py` 中配置：

```python
import pytest
import tempfile
from pathlib import Path
from src.utils.config import Config

@pytest.fixture(scope="session")
def test_config():
    """提供测试专用配置"""
    # 使用临时目录
    with tempfile.TemporaryDirectory() as tmpdir:
        test_dir = Path(tmpdir)

        # 创建测试配置
        config = Config()
        # 覆盖路径属性（通过环境变量）
        import os
        os.environ["DB_PATH"] = str(test_dir / "test.db")

        yield config

        # 测试结束后自动清理

@pytest.fixture
def sqlite_store(test_config):
    """提供隔离的 SQLite 存储"""
    from src.storage.sqlite_store import SQLiteStore
    store = SQLiteStore(test_config)
    yield store
    # 每个测试后清理
```

## 最佳实践总结

### ✅ 推荐做法

1. **日常开发**: 使用方法一（环境变量 + `.env.test`）
2. **长期测试**: 使用方法二（Git Worktree）
3. **单元测试**: 使用 `pytest` fixtures + 临时目录
4. **重要变更前**: 始终执行 `.\scripts\backup-data.ps1`
5. **版本控制**: 将 `.data-test/` 和 `.env.test` 添加到 `.gitignore`

### ⚠️ 注意事项

1. **API 成本**: 测试时使用独立的 API Keys（避免消耗生产配额）
2. **数据清理**: 定期清理测试数据（`.data-test/`）
3. **备份习惯**: 养成测试前备份的习惯
4. **环境隔离**: 避免在同一终端窗口混用生产和测试环境

## 故障排查

### 问题 1：测试数据意外写入生产数据库

**症状**: 测试数据出现在生产 `.data/` 目录

**原因**: 环境变量未正确设置

**解决**:
```powershell
# 验证环境变量
echo $env:DB_PATH  # 应显示 .data-test/...

# 如果为空，重新加载
Get-Content .env.test | ForEach-Object {
    if ($_ -match '^([^=]+)=(.*)$') {
        [Environment]::SetEnvironmentVariable($matches[1], $matches[2])
    }
}
```

---

### 问题 2：测试环境无法创建数据库

**症状**: `FileNotFoundError: .data-test/db/`

**原因**: 测试目录未创建

**解决**:
```powershell
mkdir -p .data-test/{db,vault,vectors,logs,tmp}
```

---

### 问题 3：Worktree 占用磁盘空间过大

**症状**: 多个 worktree 导致磁盘不足

**解决**:
```powershell
# 列出所有 worktree
git worktree list

# 删除不需要的 worktree
git worktree remove ../pkv-old-test

# 清理 .data 目录（谨慎）
Remove-Item -Recurse ../pkv-old-test/.data
```

## 进阶技巧

### 技巧 1：使用 Docker 容器隔离

```dockerfile
# Dockerfile.test
FROM python:3.11
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
ENV DB_PATH=/app/.data-test/db/knowledge_vault.db
CMD ["python", "-m", "src.main"]
```

```powershell
# 构建测试镜像
docker build -f Dockerfile.test -t pkv-test .

# 运行测试
docker run --rm -v ${PWD}/.data-test:/app/.data-test pkv-test archive "https://example.com"
```

---

### 技巧 2：自动化测试流水线

```yaml
# .github/workflows/test-isolation.yml
name: 测试环境隔离验证

on: [push, pull_request]

jobs:
  test-isolation:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: 设置测试环境
        run: |
          mkdir -p .data-test/{db,vault,vectors,logs,tmp}
          echo "DB_PATH=.data-test/db/knowledge_vault.db" > .env.test

      - name: 运行测试
        env:
          DB_PATH: .data-test/db/knowledge_vault.db
        run: |
          python -m pytest tests/ -v

      - name: 验证生产数据未修改
        run: |
          if [ -d ".data" ]; then
            echo "错误: 生产数据目录不应存在于测试环境"
            exit 1
          fi
```
