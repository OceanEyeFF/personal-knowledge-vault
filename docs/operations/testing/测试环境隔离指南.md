# 测试环境隔离指南

> 目标：在 Windows 上验证 PKV 功能时，确保任何测试数据都不会写入生产目录 `.data/`。

**最后更新**: 2026-07-22
**版本**: v2.0

---

## 隔离边界

PKV 将配置分为两类，两者不应混用：

| 类型 | 保存位置 | 用途 |
|------|----------|------|
| 应用配置 | Git 忽略的 `config/local.yaml` | LLM、Embedding 的 endpoint、模型、维度和密钥 |
| 运行隔离参数 | `scripts/run-test.ps1` 为子进程设置 | 将数据库、Vault、向量、日志和临时目录定向到 `.data-test/` |

不再创建或加载 `.env.test`，也不通过 `PKV_LLM_*` 或 `PKV_EMBD_*` 配置 Provider。

### 目录约定

- `.data/`：生产数据，测试期间不得写入。
- `.data-test/`：本地测试数据，由 `scripts/run-test.ps1` 自动创建和使用。
- `config/config.yaml`：版本化的默认配置，不放密钥。
- `config/local.yaml`：本机私有配置，已被 Git 忽略。

## 快速开始

### 1. 配置本机 Provider

如果测试会访问 LLM 或 Embedding 服务，在 `config/local.yaml` 中配置。可以复制 `config/config.yaml` 后修改，也可以只写需要覆盖的字段：

```yaml
ai:
  llm:
    base_url: "<LLM endpoint>"
    api_key: "<本机密钥>"
    model: "<LLM 模型>"
  embedding:
    base_url: "<Embedding endpoint>"
    api_key: "<本机密钥>"
    model: "<Embedding 模型>"
    dim: "auto"
```

`config/local.yaml` 会递归覆盖 `config/config.yaml` 的同名字段。不要将该文件加入 Git，也不要在日志、截图或测试输出中打印密钥及其前缀。

### 2. 运行隔离命令

从项目根目录运行：

```powershell
.\scripts\run-test.ps1 stats
.\scripts\run-test.ps1 archive "https://example.com"
.\scripts\run-test.ps1 search "测试查询"

# pytest、Python 脚本等非 CLI 命令必须使用 -Direct 和显式 -Command 字符串数组
.\scripts\run-test.ps1 -Direct -Command @("pytest", "tests/unit", "-q")
```

默认分支把参数拼接为 `python -m src.cli.commands <CLI-subcommand>`；`-Direct` 分支接收显式的 `-Command @("executable", "arg", ...)` 字符串数组，并按原顺序传递各元素。两条分支共享下述六项路径隔离与相同的 `DataRoot` 安全校验。

脚本会在子进程中将以下路径定向到 `.data-test/`：

```text
DATA_DIR   -> .data-test
DB_PATH    -> .data-test/db/knowledge_vault.db
VAULT_DIR  -> .data-test/vault
VECTOR_DIR -> .data-test/vectors
LOG_DIR    -> .data-test/logs
TMP_DIR    -> .data-test/tmp
```

这些变量只用于运行时路径隔离，不是 Provider 配置的替代品。

### 3. 核对隔离结果

```powershell
.\scripts\run-test.ps1 stats
Get-ChildItem .data-test -Recurse
git status --short
```

验收条件：

- 运行输出显示的数据路径均位于 `.data-test/`。
- `.data-test/db`、`.data-test/vault`、`.data-test/vectors` 按需产生数据。
- 脚本输出确认所有运行路径均在 `.data-test/`，且路径守卫未报错；AI 不枚举 `.data/` 作前后对比。
- `git status --short` 不出现 `.data-test/`、`config/local.yaml` 或其他本机运行产物。

## 真实服务测试

默认测试不应依赖真实 AI 服务。只有明确需要运行 live 测试时，才在当前 PowerShell 会话设置开关：

```powershell
$env:PKV_RUN_LIVE = "1"
.\scripts\run-test.ps1 -Direct -Command @("pytest", "<live-test-path>", "-m", "network", "-q")
Remove-Item Env:PKV_RUN_LIVE
```

`-m network` 用于覆盖 `pytest.ini` 的默认离线筛选；只设置
`PKV_RUN_LIVE=1` 仍会让 live 用例被排除。`PKV_RUN_LIVE` 只是测试放行
开关；Provider 参数仍从 `config/local.yaml` 读取。

真实归档命令会写入测试 Vault 和索引，也可能产生 API 费用。运行前应确认 endpoint 可达、模型已加载，且测试 URL 可用。

### Embedding 索引契约

Embedding 的 endpoint、模型和维度共同构成向量索引契约。任一项改变时，不得复用原有 `.data-test/vectors`；应删除测试向量索引并重新归档或重建索引。不要仅替换模型名称后继续读取旧索引。

## 常见场景

### 功能流转验证

按短路径分开验证存储、消费和管理需求：

```powershell
# 存储：归档一条可控样例，然后检查列表与详情
.\scripts\run-test.ps1 archive "https://example.com"
.\scripts\run-test.ps1 list
.\scripts\run-test.ps1 show 1

# 消费：在已知测试数据上分别验证检索策略
.\scripts\run-test.ps1 search "样例关键词" --strategy bm25
.\scripts\run-test.ps1 search "样例语义" --strategy vector

# 管理：只对测试数据执行统计或维护命令
.\scripts\run-test.ps1 stats
```

每条路径先独立通过，再进行端到端串联，可以更快区分抓取、存储、索引或检索故障。

### 单元和集成测试

单元测试优先使用 `tmp_path` 或 `TemporaryDirectory`，并将完整的存储路径注入测试配置。不要只覆盖 `DB_PATH` 而留下 Vault 或向量目录指向 `.data/`。

从 Windows 命令行运行 pytest 时，使用统一包装脚本；pytest 不是 PKV CLI 子命令，必须使用 `-Direct` 和显式 `-Command` 字符串数组：

```powershell
.\scripts\run-test.ps1 -Direct -Command @("pytest", "tests/unit", "-q")
```

### Git Worktree

每个 worktree 都应拥有自己的 Git 忽略 `config/local.yaml`。仍使用 `scripts/run-test.ps1` 运行可写测试，数据会落在该 worktree 的 `.data-test/`，不要为 worktree 新建 `.env` 或 `.env.test`。

## 故障排查

### 测试数据出现在 `.data/`

1. 立即停止当前可写命令。
2. 确认命令是通过 `scripts/run-test.ps1` 启动，而不是直接调用 Python。
3. 检查脚本输出的 `DATA_DIR`、`DB_PATH`、`VAULT_DIR` 和 `VECTOR_DIR`。
4. 保留现场并报告最小复现命令，不要自动移动或删除 `.data/`。

### Provider 连接失败

```powershell
.\scripts\run-windows.ps1 python -m src.cli.commands config show
```

只核对 endpoint、模型名和维度是否符合预期；命令应对密钥做遮罩。不要复制、打印或上传 `config/local.yaml` 的内容。

### 维度不匹配

若服务实际返回的向量维度与索引不同：

1. 检查 `config/local.yaml` 的 `ai.embedding.model` 和 `ai.embedding.dim`。
2. 在服务已加载正确模型时再次验证。
3. 清理 `.data-test/vectors` 并重建测试索引。
4. 不要对 `.data/vectors` 执行清理操作。
