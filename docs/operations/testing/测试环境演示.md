## 演示视频脚本

### 第 1 幕：初始化测试环境 (2 分钟)

```powershell
# ========== 场景：第一次使用测试环境 ==========

# 检查测试路径，不读取生产 .data/
Write-Host "✨ 步骤 1：确认测试环境路径" -ForegroundColor Cyan
.\scripts\run-test.ps1 config show

# 输出示例：
# 知识库统计
# ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
# data_dir: <仓库路径>\.data-test
# db_path: <仓库路径>\.data-test\db\knowledge_vault.db

Write-Host ""
Write-Host "✨ 步骤 2：确认本机应用配置" -ForegroundColor Cyan

# 应用配置统一写入 Git 忽略的 config/local.yaml。
# 测试路径由 run-test.ps1 自动设置，不创建或加载 .env.test。
if (!(Test-Path "config/local.yaml")) {
    Copy-Item "config/config.yaml" "config/local.yaml"
    Write-Host "  ✓ 已创建 config/local.yaml，请先在编辑器中填写本机配置" -ForegroundColor Green
} else {
    Write-Host "  • config/local.yaml 已存在" -ForegroundColor Gray
}

# 不要用 Get-Content 或日志打印 config/local.yaml，避免泄露密钥。
# LLM 配置位于 ai.llm.*，Embedding 配置位于 ai.embedding.*。

Write-Host ""
Write-Host "✨ 步骤 3：验证测试环境" -ForegroundColor Cyan
.\scripts\run-test.ps1 stats

# 输出示例：
# ========================================
#  测试环境模式 (Test Environment)
# ========================================
#   ✓ DB_PATH = .data-test/db/knowledge_vault.db
#   ✓ LOG_LEVEL = DEBUG
#

#   python -m src.cli.commands stats  # 由 run-test 包装器在 .data-test 中执行
#
# 知识库统计
# ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
# 总条目数: 0  👈 测试数据库是空的！
# ...
```

**关键点**:
- ✅ 不读取生产 `.data/` 进行对比
- ✅ 测试数据库: 0 条数据（全新环境）
- ✅ `run-test.ps1` 自动设置 `.data-test/` 下的数据库、Vault、向量、日志和临时目录
- ✅ AI 服务配置只从 Git 忽略的 `config/local.yaml` 读取
- ✅ 完全隔离！

## 真实使用案例

### 案例 1：开发新的知乎回答处理器

```powershell
# 1. 测试归档知乎回答
.\scripts\run-test.ps1 archive "https://www.zhihu.com/question/xxx/answer/yyy"

# 2. 检查处理结果
.\scripts\run-test.ps1 show 1

# 3. 以下会操作生产 .data/：必须取得用户明确授权，只由用户执行，AI 不执行
.\scripts\backup-data.ps1 -Message "正式归档前备份"
.\scripts\run-windows.ps1 python -m src.main archive "https://www.zhihu.com/question/xxx/answer/yyy"
```

### 案例 2：测试数据库 Schema 升级

测试迁移使用独立的 `DataRoot`。空目录只验证 fresh install；如需验证旧库升级兼容性，先将已脱敏的旧版 DB/Schema 夹具放入 `.data-test\migration\db\knowledge_vault.db`：

```powershell
# 1. 先只读检查待执行迁移
.\scripts\run-test.ps1 -Direct -DataRoot .data-test\migration -Command @("python", "scripts\migrate.py", "--dry-run")

# 2. 执行测试迁移；当前自动备份固定读取生产 .data/，测试时必须禁用
.\scripts\run-test.ps1 -Direct -DataRoot .data-test\migration -Command @("python", "scripts\migrate.py", "--auto", "--no-backup")

# 3. 验证升级结果
.\scripts\run-test.ps1 -DataRoot .data-test\migration stats
.\scripts\run-test.ps1 -DataRoot .data-test\migration list
```

`--auto --no-backup` 不会等待交互确认，也不会执行自动备份；待迁移文件及数量取决于测试夹具版本，不固定为某一个脚本。

测试通过后，如需执行生产升级，必须取得用户明确授权。以下步骤只由用户执行，AI 不执行：

```powershell
$pathVariables = "DATA_DIR", "DB_PATH", "VAULT_DIR", "VECTOR_DIR", "LOG_DIR", "TMP_DIR"
$remaining = $pathVariables | Where-Object { Test-Path "Env:$_" }
if ($remaining) {
    throw "检测到路径环境变量，请关闭此窗口并新开 PowerShell：$($remaining -join ', ')"
}

# 3. 以下生产备份与升级只由用户执行；AI 不执行
.\scripts\backup-data.ps1 -Message "生产环境升级前最终备份"
.\scripts\run-windows.ps1 python scripts/migrate.py
```

### 案例 3：批量导入测试

```powershell
# 1. 准备测试 URL 列表
@"
https://example.com/article-1
https://example.com/article-2
https://example.com/article-3
"@ | Out-File test-urls.txt

# 2. 在独立测试数据根目录批量归档
Get-Content test-urls.txt | ForEach-Object {
    Write-Host "归档: $_" -ForegroundColor Cyan
    .\scripts\run-test.ps1 -DataRoot .data-test\batch-import archive $_
    Start-Sleep -Seconds 2  # 避免 API 限流
}

# 3. 检查测试结果
.\scripts\run-test.ps1 -DataRoot .data-test\batch-import stats
.\scripts\run-test.ps1 -DataRoot .data-test\batch-import list

# 4. 测试数据保留在 .data-test\batch-import；确认无需保留后，仅删除该场景目录
# 生产批量归档仍需用户明确授权，AI 不执行
```
