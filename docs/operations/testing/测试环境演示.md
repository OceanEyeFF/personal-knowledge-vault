# 测试环境完整演示 🎬

> **实战演示：如何使用测试环境安全地开发和测试新功能** ฅ'ω'ฅ

> **2026-07-31 P0 安全基线**：本演示的 Agent-safe 部分只运行合成 CAT-0。G0 已按入口交付并核验：pytest=offline pytest bootstrap + root conftest，CLI/MCP=`offline_entrypoint.py`，FT7 Direct Python 仅支持仓库 `python -m` / `.py` 并在同进程 `runpy`；拒绝 `-c`/stdin/解释器 flags，清理 live/secret/proxy，绑定 base-only Config，并安装网络/子进程 guard。非 Python Direct 不属于 Python G0，且进程内 guard 不是 OS sandbox。真实数据尚未执行；CAT-U/CAT-C 仍等待 U1/G8，migration 另需 FT5。

**场景**: 你要测试一个新的内容处理器，但不想影响现有的生产数据

### 第 2 幕：在测试环境运行合成排练 (3 分钟)

```powershell
# ========== 场景：固定 seed + dev vault ==========

# setup-test-db.py 经 FT7 Direct Python 入口运行；output 必须精确位于所选 DATA_DIR。
.\scripts\run-test.ps1 -Direct -DataRoot .data-test\demo-seed -Command @(
  "python", "scripts\setup-test-db.py",
  "--seed", "42", "--count", "20",
  "--wechat-count", "3", "--zhihu-count", "3",
  "--output", ".data-test/demo-seed/db/knowledge_vault.db"

.\scripts\run-test.ps1 -DataRoot .data-test\demo-seed list --limit 5

# dev vault 重建与 --check-only 都必须经 wrapper Direct Python。
# 脚本要求 FT7 runtime attestation（process_guarded=True）；--root 必须位于本次 selected DATA_DIR。
# 裸 Python 会在产品 import 前失败，任意 .data-test sibling 也不能作为 --root 旁路。
.\scripts\run-test.ps1 -Direct -DataRoot .data-test\demo-dev-vault -Command @(
  "python", "scripts\rebuild-dev-vault.py",
  "--root", ".data-test/demo-dev-vault", "--json"
)
.\scripts\run-test.ps1 -Direct -DataRoot .data-test\demo-dev-vault -Command @(
  "python", "scripts\rebuild-dev-vault.py",
  "--root", ".data-test/demo-dev-vault", "--check-only", "--json"
)
```

**关键点**:
- ✅ 所有 Agent 操作均为合成 CAT-0
- ✅ fixed seed 的输出精确锁定到所选 `DATA_DIR`
- ✅ dev vault 重建与 `--check-only` 已使用 FT7 入口
- ✅ dev-vault `--root` 与 selected `DATA_DIR` 一致，且 runtime attestation 为 `process_guarded=True`
- ✅ 所列命令均不指向生产路径

## 真实使用案例

### 案例 1：开发新的知乎回答处理器

```powershell
# 1. Agent 仅运行离线处理器测试；不要把真实 URL 交给 CAT-0 launcher
.\scripts\run-test.ps1 -Direct -DataRoot .data-test\processor-contract -Command @(
  "python", "-m", "pytest", "tests/unit", "-q", "-k", "zhihu"
)

# 2. 以下会操作生产 .data/：必须取得用户明确授权，只由用户执行，AI 不执行
.\scripts\backup-data.ps1 -Message "正式归档前备份"
.\scripts\run-windows.ps1 python -m src.main archive "https://www.zhihu.com/question/xxx/answer/yyy"
```

授权真实快照上的 archive 属于 CAT-U，当前仍等待 U1/G8；上面的生产命令只是既有 user-only 运维接口，不是本演示的 Agent 步骤。

### 案例 2：测试数据库 Schema 升级

`scripts/run-test.ps1` 当前明确拒绝 `scripts/migrate.py` 并返回 exit 2，因此不再提供 wrapper migrate 命令。Agent 现在只运行使用临时 SQLite 的迁移单元/集成测试：

```powershell
.\scripts\run-test.ps1 -Direct -DataRoot .data-test\migration-contract -Command @(
  "python", "-m", "pytest", "tests/unit", "tests/integration", "-q", "-k", "migration"
)
```

真实快照 migration 仍需 FT5 + U1/G8 + 用户授权 + 历史 baseline + pending migration，并且只能在 disposable clone 内执行。空库 fresh install 不能证明历史升级兼容性。

测试通过后，如需执行生产升级，必须取得用户明确授权。以下步骤只由用户执行，AI 不执行：

```powershell
$pathVariables = "DATA_DIR", "DB_PATH", "VAULT_DIR", "VECTOR_DIR", "LOG_DIR", "TMP_DIR"
$remaining = $pathVariables | Where-Object { Test-Path "Env:$_" }
if ($remaining) {
    throw "检测到路径环境变量，请关闭此窗口并新开 PowerShell：$($remaining -join ', ')"
}

# 3. 以下生产备份与升级只由用户执行；AI 不执行
.\scripts\backup-data.ps1 -Message "生产环境升级前最终备份"
.\scripts\run-windows.ps1 python scripts/migrate.py
```
